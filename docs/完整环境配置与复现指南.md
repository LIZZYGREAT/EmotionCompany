# EmotionalCompany 开发环境配置与复现指南

> 本文适用于数字人综合情感陪伴对话模型竞赛的 **本地 WSL2 + NVIDIA GPU** 模型开发环境，依据已成功运行的安装、GPU 计算、量化测试和 Qwen3-1.7B 推理结果整理。本文与 `requirements.txt` 配套使用。

## 一、环境目标与验收范围

我们的开发流程为：

```text
Windows NVIDIA 驱动
      ↓
WSL2 Ubuntu → Python venv → PyTorch CUDA
                               ↓
                Transformers / TRL / PEFT
                               ↓
                  bitsandbytes 4-bit NF4
                               ↓
              Qwen3-1.7B 模型加载及生成
                               ↓
             [待完成] QLoRA 真实训练
                               ↓
        [待完成] 验证集评测、Docker 部署
```

## 二、Windows 与 WSL2 安装（队友已有 WSL2 可跳过）

首先在 **Windows 管理员 PowerShell** 中执行：

```powershell
wsl --list --online
wsl --set-default-version 2
wsl --install -d Ubuntu-22.04
```

根据提示重启，第一次启动 Ubuntu 时设定 Linux 用户名与密码。安装后检查：

```powershell
wsl --list --verbose
nvidia-smi
```

应看到 Ubuntu 对应的 WSL `VERSION` 为 `2`，Windows 能识别 NVIDIA GPU。

进入 Ubuntu：

```powershell
wsl -d Ubuntu-22.04
```

在 Ubuntu 内执行：

```bash
cat /etc/os-release | head -n 5
python3 --version
nvidia-smi
free -h
df -h ~
```

如果 WSL 中找不到 `nvidia-smi`，尝试：

```bash
/usr/lib/wsl/lib/nvidia-smi
```

**不要在 WSL2 内额外安装 Linux NVIDIA 显卡驱动。** GPU 驱动由 Windows 主机提供，PyTorch CUDA Wheel 通常已经携带所需的 CUDA 用户态运行库。当前项目不需要单独安装完整的 CUDA Toolkit。

建议将源代码、虚拟环境、训练缓存放在 Linux 文件系统（`~/projects/...`），不要将 `.venv` 建在 `/mnt/c/...` 下。Windows 的 16GB 系统内存不是 GPU 的 8GB 显存。

## 三、创建项目与 Python 虚拟环境

安装开发工具：

```bash
sudo apt update
sudo apt install -y \
  python3-venv \
  python3-pip \
  git \
  build-essential
```

项目负责人使用 Ubuntu 的 Python 3.10.12。队友应尽量使用 Ubuntu 22.04 / Python 3.10 环境，以减少二进制兼容差异。

将 Git 仓库克隆到 `~/projects/EmotionalCompany`（或者将已有项目文件放到该路径），然后：

```bash
cd ~/projects/EmotionalCompany

python3 -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip setuptools wheel
```

验证虚拟环境：

```bash
python --version
which python
python -m pip --version
```

`which python` 应位于当前项目下的 `.venv/bin/python`。此后每次打开 WSL 工作时：

```bash
cd ~/projects/EmotionalCompany
source .venv/bin/activate
```

退出使用 `deactivate`。

## 四、安装 PyTorch 与项目依赖

仓库根目录需要提供：

- `requirements.txt`：本指南附带的依赖表，**准确固定已验证的 8 个核心包版本**；辅助工具未能从现有输出中确认版本，故暂未全部锁定；
- `requirements-lock.txt`：**项目负责人已经在真实环境执行 `pip freeze` 导出的完整快照**，供队友尽可能精确复现；应提交这份原文件，不要覆盖它；
- `participant/requirements.txt`：赛事官方推理程序附带的依赖，不等于完整训练依赖，保留原样。

### 1. 优先使用真实的 requirements-lock.txt

负责人已执行过：

```bash
python -m pip freeze > requirements-lock.txt
```

队友拿到仓库之后，在虚拟环境内先安装已测试的 CUDA 12.8 PyTorch：

```bash
python -m pip install 'torch==2.10.0+cu128' \
  --index-url https://download.pytorch.org/whl/cu128
```

然后使用原机器的完整锁定文件：

```bash
python -m pip install -r requirements-lock.txt
```

这比仅依赖顶层需求文件更接近“完全一致”；如果 Python、系统架构或 GPU 不同，仍可能存在平台差异。

### 2. 备用方式：安装整理后的 requirements.txt

如果真实 `requirements-lock.txt` 还没同步过来，可以先用配套文件安装：

```bash
python -m pip install -r requirements.txt
```

该文件通过额外 PyTorch CUDA 12.8 Wheel 索引获取 `torch==2.10.0+cu128`，并固定已证实的 NumPy、Transformers、Accelerate、Datasets、PEFT、TRL、bitsandbytes 版本。还包括 `safetensors`、`pandas`、`scikit-learn`、`PyYAML`、`jsonschema`、`pytest`、`tensorboard` 等工具，但这些工具和传递依赖的精确安装版本**尚未全部固定**。

安装完成后：

```bash
python -m pip check
```

预期：

```text
No broken requirements found.
```

## 五、GPU 与依赖验收

### 1. CUDA / BF16 / 自动求导

```bash
python - <<'PY'
import torch

print('PyTorch:', torch.__version__)
print('CUDA Runtime:', torch.version.cuda)
print('CUDA available:', torch.cuda.is_available())
assert torch.cuda.is_available()
print('GPU:', torch.cuda.get_device_name(0))
print('BF16 supported:', torch.cuda.is_bf16_supported())

x = torch.randn(1024, 1024, device='cuda', requires_grad=True)
loss = (x @ x).square().mean()
loss.backward()
assert x.grad is not None
print('Loss:', loss.item())
print('Autograd test PASSED')
PY
```

预期 GPU 名称正确、CUDA 可用、最后输出 `Autograd test PASSED`。随机输入造成的 Loss 数值并非固定。

### 2. 训练依赖导入与版本

```bash
python - <<'PY'
import torch, numpy, transformers, accelerate, datasets, peft, trl
import bitsandbytes as bnb
from trl import SFTTrainer, SFTConfig
from peft import LoraConfig
from transformers import BitsAndBytesConfig

for name, module in {
    'torch': torch, 'numpy': numpy, 'transformers': transformers,
    'accelerate': accelerate, 'datasets': datasets, 'peft': peft,
    'trl': trl, 'bitsandbytes': bnb,
}.items():
    print(f'{name}: {module.__version__}')

print('Framework import test PASSED')
PY
```

验收条件：版本与第一节的核心包相符，并输出 `Framework import test PASSED`。

### 3. bitsandbytes NF4 GPU 计算

```bash
python - <<'PY'
import torch
import bitsandbytes as bnb

layer = bnb.nn.Linear4bit(
    64, 32,
    bias=False,
    compute_dtype=torch.bfloat16,
    quant_type='nf4',
).to('cuda')

x = torch.randn(2, 64, device='cuda', dtype=torch.bfloat16)
with torch.no_grad():
    y = layer(x)
torch.cuda.synchronize()

assert y.shape == (2, 32)
assert torch.isfinite(y).all().item()
print('Output shape:', y.shape)
print('Output device:', y.device)
print('4-bit NF4 CUDA test PASSED')
PY
```

预期输出：

```text
Output shape: torch.Size([2, 32])
Output device: cuda:0
4-bit NF4 CUDA test PASSED
```

这是 NF4 **前向计算测试**，尚未检验 LoRA 训练更新。

## 六、Qwen3-1.7B 模型推理验收

采用模型 [`Qwen/Qwen3-1.7B`](https://huggingface.co/Qwen/Qwen3-1.7B)。

模型第一次从 Hugging Face 下载，通常缓存于：

```text
~/.cache/huggingface/hub/
```

项目已有推理验证脚本：

```bash
python scripts/smoke_inference.py
```

脚本采用 `BitsAndBytesConfig`，主要参数：

```python
quant_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen3-1.7B",
    quantization_config=quant_config,
    device_map={"": 0},
    dtype=torch.bfloat16,
)
```

构造提示词时使用模型的 Chat Template，并指定 `enable_thinking=False`；生成时可以从 `max_new_tokens=160`、`do_sample=False` 起步。

负责人已通过测试：

```text

Generation time: 2.39 seconds
Peak GPU memory: 1.28 GiB

Qwen3-1.7B inference test PASSED
```

**这不是队友需要逐项达到的固定性能阈值。** 不同显卡、系统后台占用、首次加载和随机条件都可能影响生成内容与时间。建议记录各自实际结果。

## 八、常见问题

**1. `nvidia-smi` 显示 CUDA 13.4，但 PyTorch 是 12.8？**

前者为驱动支持的 CUDA 能力，后者为 PyTorch 配套 Runtime；不必完全一致。该组合已在 RTX 4060 WSL2 中通过 CUDA 测试。

**2. 报错 `Failed to initialize NumPy`？**

代表当时缺少 NumPy，而非 CUDA 故障。已安装版本为 `numpy==2.2.6`。

**3. 出现 CUDA out of memory？**

先查 `nvidia-smi` 后台显存占用；训练时优先缩小上下文长度与 micro-batch，考虑梯度检查点和 QLoRA。**4-bit 推理成功不能保证同一模型在任意长度下都能训练。**

**4. Docker/vLLM 是否现在必须安装？**

不必。主办方已明确答复：该数字人赛道**不提供统一的基础 Docker 镜像**，可以自行构建 vLLM 镜像，最终导出的参赛镜像文件须在 **50GB 以内**。本地训练环境与 Docker 交付环境分开管理即可。

**5. 为什么不直接修改 `participant/requirements.txt`？**

它属于赛事提供的推理入口，不应拿来充当完整训练环境说明。后续适配推理时可以按实际需要调整，但应保留其原始协议与 `start.sh` 入口要求。
