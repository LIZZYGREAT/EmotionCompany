## 一、比赛背景与项目目标

### 1. 赛题与评分

赛题：**数字人综合情感陪伴对话模型**。给定一段截至当前用户消息的对话历史，系统需要一次性生成三个核心结果：

1. **情绪识别**：预测当前用户消息的主情绪；正常类别为 **16 类**，单标签分类。
2. **用户画像**：根据已有历史预测三个维度的多标签集合：`personality_traits`（10 种）、`interests`（12 种）、`style`（11 种），共 **33 个候选标签**。三个数组均允许为空。
3. **情感回复**：生成与当前对话语境相匹配的自然中文回复。

自动评测部分合计 70 分：情绪 Accuracy 25 分、回复 BLEU-4 / ROUGE-L / BERTScore 20 分、画像 15 分、延迟 10 分；另有方案、代码、平台及材料方面的评审 30 分。**具体画像指标口径、文本指标实现和部分评分映射仍需以官方规则 / 评分脚本核实，不应自行宣称本地分数等价官方分数。**

提交协议：运行 `/root/participant/start.sh TEST_FILE RESULT_DIR`，产生 `submission.jsonl` 与 `performance_report.json`。官方 JSON 需要 `id`、`response_text`、`emotion_label`、`user_profile`、`memory_refs`。提交 Schema 额外允许空情绪 `""` 作为失败哨兵，**不是第 17 种实际情绪**。`id` 从测试记录复制，不让模型生成。

### 2. A0 已冻结的技术路线

- **单模型方案 A**：`Qwen/Qwen3-1.7B` 对话模型，同时完成情绪、画像、回复三项任务；暂不训练独立的分类器。
- **QLoRA**：基础模型采用 4-bit NF4 加载，冻结主体权重，只更新 LoRA Adapter；本地优先在 RTX 4060 Laptop 8GB 上验证。
- **Completion-only SFT**：每个预测点形成一个 Prompt + 标准 JSON Completion，损失仅作用于需要模型生成的部分。
- **P0**：已冻结的简洁任务 System Prompt，后续可独立设计 P1 对照，但不能偷偷把 P1 规则混进 E00/E01 的 A0 基线。
- **F2**：Qwen 原生 Chat Template，多轮 `system/user/assistant` 消息，`enable_thinking=False`。
- **T1**：历史超长时，从当前 User 消息向前保留最近的**连续完整消息后缀**，使用固定 Prompt 上限 P 选择；不跳过中间消息，不根据参考答案的长度重选历史。
- **A0 Completion**：字段顺序 `emotion_label → user_profile → response_text → memory_refs`，使用紧凑 JSON；画像按官方枚举顺序输出；原始参考回复保持逐字一致；模型目标中的 `memory_refs=[]`（原始 D0.3 target 仍保留其非空标注）。
- **首轮标准 Loss**：普通逐 Token 交叉熵，不加字段专属权重，不引入数据重采样、RAG、二阶段推理、DPO/RLHF 等额外机制。
- **实验对照**：`E00` = 原始 Qwen3-1.7B 零微调基线；`E01` = 同一基础模型 + A0 标准 QLoRA SFT。双方应保持相同的 Prompt、历史策略、解码条件与评测流程，尽可能只改变微调后的模型参数。
- **最终交付方向**：自建可离线执行的 vLLM Docker 镜像（官方没有该赛道专用基础镜像），镜像大小上限 50GB；版本、显存、吞吐和权重格式均须在目标运行环境验证。

## 四、D0.4.3 的完成结论（本轮审查重点）

### 1. 已实现的核心链路

```text
D0.3 的一条规范化 prediction point
  → 校验原始 history/target 及 D0.3 来源
  → 从最新 User 向前按固定 P 执行共享 T1
  → P0/F2、enable_thinking=False 的真实 Tokenizer 编码

  → 否则 input_ids = full_ids
          labels = [-100] * prompt_length + completion_ids
  → 动态右侧 Padding，产生 input_ids/labels/attention_mask 张量
  → 真实 TRL SFTTrainer DataLoader 核查三张张量逐元素一致
```

### 3. Labels / EOS / Collator / Trainer 的实际证据边界

- `input_ids` 包含 Prompt + 完整 JSON Completion + 模板结束标记。
- Prompt 的 `labels` 全为 `-100`；Completion（含首 Token、JSON 与终止 EOS）的 `labels` 为对应 Token ID；不预先执行手工 Shift。
- 动态 Padding 的 `attention_mask` 在真实 Token 位置为 1、填充位置为 0；新增填充位置 `labels=-100`；即使 EOS/PAD 使用相同 Token ID，也只依靠真实位置屏蔽新 PAD，不误伤 EOS。
- 真实 Qwen Tokenizer 下，以预编码 Train/Dev 记录对 Batch Size 1/2/4 逐元素测试。
- TRL 1.14.2、Transformers 5.20.2、Datasets 5.1.0、PyTorch 2.10.0+cu128：`SFTTrainer` 通过 `dataset_kwargs={"skip_prepare_dataset": True}`、`max_length=None`、`packing=False`、`padding_free=False` 配合自定义 Collator，在**无前向训练**的情况下验证 train/eval DataLoader 输出与预期逐元素一致。
- 验收模型是随机初始化的 tiny GPT-2 结构，`forward_calls=0`，没有训练循环、没有参数更新；不证明实际 Qwen 模型推理、显存或者损失可计算。
- 用户仓库报告记录：`14 passed, 15 warnings`（新测试），`64 passed, 15 warnings`（全仓回归）。**本轮只做代码与报告审查，未独立执行**，也没有完整 pytest warning 明细。下一步环境检查时应查看 warning 来源，避免把模型兼容性 warning 误当作无关问题。

## 五、下一阶段的任务及建议顺序

### 1. E00：零微调基线评测——建议优先推进

1. **准备评测输入与离线模型**：确认 `participant/run_inference.py` 既有入口、测试 JSONL 字段、模型权重和与 D0.4.2 相同的 Tokenizer 版本；保留 `sample_id` 到官方测试 `id` 的映射，**不要让真值泄露到 Prompt**。

3. **建立独立评测器**：对原始预测和经过容错后的提交预测分别计算有效率；情绪 Accuracy、画像多标签指标、回复 BLEU-4/ROUGE-L/BERTScore 先按明确实现计算，记录与官方指标可能不等价的限制。禁止依赖已知正确答案生成模型 Prompt。
4. **扩大至完整 Dev 1,833 条**：保留输入版本、预测文件、实验配置、分项指标、耗时与错误案例；官方 Val 2,354 条作为较晚的阶段性验证，不宜反复据此微调方案。
5. **建立简单任务基线**：如情绪多数类与空画像预测，以衡量单模型联合生成相较于简单规则的价值。与 E00 共用评测定义。

**E00 验收点**：不仅有一个平均分，而是能解释每一项分数来自什么预测、哪些样本 JSON 非法、哪种情绪/画像表现最差、是否存在回复不完整或生成达到 G 上限。所有结果必须挂到具体版本与实验 ID。

## 八、给下一轮助手 / Codex 的明确工作原则

1. **先全局流程，再模块细节**：遇到 Prompt、Tokenizer、SFT、LoRA、Trainer、Batch 等概念，首次出现时讲清含义和在真实执行链中的作用；不要只罗列配置名。
2. **当前数据与协议优先**：基于仓库真实源码、当前输入/Manifest/报告，不凭旧聊天或假设数据替换实际结论；注意公开仓库不包含用户本地原始数据与大型模型文件。
3. **不要重复造轮子**：沿用 `src/shared/prompting.py` 的 P0/F2/T1；后续 E00/E01 使用同一输出规范、相同的候选 P 与推理历史裁剪规则。
4. **守住实验可比性**：E00/E01 的输入和评测尽可能相同，一轮只改变一个主要变量；不要把 P1、字段损失加权、RAG/记忆模型等直接加入 A0。
5. **分阶段完整验收**：提出 Codex 可执行 MD 时写清新增/修改文件、执行顺序、命令、预期数值、测试、产物与停止位置；验收后再开启下一阶段。
6. **不擅改官方边界**：`/root/participant/start.sh TEST_FILE RESULT_DIR` 和提交 Schema 不得破坏；训练数据、内部 JSON Completion 与最终提交 JSON 要明确区分。
7. **严谨描述证据**：已证明 DataLoader 没改标签 ≠ 已证明真实 GPU 训练；本地近似评测 ≠ 官方最终评分；模型卡上下文能力 ≠ 实际 vLLM K。
