## 二、从原始数据到 Full Dev 的阶段链

```text
官方 Train / Val（保护输入）
  → D0.1 审计 → D0.2 政策 → D0.3 规范化/去重/关联组划分
  → D0.4.2 Token 审计 → D0.4.3 Completion-only SFT 数据
  → E00 Smoke / 错误归因
  → E01-A 8 条 Micro-overfit / 20 条 Smoke
  → E01-B Pilot 512 Train / 160 Dev
  → Full B 16,192 Train / 4,048 steps / 1 Epoch
  → Base 与 Full B Adapter 在同一 1,833 条 D0.3 Dev 上生成、评分和配对比较
```

- Full B 的 SFT Dev Loss 只使用 1,821 条 teacher-forced Dev；生成质量比较使用完整 1,833 条。
- D0.3 官方 Val 为 2,354 条，本轮没有用于调参或诊断规则制定。
- S/P/G 为 Full B 使用的 S=2048、P=1280、G=1200；部署上下文 `K` 仍需目标服务实测。
- P0/F2/T1、Tokenizer/Chat Template、NF4/BF16、Greedy 解码和 ID 集保持锁定；Base 与 Adapter 只改变 Adapter 是否启用。

## 四、核心指标与结果解读

| 指标 | Base | Full B Adapter |
|---|---:|---:|
| Emotion Accuracy / Macro-F1 | 0.1282 / 0.0690 | 0.6536 / 0.4972 |
| Profile 33-label Micro / Macro-F1 | 0.0782 / 0.0724 | 0.4223 / 0.2700 |
| Profile 三维 Exact Match | 396/1,833 = 21.60% | 588/1,833 = 32.08% |
| Raw 严格 JSON / Raw A0 Schema | 46.15% / 0.93% | 98.25% / 98.09% |
| 本地字符级 BLEU-4 / ROUGE-L | 2.3993 / 0.1188 | 12.8212 / 0.2603 |
| 空回复率 | 22.20% | 1.75% |

Full B 已消除 Pilot 几乎全空画像的现象，但画像仍有明显长尾；`interests` 表现相对较好，`style` Macro-F1 仅 0.1548。D0.3 Dev 的三维 Gold 全空为 660/1,833（36.01%）；恒空预测 Exact Match 为 36.01%，高于 Full B 的 32.08%，但会得到 0 的画像 Micro-F1。Full B 的 Micro-F1 为 0.4223，说明逐标签恢复有明显改进；Exact Match 应与逐维 Recall、Micro/Macro-F1 合看。

情绪方面，Adapter 相对 Base 的正确命中数在 Dev 每个 Gold 类均持平或提升；剩余的典型弱项是 `care=0/6`、`mixed=5/93`。Adapter 混淆较多的方向包括 fear→anxiety、helplessness→anxiety、mixed→anxiety。Raw 层还有 32 次 JSON parse 失败，其中 29 次到达 G=1,200；另有 3 次可解析 JSON 的画像标签超出 A0 枚举。详见[深度诊断报告](../experiments/E01-B_Full_深度诊断与证据整理.md)。

质量指标为 `local_proxy`；BERTScore 与官方性能没有运行。本机 Runner 的 100/100 轮统计是本地 Transformers 测量：Base 平均 4.17 秒、Adapter 平均 13.43 秒；它不等于官方部署性能，且生成越长的样本延迟也越高。没有逐样本 BLEU/ROUGE 结果，因此本轮没有计算长度与文本指标的逐样本关系。
