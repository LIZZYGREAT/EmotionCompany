#### D0.2 数据政策与 D0.3 构建账本

政策只允许对 Train 做确定性点级隔离、精确监督去重和按关联组划分；不做语义去重、文本归一化、空画像填补、类别重采样或短回复过滤。空画像是合法 Gold；短回复、长文本和空预测点按规则保留或记账。相同历史但 Target 不同则保留；Val 的 2,354 个合法点全部原样进入 Val。

### 1.5 A0 架构与 E03-A0/A0.1 监督诊断

#### A0 模型及训练目标

| 设计项 | 冻结方案 |
|---|---|
| 主体模型 | 单一自回归 `Qwen3-1.7B`，不并联独立情绪/画像分类器 |
| 参数更新 | 4-bit NF4 量化并冻结 Base；BF16 计算；LoRA 训练 |
| 联合目标 | 一次生成完整 JSON：`emotion_label → user_profile → response_text → memory_refs` |
| 训练损失 | Completion-only 标准 Token 级交叉熵；A0 不做字段 Loss 权重 |
| 输入 | P0 任务 Prompt + F2 原生 Chat Template + T1 最近合法消息后缀；Non-thinking |
| 记忆字段 | `memory_refs=[]` 固定输出；不把 D0 Gold 中非空 memory refs 擅自改成推理检索目标 |
| 标准解码 | Greedy，`P=1,280`、`G=1,200`；正式服务 `K` 需独立核验 |

联合自回归目标顺序和单模型是 A0 的架构基线，不是已比较证明的最优结构。训练时后续 Response 处于正确 Gold 前缀下；推理时则依赖模型已生成的情绪/画像字段，存在前序错误向后传播的可能，因此后续质量诊断应分开看字段和完整输出。

### A1：Loss 对照——画像字段权重与标签值权重

**研究问题。** A0/A0.1 诊断显示，画像 Completion 中固定 JSON 结构 Token 占比高。A1 检验整体加权画像区域是否有效，以及收益是否能通过只加权 33 类 Gold 标签值取得。

**冻结流程。** 从相同 Base 新建 LoRA，不续训 E01-B；使用 D0.4.3 的 16,192 条 Train、相同 P0/F2/T1、Tokenizer、样本顺序、Seed、优化器和 Completion-only Token CE。Loss 为有效 Completion Token 的加权平均。比较：

1. `token_mean`：所有有效 Completion Token 权重为 1。
2. `profile_x2`：A0 归属为 `user_profile` 的 Token 权重为 2。
3. `label_value_x2`：仅精确落在 Gold 标签字符串内容的 Token 权重为 2；画像键名、标点和其他区域不加权。

**已确认结果与使用方式。** `label_value_x2` 完成短程筛选、完整训练及 1,833 点生成配对评分；训练、逐步 Loss 核对和独立重载都有记录。完整画像指标未达到候选保留条件，故 E01-B 仍是基线。A1 的可复述贡献是“将 Token 权重精确限制在 Gold 标签值，并经过短程门禁后再做完整候选评分”；不把该候选作为提升结果引用。

### A3：短历史画像诊断与平衡采样短程对照

**研究问题。** E01-B Full Dev 的画像全空漏报是否与较短对话历史相关；在只改变样本访问策略时，能否通过平衡抽样获得可复现的召回收益？

**冻结流程。** 第一阶段对 E01-B 的完整 1,833 点 Dev 和有效 16,192 条 SFT Train 按原始历史长度、T1 保留长度、Gold 空/非空、标签数量和三个维度统计，并单独标出相关与因果解释边界。诊断后冻结 224 点/101 个完整会话的 `development_proxy` 集，按同一个只读 E01-B Full Adapter 启动两组：

- Control：从全量 Train 分布均匀采样。
- Candidate：约 50% 全量自然抽样 + 约 50% 原始历史 1–4 条；短历史池按三维 Gold 全空/非空各半。

两组均训练 128 optimizer steps、相同 Completion-only Token CE、模型、优化器、Seed、有效 Batch 和生成协议；只改变样本访问策略。随后在同一冻结 224 点运行真实 JSON 生成、完整本地评分和按会话配对 Bootstrap。

A8 的正式可引用指标仅列 P（Profile-only）线；EP 是预先设计的联合情绪与画像生成路线，其结果不并入 P 线，也不将 A7 分类头的 EP 指标转记为 A8 EP。

以上是 A8 P 专项 Prompt 下的本地代理结果，不是官方分数。Dev224 的 P4048 分数略高于 E01-B Fast-only 同集参考值 `0.425787`，但二者 Prompt 和生成任务不同，因此这不是“只改变训练方法”的严格因果对照，也不能据此自动切换正式基线。所有固定节点的对比都应保留其 Cohort、提示词版本和生成协议。

P4048 在固定 Pilot160 中为 160/160 严格有效；Dev224 为 223/224 有效，唯一无效项是标签顺序不规范，仍留在固定分母中按空画像计分；两组 EOS 完成率均为 100%。

#### Hard Replay 子线

Hard Replay 从 P4504 冻结父模型出发，先在 Train+DevFT 中确定性选 3,000 条候选（2,700 Train、300 DevFT），运行父模型真实 Greedy 预测，再在冻结预测后按 miss/extra/mixed/clean 分类困难样本。先冻结 384 步/1,536 次曝光的调度，曝光桶为漏报重点 45%、误报重点 25%、普通维持 30%；Pilot 为 128 步，只有同集质量门通过才允许续到 256/384 步，并在会话互斥的 val_gate/val_confirm 上评测。Replay 只重复原 Gold Completion，不改 Gold、不造伪标签、不改变 JSON 或 A8 Prompt。

**已确认结果与使用方式。** Run 执行到 Replay128 后按预设门停止扩展；selection 仍指向只读 P4504，Replay256/384 与 val_confirm 候选结果不纳入汇总。该子线的有用记录是“确定性挖掘→冻结错误桶与曝光计划→小步配对门禁→通过才扩展”的实验流程，不应引用为已证实的性能改进。

## 4. 全局实验报告可复用的归纳

1. **基线与评价口径先写清。** E01-B Full 的 1,833 Dev 分数、224 点 Fast-only 筛选分数、2,354 点 Val 分数对应不同运行、数据集和输出层；不能合并成一张未标注口径的“模型排行榜”。
2. **A1–A4 的贡献主要是控制变量和诊断流程。** A1 锁定 Token 区域权重、A2 测冻结模型概率信号、A3 用相同起点等步数比较采样、A4 固定 Raw/Fast-only 口径。候选结果未进入 E01-B 正式基线。
3. **A5 与 A7 的 BCE/分类头路线不能混为一项。** A5 是给生成式 SFT 增加辅助 BCE、但真实 GPU 阶段尚未运行；A7 直接把任务输出改为分类头且完全移除 Response Loss，目前仅有单节点证据。
4. **A6 与 A8 都采用文本生成结构化标签，但实验目标不同。** A6 研究 F2 JSON 与 F3/F4 字段格式的表达差异，并保留 Response 生成；A8 使用独立画像 Prompt 和 P/EP Completion，不训练 Response。两者不能合并为同一协议或同一成绩。
5. **A8 是目前最值得纳入总报告的正向候选证据。** P4048 固定集训练曲线和 DevFT→Val 画像结果均已实际产出；引用 Val 分数时应标为本地代理评测，并说明模型原生 Prompt 不同、Dev 已参与续训以及 Val 曾有局部会话探索。
6. **不要从工程通过推出质量通过。** 训练 Loss、Checkpoint 重载、解析成功、格式/Schema Smoke 和固定分母质量指标是不同证据层；只有实际生成评分可支持模型质量结论。
