# 赛事文件边界与运行契约

本文记录赛事运行时必须保持的接口、项目主动采用的文件保护策略及升级流程。这里的“只读”是仓库协作规则，不表示赛事资料禁止修改所有参考源码。

## 官方运行契约

平台调用入口为：

```bash
bash /root/participant/start.sh TEST_FILE RESULT_DIR
```

入口路径、两个位置参数、输入 JSONL 语义以及执行预测的行为必须保留。`start.sh` 固定激活 `conda_env`。运行应在 `RESULT_DIR` 写入 `submission.jsonl` 与 `performance_report.json`，允许结果目录预先存在，并保留目录内其他文件。最终预测必须满足 `participant/templates/submission_schema.json`；失败情绪哨兵 `""` 属于提交 Schema 的容错值，不是有效的第 17 个情绪类。

`participant/run_inference.py` 是可适配的参考实现，不存在禁止修改整份源码的赛事依据。允许按模型、Tokenizer、LoRA、量化或后端需要修改，但每次变更都要通过固定入口、输出 Schema、默认双文件行为和推理协议回归。不得把整个 `participant/` 目录冻结。官方原始 README 中与交付相关的段落应保留；项目开发说明放在本文件和 `docs/workflow.md`。

## 文件权限矩阵

| 类别 | 文件/目录 | 规则 |
|---|---|---|
| 固定赛事入口 | `participant/start.sh` | 仅在部署需求明确时改；入口、两个参数、`conda_env` 和两份结果文件行为不可破坏，以行为测试保护，不要求脚本字节级不变。 |
| 官方提交 Schema/模板 | `participant/templates/submission_schema.json`、`participant/templates/submission_template.json` | 常规任务只读；基准 SHA-256 见下文。更新须有新官方来源、版本记录及兼容测试。 |
| 官方数据 Schema | `data/train/train_public.schema.json`、`data/val/val_public.schema.json` | 常规任务只读；当前仓库文件 SHA-256 见下文。更新须有来源证据和适配测试。 |
| 官方原始数据 | `data/train/train_public.jsonl`、`data/val/val_public.jsonl` | 只读处理，不修改、不提交 Git；保护来源指纹。 |
| 项目协议与划分 | `configs/prompts/p0.txt`、D0.3 split/Manifest、Tokenizer/Chat Template 锁定指纹 | 禁止静默改写；协议或数据语义变化须升级版本，历史产物保留。 |
| 可编辑赛事参考实现 | `participant/run_inference.py`、`participant/configs/inference_config.json`、`participant/requirements.txt` | 可因适配需要修改；必须回归固定入口、Schema、默认 Raw 关闭、结果目录保护、性能边界和旧协议。 |
| 项目自有实现 | `src/evaluation/`、`tests/`、`docs/`、`configs/evaluation/` | 按常规流程开发、测试、审查；不得绕开上列契约。 |
| 参考说明 | 根 `README.md`、`participant/README.md` | 保留赛事交付说明；新增项目内容优先放在 `docs/`，根 README 仅保留入口链接。 |

## 内部协议升级

- P0 文本及其哈希保持冻结。提示词语义变更应新增 P1 等版本，保留 P0，并为新实验显式指定版本。
- `src/shared/prompting.py` 可修复可证明的 Bug；修复不得静默改变同一 P0/F2/T1 输入的行为。语义变化须提升协议版本并更新回归用例。
- D0.3 原始数据划分、Manifest 和 D0.4 历史报告应保留。发现错误时追加修订证据，不覆盖原始产物。

## 模型缓存与 E00.2 预检

E00.1 当时没有真实 Qwen 推理；之后 E00.2 已完成 20 条真实模型 Smoke，E00.2-D 也完成 20 条单字段诊断。两者都不是完整 Dev 评测或官方性能轮次，阶段结果分别见 [E00.2 报告](../experiments/E00.2_真实模型Smoke与解码对照报告.md)、[E00.2-D 报告](../experiments/E00.2-D_单字段情绪诊断报告.md) 和 [E00 阶段总结](../experiments/E00_阶段总结与E01交接.md)。

Tokenizer 已缓存不代表完整模型权重已缓存。当前推理器需要本地实体模型目录（默认 `participant/model`），Tokenizer 仍执行固定 revision、签名和 Chat Template 校验。检查缓存时使用实测目录，不猜测 revision：

```bash
cd ~/projects/EmotionalCompany
source .venv/bin/activate

ls -ld participant/model 2>/dev/null || true
ls -lah ~/.cache/huggingface/hub/models--Qwen--Qwen3-1.7B/snapshots/ 2>/dev/null || true
find ~/.cache/huggingface/hub/models--Qwen--Qwen3-1.7B \
  -name '*.safetensors' -o -name config.json 2>/dev/null
```

确认目录实际存在且含配置和完整分片权重后，才设置 `EVALUATION_MODEL_PATH`。如果该 snapshot 的 Tokenizer 不满足锁定指纹，可单独指定经过核验的 Tokenizer 目录。不得为绕过加载问题启用隐式联网、关闭 `local_files_only` 或跳过 Chat Template 校验。E00.1 不下载/复制模型，也不包含真实模型、GPU、NF4、显存或生成质量验收；这些留给 E00.2。
