### B4. 推理、评分与部署（保留为后续工程候选）

- `I-01` Greedy vs Sampling/Temperature/Top-p/Top-k：必须在足够数量的同分布 Dev 样本上配对比较质量和延迟；20 条不足以冻结策略。
- `I-02` 不合规字段的诊断与容错后处理：先分别统计 Raw 合法率、抽取率、实际提交准确率；若修改 `normalize_prediction()`，需单独版本化策略和做无标签泄漏测试，不覆盖 E00 历史结果。
- `I-03` 回复长度与 G/P/K：记录 EOS、Token 长度和慢样本；先保证 P+G≤真实服务 K，不能把较低延迟直接等同于总体胜出。
