## 一、问题定义及已确认事实

本阶段要回答的不是“怎样尽快把 5% 改高”，而是：**模型原始输出到底是什么、哪一层出了问题、当前指标中格式失败与任务失败各占多少**。

现有实测：同一组 **20 条 D0.3 Dev Smoke**，Greedy 与 Sampling 各完成 20 条真实 Qwen 推理；Emotion Accuracy 均为 `1/20=5%`；Raw 严格 JSON 合法率分别为 `10/20` 与 `9/20`；两组 Raw A0 Schema 合法率均为 `0/20`；最终 Submission Schema 合法率均为 `20/20`；两组分别记录 `5 parse_failure + 15 invalid_label`；EOS 均为 `20/20`，未触及 G=1200。**不要据此直接推断 15 条情绪标签错误**：`invalid_label` 由情绪或任一画像维度不合规触发。

### 1. 模型身份：先纠正命名误解，不因传言更换模型

- 当前归档指向 Hugging Face `Qwen/Qwen3-1.7B`，revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`，真实权重聚合 SHA-256 已记录为 `005d20550c04f4e246e5b434448786b44a0196b47d758d0acc77aba279e5bbc5`。这一模型**已经过官方后训练**，并不是仅预训练的 `Qwen/Qwen3-1.7B-Base`。Qwen 官方 Model Card 分别把两者标成 `Pretraining & Post-training` 与 `Pretraining`。
- 竞赛语境中的“E00 基础模型/零微调模型”是指**还没有对本次竞赛进行 SFT**，不等于 Hugging Face 命名中的 `-Base`。
- 继续检查 `participant/model` 实际符号链接目标、Hugging Face repo/snapshot/revision、权重分片索引与 E00.2 记录的聚合指纹是否一致。**不得把 `AutoConfig.from_pretrained('./model')._name_or_path` 单独视为模型来源证明**；本地加载时该属性可能显示当前路径，配置文件也可能不记录原始仓库身份。
- 若发现实际挂载路径与实验归档不一致，先报告并停止跨运行比较；不要在本任务自动改用 `-Base`、重新下载权重或覆盖历史模型。

官方来源：`https://huggingface.co/Qwen/Qwen3-1.7B`、`https://huggingface.co/Qwen/Qwen3-1.7B-Base`。

### 2. P=1280 的截断情况：必须区分 Dev 与 Val

D0.4.2 精确 Token 审计中，候选 `S=2048/P=1280` 的 **历史消息截断率**：

| 数据集 | 样本数 | 截断率 | 来源 |
|---|---:|---:|---|
| Train | 16,312 | 30.19% | D0.4.2 审计 |
| Dev | 1,833 | **31.26%** | D0.4.2 审计 |
| Val | 2,354 | **24.81%** | D0.4.2 审计 |

这是 T1 为满足 P 删除了至少一条较早历史消息的比例，**不是丢失样本的比例**；`S` 是训练序列预算，不是 E00 推理时的独立截断因子。历史审计的全量比例不可代替本次特意分层选择的 20 条 Smoke 的实测截断率。Greedy/Sampling 均使用相同 P/T1/输入，因此现有**两组之间的配对对照仍然可比较**；但所得质量数字只能解释为 P=1280 条件下的模型表现，不能代表看见完整历史时的表现。

### 3. 对另一份 Agent 诊断的采纳范围

| 对方意见 | 本次判断 | 处理 |
|---|---|---|
| “5% 说明模型大量产生空标签/非法值” | 有合理怀疑，但**尚未证明**；不能凭 Val 类分布推断特意覆盖 16 类的 Smoke | 先统计原始字段及转换路径 |
| “15 个 invalid_label 就是 15 个情绪错误” | 不成立，现有代码将**画像不合规**也计入该状态 | 拆分情绪/画像原因 |
| “Base 没受指令训练，5% 正常” | 对当前 `Qwen/Qwen3-1.7B` 的描述不准确 | 审计本地权重来源即可，不擅自替换模型 |
| “P=1280 的 24.8% 样本超限” | Val 24.81%，当前 Dev 31.26%；属于历史消息裁剪，非直接评分失败 | 分数据集、分样本记录截断 |
| “`</think>` 未闭合必然导致解析失败” | 不成立：现有 `extract_object()` 会寻找 `{` 后尝试解析完整 JSON | 加回归用例，先分清真实解析失败种类 |
| “`normalize_prediction` 直接修掉再评测” | 不应先改：会改变历史基线与提交语义 | 先增加**只读诊断**；有确认的解析 Bug 再最小修复并升级版本 |
| “只预测 emotion_label 跑 100 条” | 可用作**独立诊断对照**，但改变了任务 Prompt，不能与 A0 联合 JSON 成绩直接等同 | 仅在离线归因后按条件开展，不作为本轮必做 GPU 实验 |
| “六类 preserve_emotions 应变成十六类” | 是潜在数据代表性问题，但 D0.3 split 已冻结，擅改会造成 Train/Dev 漂移 | 只核查 Dev 逐类 support；不重划分、不替换 Macro-F1 口径 |
| “人工盲标 20 条可证明标注无问题” | 对话中的 65% 未经本项目可复核协议、标注记录及多人一致率验证 | 仅作为参考，不能直接进入项目实验证据 |

### 阶段 B：增加一个离线、只读的逐字段诊断入口（核心任务）

建议新增 `scripts/e00_2_diagnose.py`（可将纯分类/解析计算放在已有 `src/evaluation/` 适当模块，但禁止复制一套独立推理引擎）。输入为本次运行 Manifest、已归档的两组 Raw/Submission/Performance、E00.1 Smoke References/ID Map；支持明确 `--run-root`、`--output-dir`，输出到本地 `outputs/evaluation/e00_2/diagnostics/<run-id>/`，**不能覆盖原始数据**。

对 Greedy/Sampling 的每一条样本，依次独立判定：

1. **Raw 严格 JSON**：是否为合法完整 JSON object（拒绝前后额外内容、代码围栏、重复键和非标准常数），保留不可解析类别。
2. **宽松提取**：用现有 `participant.extract_object` 在原始文本中尝试提取完整对象。区分 `strict_fail_but_extracted` 与 `no_object_extracted`；不要把宽松提取成功冒充严格 JSON 成功。
3. **字段完整性**：四字段是否出现，是否有多余字段，根对象及 `user_profile` 是否为预期类型。
4. **情绪字段**：原始 `emotion_label` **实际取值**（含缺失、`null`、中文、别名、空字符串、其他非法字符串、合法枚举），原始合法数；在合法子集中与 gold 匹配数；最终 Submission 是否被归一化为 `""`，以及由哪种原因造成。
5. **画像字段**：三维逐个计数——缺失、非数组、非法枚举、重复值、合法非空、合法空；原始合法画像标签与 gold 对应的 TP/FP/FN；归一化成 `[]` 的原因；实际空集正确匹配数与“非空标签”正确预测数。
6. **回复字段**：缺失、非字符串、空白、正常字符串；最终 `response_text` 是否由原始字段保留或 `recover_response_text` 容错提取。只输出必要的长度与错误类别统计，避免报告中复制真实对话。
7. **`memory_refs`**：缺失、非数组、非空数组、恰好 `[]`；报告原始 A0 Schema 为什么不成立。
8. **运行/停止**：关联 `parse_failure`、`invalid_label`、`success`、`stop_reason`、`generated_tokens`，明确这几类状态为何触发，不能将其简单等同于情绪错误。
9. **样本级对齐**：Raw、最终 Submission、Gold 统一按 ID 连接，不按 JSONL 行序对齐；记录同一 ID 的两组比较、错误原因变化。

**重要**：现在 `normalize_prediction()` 对非法情绪置空、对不合法的画像维度整体置空，这是当前提交容错行为。优先保留行为，新增**旁路可追溯诊断**；不得通过事后读取金标签来替模型修正预测。

建议交付产物：

```text
outputs/evaluation/e00_2/diagnostics/<run-id>/
├── diagnosis_summary.json         # 两组总量、逐字段率、错误交叉表、ID 守恒
├── diagnosis_cases.jsonl          # 每个样本 ID 的原始/最终字段状态、错误原因，不复制完整历史
├── label_histograms.json          # 原始情绪合法/非法具体值的次数及最终空值数；仅本地
├── profile_diagnostics.json       # 三维细分、空集匹配、TP/FP/FN
├── truncation_diagnostics.json    # 截断/未截断对照（见阶段 C）
└── diagnosis_report.md            # 可读结论，含尚未定位的问题与局限
```

只读诊断没有权利改写 `run_manifest.json`、历史 `metrics.json`、Raw/Submission、D0.3 数据和 E00.2 原报告；如需要补充正式报告，**新增修订附录**并引用诊断 run/hash，不覆盖原始数值。

### 阶段 C：预算与截断归因（复用已经记录的数据）

1. 根据 `performance_report.json` 的 `sample_diagnostics`（`original_history_messages`、`retained_history_messages`、`removed_history_messages`、`client_prompt_tokens` 等）按真实 Smoke 的 20 个 ID 判断是否发生 T1 裁剪；和 `raw_predictions` 的 `removed_history_messages` 相互核验。
2. 记录两组本应相同的裁剪决定是否**逐 ID 完全一致**，并输出本轮 Smoke 的截断比例，而非使用 Val 24.81% 或全 Dev 31.26% 代替。
3. 分别报告截断/未截断子集的样本数及当前 Accuracy、原始 JSON、原始 A0 Schema、回复空值率；小样本子集只做描述，**不作显著性结论**。
4. 如需未截断 Prompt 的精确 Token 长度，优先复用 D0.4.2 `outputs/token_audit/v1` 的逐样本统计并按原 `sample_id` 对齐；仅在必要时调用已冻结 Tokenizer/P0/F2 编码重新计数，绝不能把完整历史补入已经运行过的 Smoke 预测。
5. 不因为审计发现裁剪就直接改变 P=1280、T1 或 S=2048。若有充分证据显示裁剪显著干扰某些样本，再提出一份**另设 run/config 的 P 敏感性小规模对照方案**，留待批准后执行；禁止将不同 P 下的结果混成同一实验。

### 阶段 D：Prompt / 训练协议一致性审查（只读为主）

- 抽查 `src/shared/prompting.py` 与 `src/data/sft_dataset.py`、`participant/run_inference.py` 在同一 `history` 下是否复用 P0/F2/T1、`enable_thinking=False` 与相同 Tokenizer 指纹。比较应只针对**训练 Prompt 前缀与推理 Prompt**的语义/Token 边界；SFT 训练另外附有 Gold Completion，是正常差异。
- 检查实际 Completion 的生成边界、EOS 和 `skip_special_tokens=True` 是否按既有设计工作；检查日志里已归档的 `prompt_tokens` 和 history 选择是否符合预算。
- 若没有可复现的差异，结论明确写 `protocol_check_passed`，**不得为了“对齐”而修改冻结协议**。如存在差异，定位最小反例，先补回归测试，再根据是否改变历史实验含义决定修 Bug 还是新建版本。

### 阶段 E：有条件的后续诊断，禁止自动扩大任务

完成 B/C/D 后根据证据做分支选择：

- **若主要是 JSON 外围格式/字段名/标签格式失败**：先在诊断报告中给出确切频数与真实例子特征，再提出最小、独立的修正方案；不可直接静默“自动猜标签”。原始 E00.2 成绩必须保留。
- **若原始字段合法但情绪识别仍弱**：可以建议一个单字段 `emotion_label` 的轻量诊断实验，以区分联合 JSON 任务压力与情绪理解能力；该实验使用**独立 P-diag 与 run ID**，其结果仅是诊断，不能与正式 A0 联合任务的 Accuracy 等量比较。
- **若怀疑标签质量或少数类支持不足**：从当前冻结 Dev/Val 汇总实际 support，附小样本不确定性；不在 E00.2 修改 D0.3 `split.preserve_emotions`、不重划 Dev、不将固定 16 类 Macro-F1 改成只计有 support 类的 Macro-F1。未来如需要其他划分，作为新数据版本另行立项。
- **若要跑 100 条分类-only**：先写明分层取样、随机种子、训练/评测隔离、P/T1、输出 Schema、预期判定指标、预算与独立报告，经队伍确认后再做；本轮默认**不启动新 GPU 实验**。
