# E0.3-A6 F3：512 与 1,024 条 Pilot 扩展对照

## 目的与边界

在 A6 F3 的其余训练设置、Base、F3 输出格式、固定评测集和质量门槛不变的前提下，将 Pilot Train 从 512 条扩至 1,024 条，并按一个 epoch 将优化步数从 128 增至 256。新增 512 条采用相同的确定性分层选择，原有 512 个样本 ID 全部保留。

这是一次补充 Pilot，不是 Full 训练。没有读取官方 Val，也没有改写受保护数据或 F3 协议。训练、预测和评测产物位于忽略跟踪的 `outputs/`。

| Train 样本数 | 512 | 1,024（嵌套包含原 512 条） |

## 结果

### Fast Dev：画像门槛未通过

| 指标 | 512 条 | 1,024 条 | 变化 |
|---|---:|---:|---:|
| 情绪准确率 | 46.25% | 49.38% | +3.13 个百分点 |
| 非空画像预测数 / 160 | 3 | 4 | +1 |
| 33 类画像微 F1 | 0.0375 | 0.0153 | -0.0222 |
| 画像 TP / FP / FN | 5 / 4 / 253 | 2 / 2 / 256 | TP 减少 3 |
| 三个画像维度同时精确匹配 | 37.50% | 36.25% | -1.25 个百分点 |
| Fast 质量门槛 | 未通过 | 未通过 | 两组均未达到非空画像数门槛 |

画像预测的空值率仍然很高。1,024 条组的性格和交流风格维度没有命中正例，兴趣维度微 F1 从 0.1034 降至 0.0678。情绪准确率略有提高，但不能抵消画像信号下降；当前证据不支持“仅翻倍样本即可改善画像预测”。

上述画像指标是固定 160 条评测集上的本地代理指标，样本数较小，不应解释为正式泛化结论。两组使用相同 Fast Dev，因此这是配对小样本对照，而不是独立验证集复现。

### Smoke：生成协议门槛通过

1,024 条组在 32 条 Full-generation Smoke 上全部成功：严格 F3 解析、官方 Schema 校验、Fast/Full 字段前缀一致、非空回复和 EOS 五项均为 100%，Smoke 门槛通过。这说明输出与落盘协议稳定，不代表画像预测质量达标。

### SFT Dev Loss

扩展组的 SFT Dev loss 从 step 64 的 `2.1448` 降至 step 256 的 `2.0011`。训练期损失下降与 Fast 画像指标未同步改善，不能单独作为继续 Full 训练的理由。

## 验证与执行记录

- 1024 条选择和训练资产 CPU 预检通过，原 512 条 ID 均在扩展集合中。
- GPU 单步 Dry Step 验证通过，确认有限 Loss、梯度和 LoRA 参数更新。
- 训练从同一 Run 的 step 64 检查点恢复，未重复前 64 步；step 256 检查点与适配器均成功保存。
- 独立 Adapter reload-check 通过。
- 扩展评测预检通过；`tests/test_e03_a6_f3_pilot_eval.py` 与 `tests/test_e03_a6_training_contract.py` 共 32 项通过。
- Fast 160 完成 160/160 条生成；Smoke 32 完成 32/32 条生成并通过格式门槛。
- Full 训练未运行，训练清单记录 `not_authorized_not_run`。

首次 Dry Step 在首次 optimizer update 前发现 TRL 将 A6 LoRA dtype 转为 BF16 的问题。修复后重新进行 Dry Step，通过后才恢复 Pilot 训练；失败尝试没有产生训练更新。

## 结论

本次扩容提高了情绪准确率，但画像微 F1、TP 数及三维精确匹配均下降，Fast 门槛仍失败。因此不建议基于这组结果启动 Full。下一步应优先验证画像监督和输出/损失设计；完整字段名实验应作为独立协议版本，避免与这次样本量对照混淆。
