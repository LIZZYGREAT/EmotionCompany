# E03 最终镜像可移植性修复与导出记录

> 日期：2026-11-10。范围：修复官方平台启动阶段 `ERROR: backend 必须为 transformers 或 openai_compatible: vllm`，补充环境适配、失败兜底与诊断，复用既有完整镜像构建 Overlay，重新导出 tar。未修改 Base、LoRA、训练产物、冻结 Prompt、提交 Schema 或官方数据。

## 官方日志与根因

官方平台只返回：

```text
ERROR: backend 必须为 transformers 或 openai_compatible: vllm
```

该错误来自 `participant/start.sh` 的单模型分支。镜像原先设置 `EVALUATION_BACKEND=vllm`；当平台使用官方 `participant/configs/inference_config.json`（无 `mode: dual_adapter`）或其它非 Dual 配置时，入口不会进入 Dual 分支，而单模型分支只接受官方 README 的 `transformers` / `openai_compatible`，因此在任何样本推理前退出。

## 修订内容

| 文件 | 修订 |
|---|---|
| `docker/final_dual/Dockerfile`、`Dockerfile.overlay` | `EVALUATION_BACKEND` 改为官方值 `openai_compatible`；复制单模型兜底脚本。 |
| `docker/final_dual/entrypoint.sh`、`entrypoint_args.sh` | 入口改为透传：支持 `bash -lc`、`/bin/bash -c`、`sh -c`、单字符串命令、直接 `start.sh` 路径；未知形式不再 exit 2。无参数仍保持 idle 以支持 `docker exec`。 |
| `participant/start.sh` | 镜像路径 `/root/participant` 下优先使用内置 `configs/deployment/final_dual_docker.json`；所选配置不是 `dual_adapter` 时告警并切换。Dual 分支接受 `vllm` / `openai_compatible` 并统一为内部 `vllm`；导出解析后的配置路径。单模型分支接受 `vllm` 别名；缺失 P/G/K、显存探针时使用兼容默认值；复制 `run_inference.py` / `e02_vllm_probe.py` 后单模型兜底可运行。 |
| `src/inference/final_dual_vllm.py` | `--dtype auto`；`gpu_memory_utilization` 默认 0.7；支持 `VLLM_GPU_MEMORY_UTILIZATION`、`VLLM_PORT`、`VLLM_HOST`、`VLLM_ENFORCE_EAGER`；启动时尝试备用端口、降低显存、`--enforce-eager`。 |
| `participant/final_dual_inference.py` | vLLM 启动或运行失败时按 `fallback.degraded_output_on_runtime_failure` 写出完整空字段 Submission；失败时保留 `vllm_server.log` 与 `runtime_failure.json`；报告补充官方字段（`rounds`、`required_rounds`、`average_latency_ms`、`hardware_label`、`test_file_sha256`、`submission_sha256`、`parse_failure_count` 等）和非致命 Schema 统计。 |
| `configs/deployment/final_dual_docker.json`、`final_dual_v1_2.json` | 版本升为 portable；`dtype=auto`、`gpu_memory_utilization=0.7`、启用 degraded fallback。 |
| `scripts/final_dual_overlay.py`、`final_dual_docker_package.py` | Overlay 复制新运行文件；Smoke 增加 `shell-wrapper`、`bin-bash-command`；导出要求与构建 Image ID 匹配的真实 Smoke；本地 `verify-output` 增加官方 Submission Schema 校验。 |
