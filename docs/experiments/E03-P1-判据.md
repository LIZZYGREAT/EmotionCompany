# E03 P1 底模代理对照：判据（跑之前冻结）

> 冻结时间：2026-11-03 01:35。本文件在任何一轮生成开始之前写定，跑完不得修改分母、阈值或指标定义。
> 口径：Qwen3-1.7B 底模（无 Adapter）。结论只适用于底模，不代表参赛模型 Full B。

## 一、要回答的问题

在同一个底模、同一套 F2/T1、同一批样本上，只把 system prompt 从 P0 换成 P1 的三种写法，输出在格式合法性和指令遵循上有没有可测的差别。

## 二、样本

- 来源：`data/val/val_public.jsonl`，900 段对话，展开 2354 个预测点。
- 抽样：按对话整段抽，seed=20261103，抽 78 段（预计 200 点上下）。
- 代理集 id 列表与展开后点 id 写入 run 目录 `sample_ids.json`；剩余整段封存，本轮不读。
- 禁止：用 Train 抽样（Adapter 在 Train 上训过），用 Dev 错例反推 P1 措辞。

## 三、固定参数（四轮完全一致）

| 项 | 值 |
|---|---|
| 基座 | `participant/model`（Qwen3-1.7B，revision 记入 handoff） |
| 量化 | NF4（nf4、double quant、compute bf16） |
| P（prompt cap） | 1280 |
| G（max_new_tokens） | 1200 |
| 解码 | do_sample=False，greedy |
| 批次 | batch=1，顺序执行 |

## 四、指标（全部基于 raw 输出，不读 submission）

1. `json_object_rate`：raw 能被解析成一个 JSON object 的比例。
2. `required_fields_rate`：四字段 `emotion_label`、`user_profile`、`response_text`、`memory_refs` 齐全的比例。
3. `enum_valid_rate`：情绪与三组画像标签全部落在官方枚举内的比例。
4. `profile_nonempty_rate`：`user_profile` 三维至少一维非空的比例。
5. `schema_extra_label_rate`：出现官方枚举之外标签的比例。
6. `truncation_rate`：生成被 G 截断（finish_reason 为 length）的比例。
7. `empty_response_rate`：`response_text` 为空的比例。
8. `mean_response_chars`：`response_text` 平均字符数。

## 五、判定规则

- **支持**：某变体在指标 1、2、3、9 中至少一项比 P0 高 10 个百分点以上（约 20 条），且没有任一项低 5 个百分点以上，schema 外标签不增加。
- **不支持**：任一项合法率低 5 个百分点以上，或 schema 外标签增加。
- **证据不足**：完成率低于 90%，或失败/OOM 样本超过 10%，或样本 id 与冻结列表不一致，或以上都不满足。

结论只写这三选一，不写「提升多少分」。画像非空率、回复长度只做描述，不判好坏。

### v1.1 追加（2026-11-03 01:36，首轮尚未跑完，未见任何结果）

1. 新增指标 9 `field_type_valid_rate`：`emotion_label`、`response_text` 为字符串；`user_profile` 是对象且三维都是数组；`memory_refs` 是数组。任何类型错单独计数，不计入四字段齐全。
2. 判定阈值由「显著」改为白咲提出的 10／5 个百分点，便于两人独立复核。
3. 「平均丢 8 轮」中的一轮指一条消息（user 或 assistant 各算一条），不是一问一答的对。
4. 三份 P1 比 P0 多 275 到 323 字节，可能让边界样本多裁一条历史：每轮记录 prompt token 与 T1 选中的消息条数，历史选择与 P0 不同的样本单列，并做一次剔除这些样本的敏感性检查。
5. 类型错误（如 `style` 写成字符串）不在本轮临时修，留作 P1-d 候选。

## 七、失败处理

OOM 或单条异常：切块重试同一批，参数不变；连续失败超 10% 即判证据不足并停下写现场。不临时改 G、温度或量化。
