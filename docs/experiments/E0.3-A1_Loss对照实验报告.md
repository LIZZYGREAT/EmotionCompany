`label_value_x2` 通过短程门槛，可以进入完整训练；其改善幅度刚超过最低要求。`profile_x2` 的训练和 Dev Loss 计算也已完成，Base 权重前后 SHA 一致。但它的标签值 CE 只比基线低 1.08%，未达到至少 2% 的要求；重载检查也未通过，因此该组不能进入完整训练。

两组使用相同的固定 128 条 Dev 样本，合计 22,023 个有效 Token，其中精确标签值区域为 418 个 Token。表中 CE 均为未加权的 teacher-forced Dev Loss。

| 条件 | 优化步数 | 全 Token CE | 标签值 CE | 重载检查 | 判定 |
|---|---:|---:|---:|---|---|
| `token_mean` | 128/128 | 1.97281 | 0.70518 | 64 个 Token IDs 完全一致 | 通过，作为基线 |
| `profile_x2` | 128/128 | 1.97389 | 0.69757 | 64 个 Token IDs 不一致 | 未通过 |
| `label_value_x2` | 128/128 | 1.97422 | 0.69081 | 64 个 Token IDs 完全一致 | 通过短程门槛 |

相对 `token_mean`，`profile_x2` 的标签值 CE 改善 `1.08%`，低于 `2%` 门槛；全 Token CE 上升 `0.055%`，在最高 `1%` 的限制内。`label_value_x2` 的标签值 CE 改善 `2.04%`，全 Token CE 上升 `0.071%`，并通过重载检查；因此符合进入完整训练的短程条件。两项百分比均按固定 128 条 Dev 子集计算。

## 重载核对

`profile_x2` 保存前与重载后使用相同的 Prompt Token IDs，且 `do_sample=false`。两次各生成 64 个 Token IDs，从第 14 个 Token 起出现差异。Base 权重 SHA 前后均为 `005d20550c04f4e246e5b434448786b44a0196b47d758d0acc77aba279e5bbc5`；Adapter 文件身份有记录。现有证据无法确定 Token 分叉的具体原因。

`label_value_x2` 保存前后的 64 个生成 Token IDs 完全一致，Base SHA 前后相同。它与 `token_mean` 使用相同的 128 条 Dev 样本和 Loss 区域映射。
