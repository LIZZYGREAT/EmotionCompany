## 数据、训练和推理链路

### 训练链路

```text
官方原始 Train：8,338 段对话 / 18,657 个预测点
  → D0.2 清理：隔离 4 个预测点、去除 508 个重复点
  → D0.3：Train 16,312 / Dev 1,833；官方 Val 2,354 单独保留
  → D0.4.2：对 20,499 条 Train/Dev/Val 做 Token 审计；S=2048/P=1280 为预算候选
  → D0.4.3：P0/F2/T1、Completion-only JSON 编码和动态 Collator
       Train 输入 16,312 → 可用 SFT 16,192
       Dev 输入 1,833 → 可用 SFT 1,821
       Val 2,354 → 仅交叉核对，不生成 SFT 文件
```

D0.4.3 已用真实 Tokenizer、预编码数据和 TRL DataLoader 验证 Prompt `labels=-100`、Completion/EOS 标签与右侧 Padding；验收中的 tiny GPT-2 没有执行 forward、训练循环或反向传播。因此数据通路通过不等于 QLoRA 已能训练。预编码数据与输出清单在本机 `data/processed/sft/v1/`、`outputs/sft_data/v1/`，属于可重建的忽略产物，不在 Git。

### 推理和评测链路

```text
D0.3 Dev 1,833
  → E00.1 生成无标签 inference_input + References + ID Map
  → 固定种子选 20 条 Smoke
  → E00.2：同一 Qwen 权重、P0/F2/T1、Greedy 与 Sampling 各生成 20 条
  → Raw / Submission / Performance → E00 scorer 与离线归因
  → E00.2-D：同 20 条及 A0 已选历史，以 Pdiag-E1 做单字段 Greedy 诊断
```

E00.1 的 1,833 行 Dev 适配器和评分链通过 Mock 验收；Mock 不代表模型能力。E00.2/E00.2-D 的 Raw 和逐条评分留在本机 `outputs/evaluation/`。所有报告保留输入 ID、配置和模型指纹；未把参考标签放入推理输入。E00.2 仅跑 20 条 Smoke，性能报告要求的 100 轮未完成；E00.3 全 Dev、官方性能轮次、vLLM/Docker 和服务端 Token ID 等价均未验收。

## 实验汇总

| 实验 | 身份与范围 | 主要结果 | 解释边界 |
|---|---|---|---|
| E00.1 | 1,833 Dev 适配器；合成 4 条及真实 Smoke ID 的 Mock 闭环 | ID、Hash、目标隔离与本地指标处理通过 | `mock_fixture`，不是 Qwen 推理或模型分数 |
| E00.2 Greedy | `E00.2-20261026-220635`；真实 Qwen；20 条 | Emotion Accuracy 1/20，Macro-F1 0.0179；Raw 严格 JSON 10/20、Raw A0 Schema 0/20，归一化 Submission Schema 20/20 | 真实基础模型 Smoke；非完整 Dev、非官方基线 |
| E00.2 Sampling | 同 Run ID；同 20 条、权重和 P0/F2/T1 | Accuracy 1/20，Macro-F1 0.0179；Raw 严格 JSON 9/20、Raw A0 Schema 0/20，Submission Schema 20/20 | 20 条不足以判定优于 Greedy；BERTScore `not_run` |
| E00.2 归因 | 对上述 Greedy/Sampling Raw 做离线逐字段审查 | Greedy 宽松提取 11 条合法情绪（1 正确、10 错）；Sampling 10 条（1 正确、9 错）；格式错误与分类错误并存 | 未发现可复现 Parser/归一化实现错误；归一化 Submission 合法不代表 Raw 合法 |
| E00.2-D | `E00.2-D-emotion-003`；真实 Qwen、Pdiag-E1、同 20 条历史 | 严格单标签 15/20，Accuracy 0/20，Macro-F1 0；20/20 EOS，未达生成上限 | `diagnostic_only`；输出合同和任务说明均变化，不能取代 A0 或作因果结论 |

E00.2-D 的 15 个严格合法预测都没有命中 Gold；Train 多数类 `anxiety` 在该 Smoke 上为 2/20。A0 的 11/20 来自宽松提取器，与 E00.2-D 严格原文匹配不是同一格式口径，不能直接比较两者合法率。诊断细节和同 ID 转移见 [E00.2-D 报告](E00.2-D_单字段情绪诊断报告.md)。

## E01 起点和通过条件

下一项工作应单独制定 **真实 Qwen3-1.7B + NF4 QLoRA + Completion-only SFT 的最小可学习性方案**。`src/training/training_sft.py` 当前为空文件；不能假定仓库已有真实训练入口。先从 D0.4.3 Train 选择少量样本做 micro-overfit，训练集拟合成绩不当作泛化结论。

通过门槛至少包括：

1. 训练输入与 D0.4.3 标签逐元素一致；Prompt 标签全为 `-100`，Completion/EOS 保留监督，Dev 不参与训练。
2. 基础模型按锁定 Qwen3-1.7B 权重加载并冻结；只有预期的 LoRA 参数可训练，记录参数数量和梯度。
3. 真实 forward/backward 与至少一个 optimizer step 成功，Loss 和梯度有限，Adapter 参数确实改变；记录峰值显存、耗时、seed 和配置 Hash。
4. Adapter 可保存并重新加载到相同基础权重；重载后使用相同 P0/F2/T1 和 Tokenizer 做确定性推理。
5. 分开报告训练样本 micro-overfit 和独立 Dev 表现。若后续比较 E00/E01，使用相同输入、Prompt、历史、解码和评分定义，标注各自 Run ID。

已有资产包括 `configs/sft_data.yaml`、`src/data/sft_dataset.py`、`src/data/sft_collator.py`、`src/data/sft_trainer_validation.py`、共享 `src/shared/prompting.py` 和 `participant/model` 本地路径契约。P0 SHA 为 `d427e4996d0075a3adfe03ae25881d093687a6565f5b037f605accecc84c70b2`；Tokenizer 签名和 Chat Template 指纹见 D0.4.3 报告。两台机器应各自确认本地权重和数据存在，并比对权重聚合 SHA、Tokenizer 签名、Template SHA 与配置版本；克隆仓库不包含本地模型和生成数据，缺少时按 [workflow](../workflow.md) 重建，不经 Git 传模型、Raw 或处理数据。

若先不跑 E00.3，后续仍须把 E00.2 结果称作 20 条 Smoke 探索。要形成完整 Dev 的 E00/E01 公平对照时，再单独确定并执行同协议全 Dev 评测。
