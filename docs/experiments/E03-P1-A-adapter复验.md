# E03 P1 复验：在 E01-B Full Adapter 上重跑四轮

> 口径：本机 Transformers + NF4 + PEFT 挂 `E01-B Full` Adapter，不是官方 vLLM 服务，结论只到「本地 Full B 权重」。
> 日期：2026-11-04。运行 `p1-adapter-run1-20261104`。

## 一、目的

昨天在底模上，P1 三种写法与 P0 在格式上有差异，其中 p1-c 五项一致改善。本轮把同一个 Adapter 挂上去，重跑四轮，检验那些差异在真模型上还在不在。

## 二、方法与核验

- Adapter：`E01-B-FULL-20261028-133805/adapter`，`adapter_model.safetensors` sha256 `83d1ccb0…`（与 manifest、checkpoint-4048 副本一致），`adapter_config.json` sha256 `05d578eb…`；base 为 `Qwen/Qwen3-1.7B`，LoRA r=8、alpha=16、七个 target、`inference_mode=true`。
- 挂载：`PeftModel.from_pretrained`，基座同前（NF4、compute bf16）。
- 样本：与昨天同一批 209 点（seed 20261103，78 段），`sample_ids.json` 未改。
- 参数：P=1280、G=1200、do_sample=False、batch=1，四轮同一进程。
- 新增依赖：`.venv` 原缺 `peft`，安装 0.21.2（与 adapter 记录的 peft 版本一致）。

## 四、判定

按冻结判据（升 10 个点算有信号、降 5 个点算不支持、其余证据不足）：

- **p1-a、p1-b、p1-c 全部为「证据不足」**。四轮格式指标差异在 1.4 个百分点以内，没有任何一项达到 10 点或掉 5 点。本轮没有变体达到「支持」。

## 五、关键发现

1. **底模上的 P1 收益不能外推。** 底模格式本来就没学对，P1 的措辞差异被格式噪声淹没；挂上 Adapter 后格式接近饱和，P1 的边际收益消失。
2. **P1 没有救回画像漏报，反而略微压低。** 画像非空率 P0 40.67%，三个变体 32.5%–36.8%，都低于 P0。方向上支持「底模上的非空率提升是格式修复带来的假象」。
3. **`emotional_stable` 错拼在真模型上不存在。** 四轮外标签均为 0，昨天底模上那个 80% 占比的错拼是底模不会拼标签的产物。原计划 P1-d 先修拼写，这条在真模型上不成立，优先级可以撤掉。
4. **p1-c 的格式优势同样消失。** 它在底模上有五项改善，在 Adapter 上是四轮里最低的 97.61%，虽然差异不显著。

## 六、局限

1. 本机 Transformers + NF4 + PEFT，不是官方 vLLM 服务；官方部署口径仍待验。
2. 只有 209 点，1–2 个百分点的差异无法判定显著性。
3. 只比了格式与结构指标，情绪、画像 F1 需要 Gold 评分，本轮未做。
4. 执行环境仍是 WSL 旧 checkout 加本地改动；Adapter 从 Windows 侧 `/mnt/c` 路径加载。

## 七、下一步

1. Prompt 这条线到此为止：真模型上格式已饱和，继续调指令的收益预期很低。
2. 画像漏报不是提示词能解决的，方向上应转向训练侧（字段 Loss、数据）或 T2 的历史信息组织。
3. 若还要做 P1，唯一有意义的方向是情绪/画像准确率而不是格式，但需要 Gold 评分与更大样本。
