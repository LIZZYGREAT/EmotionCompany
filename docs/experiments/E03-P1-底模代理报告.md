# E03 P1 底模代理对照：P0 与三个提示词变体

> 口径：Qwen3-1.7B 底模（无 Adapter）。结论只适用于底模，不代表参赛模型 Full B。
> 日期：2026-11-03。判据见 `E03-P1-判据.md`（跑前冻结，v1.1 追加）。

## 一、目的

同基座、同 F2/T1、同样本，只换 system prompt（P0 → p1-a/b/c），看格式合法性与指令遵循有没有可测差异。不回答情绪、画像准确率是否提升。

## 二、方法

- 样本：Val 900 段按 seed 20261103 整段抽 78 段，展开 209 点；其余整段封存。
- 参数：NF4、P=1280、G=1200、do_sample=False、batch=1，同一进程顺序跑四轮。
- 指标全部来自 raw 输出，不读 submission。
- 三个变体都只比 P0 多一段，分别管时间范围（a）、证据来源（b）、不确定处理（c）。

## 三、结果

四轮都是 209 点，截断率均为 0。

| 指标 | P0 | p1-a | p1-b | p1-c |
|---|---:|---:|---:|---:|
| JSON object 可解析率（可抽取：文中抠对象） | 76.08% | 67.46% | 63.16% | **88.52%** |
| JSON object 可解析率（严格：整串解析，判定主口径） | 50.24% | **61.24%** | 48.80% | **57.42%** |
| 四字段齐全率 | 55.50% | 61.24% | 52.15% | **64.59%** |
| 字段类型合法率 | 5.74% | 11.96% | 6.70% | **13.88%** |
| 枚举全合法率 | 1.91% | 0.00% | 5.26% | **9.57%** |
| 画像非空率 | 50.72% | 55.98% | 22.49% | 53.11% |
| schema 外标签：样本率 / 标签数 | 40.19% / 94 | **54.07% / 135** | 18.18% / 47 | **43.06% / 102** |
| 空回复率（操作定义：无 response_text 或不可解析） | 44.50% | 38.76% | 47.85% | **35.41%** |
| 回复平均字符数（209 条全算，无回复记 0） | 51.0 | 53.2 | 48.5 | 57.6 |

**这四项是逐级通过率，不是四个独立指标**：先要能解析，才谈四字段齐全；齐全才查类型；类型对了才查枚举。所以枚举从 1.91% 到 9.57%，主要来自解析和字段补齐，不能直接读成「标签判断变好」。

**解析必须分两个口径**：可抽取口径（文中找第一个闭合对象）是 76.08／67.46／63.16／88.52，严格口径（整串即 JSON）是 50.24／61.24／48.80／57.42。冻结判据的字面是「raw 能被解析成一个 JSON object」，因此**判定以严格口径为主**。可抽取口径下 P0 的 76.08% 里有 49 条是散文加 JSON、9 条是 ```json 围栏、46 条是纯散文，抠出来的常常只是 `user_profile`，缺 `emotion_label` 和 `response_text`。

口径换了结论会变：严格口径下 p1-a 升 11.0、p1-c 升 7.2、p1-b 只降 1.4；可抽取口径下 p1-a 降 8.6、p1-b 降 12.9。下版判据先写死用哪个。

## 四、判定

按冻结判据字面、以严格口径为主：

- **p1-a：不支持**。严格解析升 11.0 个点，但外标签从 94 个涨到 135 个、样本 84→113（42 新／13 失，p≈1.1e-4），按「外标签不增加」不通过。
- **p1-b：证据不足**。没有一项合法率降 5 个点以上（严格解析 −1.4，p=0.63）；外标签从 94 降到 47、样本 84→38，大幅改善。若用可抽取口径则是「不支持」（解析 −12.9），判定依赖口径，报告中两说。
- **p1-c：不支持**。严格解析 +7.2，未达 10 个点线；外标签 94→102 个、样本 84→90（30 新／24 失，p≈0.50，属噪声但字面算增加）。它是唯一在解析、字段、类型、枚举、空回复五项一致改善的变体。

**格式改善是真的，判据不通过是判据口径不完善**，两者要分开写。p1-c 的收益不会因为判据字面不通过而消失。

**外标签的构成值得单说**：约六到八成是把 `emotionally_stable` 拼成了 `emotional_stable`（四轮占比 79.8%／71.3%／63.8%／80.2%，标签数 75／97／30／81）。只做一个拼写映射，枚举合法从 P0 的 4 条升到 9 条、p1-c 从 20 条升到 24 条。这条只作描述，不进判据。

**表格里的样本率和标签数是两个口径**：样本率按交付 `check` 的口径（至少一个外标签的样本），标签数是**交付 `check` 判定样本内的外标签总数**（与样本率同源，所以 p1-a 是 135 而不是全可解析口径的 136，差在 `val_conv_000694_3`：解析成功、缺 `memory_refs`、带 1 个外标签）；判定用的是样本率。

## 五、敏感性

四份 prompt 长度不同，T1 选择在 26 个点上与 P0 不同。剔除这 26 点后用 183 点重算：p1-c 宽松解析 88.52→89.07、字段 64.59→66.67、类型 13.88→15.85、枚举 9.57→10.93、外标签 43.06→44.81，结论方向不变。

每轮每点的 T1 选中消息数与 prompt token 记在 run 目录 `t1_selected.json`，可独立复核这 26 个点。

## 六、局限

1. 底模没学过标签与格式，画像接近地板；本实验只能说明「在底模上这条提示写法有没有改善格式」，不能推到参赛模型。
2. 无 Adapter、无 Full B 逐样本预测，未做与画像漏报的交叉。
3. 执行环境为 WSL 旧 checkout（main 9e79961）加 E01/E02 遗留改动；提交在干净 clone，最终头 `469fb57`（P1）／`5b5eb38`（统计）。P0 在提交树里有 blob，sha256 与冻结值 `d427e4…` 一致，**blob 仲裁通过**；「configs/prompts 未被跟踪」只适用于那个 WSL 旧 checkout，不是上游缺失。
4. 判据 v1.1 的文本在 2026-11-03 01:35:41 发布于群内，本地文件 mtime 01:35:49，开跑 01:38；提交到 git 是 03:02，git 时间戳不能证明先后，以群内消息和 mtime 为准。
5. 空回复的判据原文写「response_text 为空」，实现是「缺失或不可解析」，报告按操作定义写，下一版判据改词。
6. 外标签判定用的是「样本率」；标签总数另列，两者不可混用。

## 七、下一步
