# E03 P1 底模代理对照：P0 与三个提示词变体

> 口径：Qwen3-1.7B 底模（无 Adapter）。结论只适用于底模，不代表参赛模型 Full B。
> 日期：2026-11-03。判据见 `E03-P1-判据.md`（跑前冻结，v1.1 追加）。

## 一、目的

同基座、同 F2/T1、同样本，只换 system prompt（P0 → p1-a/b/c），看格式合法性与指令遵循有没有可测差异。不回答情绪、画像准确率是否提升。

## 二、方法

- 样本：Val 900 段按 seed 20261103 整段抽 78 段，展开 209 点；其余整段封存。
- 参数：NF4、P=1280、G=1200、do_sample=False、batch=1，同一进程顺序跑四轮。
- 指标全部来自 raw 输出，不读 submission。
- 三个变体都只比 P0 多一段，分别管时间范围（a）、证据来源（b）、不确定处理（c）。

## 三、结果

四轮都是 209 点，截断率均为 0。

| 指标 | P0 | p1-a | p1-b | p1-c |
|---|---:|---:|---:|---:|
| JSON object 可解析率 | 76.08% | 67.46% | 63.16% | **88.52%** |
| 四字段齐全率 | 55.50% | 61.24% | 52.15% | **64.59%** |
| 字段类型合法率 | 5.74% | 11.96% | 6.70% | **13.88%** |
| 枚举全合法率 | 1.91% | 0.00% | 5.26% | **9.57%** |
| 画像非空率 | 50.72% | 55.98% | 22.49% | 53.11% |
| schema 外标签率 | 40.19% | **54.07%** | 18.18% | **43.06%** |
| 空回复率 | 44.50% | 38.76% | 47.85% | **35.41%** |
| 回复平均字符数（全量） | 51.0 | 53.2 | 48.5 | 57.6 |

**这四项是逐级通过率，不是四个独立指标**：先要能解析，才谈四字段齐全；齐全才查类型；类型对了才查枚举。所以枚举从 1.91% 到 9.57%，主要来自解析和字段补齐，不能直接读成「标签判断变好」。

## 四、判定

按冻结判据（至少一项升 10 个点、没有任一项降 5 个点、schema 外标签不增加）：

- **p1-a：不支持**。JSON 可解析率降 8.6 个点，外标签升到 54.07%。
- **p1-b：不支持**。可解析率降 12.9 个点；外标签大幅降到 18.18%，但整体格式更差。
- **p1-c：不支持**。可解析率升 12.4 个点、字段升 9.1、类型升 8.1、枚举升 7.7、空回复降 9.1，是三个里唯一在多项上明显改善的；但 schema 外标签从 40.19% 升到 43.06%，按「外标签不增加」这一条被判不通过。

p1-c 的失败点值得单说：它同时让更多样本给出画像（非空率 50.7→53.1），外标签率上升可能只是「写得更多所以错得更多」。这是判据口径问题，不是结果变差。是否把该条改成「外标签比例不劣化超过 X」或按标签总数算，需要下一轮改判据，本轮不改。

## 五、敏感性

四份 prompt 长度不同，T1 选择在 26 个点上与 P0 不同。剔除这 26 点后用 183 点重算：p1-c 可解析 88.52→89.07、字段 64.59→66.67、类型 13.88→15.85、枚举 9.57→10.93、外标签 43.06→44.81，结论方向不变。

## 六、局限

1. 底模没学过标签与格式，画像接近地板；本实验只能说明「在底模上这条提示写法有没有改善格式」，不能推到参赛模型。
2. 无 Adapter、无 Full B 逐样本预测，未做与画像漏报的交叉。
3. 执行环境为 WSL 旧 checkout（main 9e79961）加 E01/E02 遗留改动，提交在干净 clone 的 `92eaa03`；`configs/prompts` 在该 clone 未被 git 跟踪，P0 哈希以文档为准。

## 七、下一步

1. p1-c 值得在 Adapter 上复验：它是唯一在解析、字段、类型、枚举、空回复五项都改善的写法。
2. 单独做 P1-d 处理 `style` 类型错误（要求输出数组），这不属于本轮，也不改本轮结论。
3. 判据里「外标签不增加」改为按标签总数或允许小幅劣化，需两人先对齐再冻结下一版。
