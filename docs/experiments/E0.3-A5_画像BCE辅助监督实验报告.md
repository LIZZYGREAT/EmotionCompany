## A5.0 数据对齐和监督语义

### A5.1 CPU 实现和 preflight

新增的 Prompt-only 路径只把每条 SFT `input_ids[:prompt_length]` 送入冻结模型，并从最终归一化层 Hook 取 `prompt_length - 1`。Hook 与因果 LM logits 共用同一次前向，保留训练图供 A5.2 使用；探针拟合固定在 CPU FP32。合成测试覆盖互相矛盾 Gold 后缀不影响特征、故意错取最后 Token 能检测泄漏、右填充位置、Hook 梯度、FP32 Masked BCE、`λ=0` 的 CE 梯度精确等价及固定阈值重现。

实际 CPU 检查：`.venv/bin/python -m pytest -q tests/test_e03_a5_integration.py tests/test_e03_a5_probe.py` 为 `13 passed`；`compileall` 通过。命令 `.venv/bin/python -m scripts.e03_a5_probe cpu-preflight --audit-run-id E03-A5-SUPERVISION-20261106-04` 返回 `cpu_preflight_passed`，绑定配置 SHA `877b96fba1cdd5e91ec9b42a91acdb7c039ab958d9170dd265ee1e1ca2b34086` 与 A5.0 Audit Manifest SHA `dbfd4e62bc3c9b56a4dcbd839d94205b2c62e84d34c0823d185d6f2f58a4b598`。Fit/Calibration/Internal Holdout 为 11,304/2,455/2,433 行；`gpu_run_started=false`。这只证明输入身份和 CPU 路径就绪，不是模型探针结果。

### A5.2 配对训练 CPU 实现

新增的配对 Runner 先按固定 seed 从 Train Fit 冻结 128×1×4=512 个无放回样本，Control 与 Candidate 共用完全相同的顺序和微批次。准备阶段核对完整 SFT Train SHA、Train-only 来源、监督 ID 集和 Prompt/Completion Token Mask；Manifest 保存 schedule、标签、协议和初始模型身份的 Hash。dry-step 固定选 schedule 中最长序列，并仅右填充到完整 S=2048，不缩短序列或更换精度。

Control 固定 `λ=0`，只计算原始 Completion-only CE；其辅助头初始化后冻结、不计算 BCE。Candidate 用同一初始化辅助头计算 FP32 BCE，并以冻结的正 λ 更新 LoRA 与分类头。每个样本的 Completion CE 先按有效 Token 求均值，再对 4 个微批次做梯度累积；A5 λ=0 实现对独立标准 CE 的分微批次梯度回归已通过。两组重新加载相同只读 E01-B Adapter，分别创建新 AdamW 状态；不恢复 A4/E01-B 优化器。训练、重载、Base/Adapter 只读检查与候选打分均由不同阶段 Run Manifest 记录。

Probe Gate 必须基于完整 A5.1 报告显式冻结；dry-step 和 Control/Candidate 训练分别要求阶段、Run ID、Pair、Gate、组别、λ、配置/监督 Hash 与预算相符的独立票据。两组 2048-token dry-step 通过后，另以审阅者和理由冻结 λ，不改写 A5.0 已绑定的配置文件。当前 λ `0.1` 仍标记 provisional，实际训练命令会在缺少 `probe_supported` Gate、任一 dry-step 或 λ 冻结时拒绝。

新增 schedule、梯度、头部重载和票据合同合成用例后，四个 A5 测试文件合计 `.venv/bin/python -m pytest -q tests/test_e03_a5_labels.py tests/test_e03_a5_probe.py tests/test_e03_a5_multitask.py tests/test_e03_a5_integration.py` 为 `29 passed`；全部 A5 脚本/模块 `compileall` 通过。该结果是 CPU 实现证据，不代表任何 GPU 前向、dry-step 或训练通过。
