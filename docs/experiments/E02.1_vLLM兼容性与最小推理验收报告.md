# E02.1 vLLM + Full B Adapter 兼容性与最小推理验收

> 记录范围：版本/参数静态依据、代码门禁、独立运行配置与验收协议。<br>
> GPU smoke 由使用者执行后，在忽略的 `outputs/evaluation/e02/<RUN_ID>/run_manifest.json` 保存实际结果；本文件不预填未经运行的显存、延迟或生成结论。<br>
> 基线身份：[E02 Full B 基线资产与证据索引](E02_基线资产与证据索引.md)

## 1. 部署判断

现有 vLLM Base-only 路径不能代表 Full B。E02 配置现在使用独立 LoRA 别名 `e01-full`；只有在 vLLM 注册该 Adapter、`/v1/models` 返回该别名、Runner 每次请求使用该别名且本地 Base/Adapter 文件 Hash 与冻结值一致后，才记录“本地启动输入和请求路由已核验”。vLLM 服务端实际权重仍标记 `unverified`，不会由本地 Hash 或模型列表冒充证明。

目前固定一个**可复现的兼容性目标版本**：vLLM `0.11.1`。该版本官方安装文档记录 CUDA 12.8 预编译轮子及 Linux/Python 3.10 支持；同系列模型列表包含 `Qwen3ForCausalLM`；LoRA 文档定义 `--enable-lora`、`--lora-modules name=path`、`--max-lora-rank` 及通过请求 `model` 指定 LoRA 名称。项目 `scripts/e02_vllm_probe.py` 会在运行前核验安装版本与 CLI 参数，避免使用不匹配的最新版本或靠文档猜测兼容性。

官方依据（访问日期 2026-10-29）：[vLLM 0.11.1 GPU 安装与 CUDA/Python 支持](https://docs.vllm.ai/en/v0.11.1/getting_started/installation/gpu/)、[vLLM 0.11.0 支持模型列表](https://docs.vllm.ai/en/v0.11.0/models/supported_models.html)、[vLLM 0.11.2 LoRA 适配器与请求路由](https://docs.vllm.ai/en/v0.11.2/features/lora/)、[vLLM 0.11.1 `serve` CLI 参数](https://docs.vllm.ai/en/v0.11.1/cli/serve/)。版本文档能说明候选参数和模型架构支持，不能替代 Full B 本地权重、真实服务器和 GPU 实测。

## 2. 冻结的最小 smoke 配置

可执行配置和版本 pin：

```text
configs/deployment/e02_vllm_smoke.json
configs/deployment/e02_vllm_requirements.txt
```

| 项目 | Smoke 设置 | 解释 |
|---|---|---|
| vLLM | `0.11.1` | 独立环境的精确版本；不安装到训练 `.venv` |
| Base | `Qwen/Qwen3-1.7B`，冻结 Base SHA `005d2055…e5bbc5` | 从本地 `participant/model` 启动 |
| LoRA | `e01-full`，rank 8，7 个冻结 target modules | Full B Adapter SHA/config SHA 与索引逐项比较 |
| 计算 dtype | BF16 | 原始 Base `config.json` 声明 BF16；不把 Transformers 的 NF4 训练设置误当 vLLM 量化格式 |
| Context | P=1,280，G=1,200，候选 K=2,560 | P+G=2,480≤K；K 只作为待实测预算候选 |
| 调度 | `max_num_seqs=1`、`max_num_batched_tokens=2,560` | 10 条逐条小样本，不测试并发性能 |
| 解码 | Greedy、`max_tokens=1,200`、`enable_thinking=false` | 不变更 P0/F2/T1 或 Full B Adapter |
| 样本 | 从现有无标签 `id+history` Dev 输入按 History 字符长度抽 10 条 | 输入中不得包含 Gold/target；原文只留在本机 ignored `outputs/` |

该设置不预判 8 GiB GPU 一定能启动。若加载失败/OOM，保留真实 Run 日志和错误，不在同一次 Run 中自动降低 K、Rank 或改量化继续执行。

## 3. 实现与身份门禁

### `participant/start.sh`

- 保持官方两参数入口、固定 `conda_env` 环境、默认 Transformers 路径和 `submission.jsonl` / `performance_report.json` 契约。
- 启动时从 `CONDA_EXE` 或 `PATH` 定位 Conda，执行 `conda shell.bash hook` 后激活固定环境 `conda_env`；不依赖固定的 `/etc/profile.d/conda.sh` 路径。若环境已激活则复用当前环境。
- 仅当所选推理配置显式启用 Adapter 时，追加 `--enable-lora --lora-modules <alias>=<path> --max-lora-rank 8`；默认配置不启用 LoRA。
- 在启动前调用预检程序验证 Base/Adapter 文件哈希、Adapter Base reference、LoRA rank、7 个 `target_modules`、vLLM 精确版本和所需 CLI 参数。
- 服务 Health 成功后还要验证 `/v1/models` 返回请求模型 ID；别名未出现时直接失败。可将启动日志写入本 Run 目录，拒绝覆盖同名日志。
- Run Manifest 保存实际 vLLM 命令参数；API Key 值会替换为 `<redacted>`，同时记录是否配置了 API Key。
- Run Manifest 记录执行时的 Git Commit、分支、工作区状态指纹，以及启动器、Runner、E02 probe、共享协议和 smoke 配置的文件 Hash。
- 可用 `E02_VLLM_RUN_ROOT` 生成只含统计和 Hash 的 Run Manifest，不改变默认比赛输出行为。

### `participant/run_inference.py`

- API 请求仍使用 `config.api_model`；启用 Adapter 时强制该值等于冻结的 `expected_server_model_id`，并要求该 ID 出现在启动器核验的服务模型列表中。
- API 报告分别记录本地 Base/Adapter 文件 Hash、所请求 LoRA 别名、服务端列表中观察到的路由、vLLM 版本和显存观察值。
- `model_weight_identity.identity_status=server_unverified`、`server_weight_identity=unverified`。这会阻止 E01 Transformers Scorer 把 vLLM Run 错记为已验证模型权重身份。
- 服务端完整 Token IDs 尚不可从兼容 API 获得时，报告保留 `not_verified`；客户端 Token 数一致不充当服务端 Token ID 等价证明。

### CPU 检查

`scripts/e02_vllm_probe.py` 提供：

- `preflight`：文件 Hash、Full B LoRA 结构、Rank、别名和 vLLM CLI 版本/参数门禁，不加载模型；
- `make-sample`：拒绝包含 target/Gold 的输入，生成 5～20 条短到长 History 样本；
- `models`：读取服务模型清单并验证请求路由；
- `gpu-facts`：服务启动后采集 `nvidia-smi` 的设备、Compute Capability、Driver 和显存观察值；
- `write-manifest`：将输入、输出、配置和环境指纹写入新 Run，拒绝覆盖已有 Manifest；不保存原始对话到 Git。

纯 CPU 测试覆盖合成 Base/Adapter Hash、Rank/别名错误、Base-only 服务缺失 LoRA 路由、API 请求 LoRA 名称、Gold 输入拒绝和 Run Manifest 的服务身份边界。

## 4. GPU 最小运行命令

命令须在 Linux/WSL 项目仓库中，由使用者按需执行。vLLM 安装在项目外的独立目录；项目训练 `.venv` 与已完成权重不升级或改写。官方入口仍固定激活 `conda_env`；若本地没有该环境，应先补齐官方运行环境再调用入口。

### 4.1 建立隔离 vLLM 环境与运行目录

```bash
cd ~/projects/EmotionalCompany

VLLM_ENV_DIR="$(python3 -c 'from pathlib import Path; print(Path.home() / ".venvs/e02-vllm-0.11.1")')"
python3.10 -m venv "$VLLM_ENV_DIR"
"$VLLM_ENV_DIR/bin/python" -m pip install --upgrade pip
"$VLLM_ENV_DIR/bin/python" -m pip install \
  --extra-index-url https://download.pytorch.org/whl/cu128 \
  -r configs/deployment/e02_vllm_requirements.txt
"$VLLM_ENV_DIR/bin/python" -m pip check

RUN_ID="E02.1-VLLM-FULLB-$(date -u +%Y%m%dT%H%M%SZ)"
RUN_ROOT="$PWD/outputs/evaluation/e02/$RUN_ID"
mkdir -p "$RUN_ROOT"
"$VLLM_ENV_DIR/bin/python" -m pip freeze > "$RUN_ROOT/vllm_environment_freeze.txt"

python3 scripts/e02_vllm_probe.py make-sample \
  --source outputs/evaluation/e00_1/dev_adapter_v2/inference_input.jsonl \
  --output "$RUN_ROOT/test_input.jsonl" \
  --count 10
```

`make-sample` 只接受字段恰为 `id` 与 `history` 的输入。核对输出报告显示 10 行，输入 Hash 与文件路径后即可继续。

### 4.2 按固定比赛入口运行 LoRA Smoke

```bash
EVALUATION_INFERENCE_CONFIG="$PWD/configs/deployment/e02_vllm_smoke.json" \
EVALUATION_RUN_ID="$RUN_ID" \
EVALUATION_RAW_OUTPUT_PATH="$RUN_ROOT/raw_predictions.jsonl" \
E02_VLLM_RUN_ROOT="$RUN_ROOT" \
VLLM_LOG_FILE="$RUN_ROOT/vllm.log" \
VLLM_BIN="$VLLM_ENV_DIR/bin/vllm" \
PYTHON_BIN="$PWD/.venv/bin/python" \
VLLM_LORA_ENABLED=true \
bash participant/start.sh \
  "$RUN_ROOT/test_input.jsonl" \
  "$RUN_ROOT/runner"
```

入口会在启动 vLLM 前拒绝错误权重/别名/版本/参数；启动后核验 Base 与 `e01-full` 路由，逐条运行 Runner，最后创建 `run_manifest.json`。该 Manifest 的 `status=completed` 只表示本次程序完整写完并通过结构检查；`acceptance_status` 仍应根据服务端 Token IDs 可观察性和输出错误明细判断。它不会宣称 vLLM 内部模型权重已独立证明。

若命令在创建 Run 目录之后中止，不要复用同一 Run ID 覆盖记录；保留已有日志/部分结果，修复原因后重新生成 Run ID。不要自动改成完整 Dev、100 轮性能测试或 Docker 构建。

## 5. Run 后核验

```bash
cat "$RUN_ROOT/run_manifest.json"
python3 -m json.tool "$RUN_ROOT/runner/performance_report.json" >/dev/null
sha256sum \
  "$RUN_ROOT/run_manifest.json" \
  "$RUN_ROOT/runner/submission.jsonl" \
  "$RUN_ROOT/runner/performance_report.json" \
  "$RUN_ROOT/raw_predictions.jsonl"
```

需要回报：Run Manifest、vLLM 版本和环境 freeze、实际 GPU/显存、输入与输出行数、模型请求 ID、Raw parse/Schema 错误计数、平均/P50/P95 延迟、OOM/异常日志。不要仅凭 `/health` 或 `/v1/models` 将运行写作 Full B 服务端 Adapter 权重已验证。

## 6. 验收口径与后续

| 层级 | 当前程序能提供的证据 | 结论边界 |
|---|---|---|
| Base/Adapter 身份 | 本地 SHA、config SHA、LoRA rank/modules 与配置核验 | 只证明启动输入文件身份 |
| 服务路由 | `/v1/models` 包含 `e01-full`，客户端请求的 `model=e01-full` | 证明路由名被公布且被请求；不证明服务内部权重文件来源 |
| 输入协议 | 本地 P0/Tokenizer 指纹、客户端编码、服务侧 prompt token 数（若 API 返回） | 没有服务端完整 Token IDs 时，等价性仍 `not_verified` |
| 输出行为 | 10 条 Raw/Submission、A0/提交 Schema 错误、EOS/G、响应和延迟记录 | 只作可行性 Smoke，不得拿小样本分数挑方案 |
| 资源 | 服务启动后的 `nvidia-smi` 总显存观察、vLLM 版本与日志 | 只描述该 GPU/该版本/单请求配置 |

只有本次运行无启动/OOM/身份路由错误、样本与输出契约完整且可观测层通过，才可记 `passed_minimal_smoke`。服务端 Token IDs 或权重来源不可观测时，维持 `partial / not_verified`。完整容器、官方入口在干净交付环境的复核、长序列与正式性能测试属于 E02.2；官方分数/指标对照继续等待赛事方评分来源。
