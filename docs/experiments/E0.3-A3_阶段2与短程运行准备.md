## 当前状态

用户已明确授权单一 Control/Candidate 短程对照。阶段 2 工程实现及 CPU 验收通过。**本轮没有执行 GPU dry-step、训练或模型生成**；下文命令由用户在 GPU 环境执行。阶段 4 的完整 4,048 步训练、完整 1,833 点 Dev 重生成、官方 Val 和赛事提交不在本轮范围内，仍需单独授权。

候选只改变样本访问策略。两组都从只读 E01-B Full Adapter 加载 LoRA 参数，创建新的空 AdamW 状态，不加载 Full B 优化器/调度器或 checkpoint；模型、NF4/BF16、LoRA、completion-only token CE、P0/F2/T1、Batch、seed、学习率和生成协议保持锁定。

| 组别 | 每个 optimizer step 的 4 个 microbatch | 前 128 步样本情况 |
|---|---|---|
| Control | 4 个全量 Train 自然均匀抽样 | 512 次 draw，512 个不重复样本 |
| Candidate | 自然、短历史 Gold 全空、自然、短历史 Gold 非空 | 256 次自然抽样；两类短历史各 128 次、有放回 |

短历史按原始 history 消息数 `<=4` 定义。Gold 仅用于离线分层，不进入模型输入。每个 Run 上限 128 个 optimizer steps，在 64/128 步保存 checkpoint；单组最多 2 小时，两组合计最多 256 步。达到资源停止条件但未完成 128 步的 Run 标记为 `stopped_budget`，不得进入生成评测。

## GPU 执行命令

从仓库根目录运行，先完成静态预检，再做一个无优化器更新的 GPU dry-step。**只有 GPU dry-step 的 Manifest 状态为 `passed_gpu_dry_step_no_optimizer_update` 才继续。**

```bash
source .venv/bin/activate

python scripts/e03_a3_short_train.py --mode preflight

python scripts/e03_a3_short_train.py \
  --mode gpu-preflight \
  --run-id E03-A3-GPU-PREFLIGHT-20261105
```

GPU 预检会确认 CUDA/BF16 和显存门槛，加载 NF4 Base 与可训练 Adapter，在最长 SFT 序列上做一次 forward/backward，验证有限非零梯度、Adapter 值未改变、没有创建 optimizer、Base SHA 未变化。结果写入 `outputs/training/E03-A3-preflight/E03-A3-GPU-PREFLIGHT-20261105/`。不通过时停止，不运行训练。

预检通过后依次运行两组。两组共享同一份 CPU schedule、参数和只读初始化 Adapter，各自创建全新的 optimizer 状态：

```bash
python scripts/e03_a3_short_train.py \
  --mode train \
  --group control \
  --run-id E03-A3-SHORT-CONTROL-20261105 \
  --gpu-preflight-run-id E03-A3-GPU-PREFLIGHT-20261105 \
  --allow-e03-a3-short-training

python scripts/e03_a3_short_train.py \
  --mode train \
  --group candidate \
  --run-id E03-A3-SHORT-CANDIDATE-20261105 \
  --gpu-preflight-run-id E03-A3-GPU-PREFLIGHT-20261105 \
  --allow-e03-a3-short-training
```

只有两组都返回 `trained_pending_eval`、各完成 128 步、64/128 checkpoint 和独立 Adapter 重载一致性检查后，才运行同 ID 冻结集生成：

```bash
python scripts/e03_a3_short_evaluate.py \
  --mode run \
  --training-run-root outputs/training/E03-A3-short/E03-A3-SHORT-CONTROL-20261105 \
  --run-id E03-A3-EVAL-CONTROL-20261105

python scripts/e03_a3_short_evaluate.py \
  --mode run \
  --training-run-root outputs/training/E03-A3-short/E03-A3-SHORT-CANDIDATE-20261105 \
  --run-id E03-A3-EVAL-CANDIDATE-20261105

python scripts/e03_a3_short_evaluate.py \
  --mode compare \
  --control-run-root outputs/evaluation/e03_a3/short/E03-A3-EVAL-CONTROL-20261105 \
  --candidate-run-root outputs/evaluation/e03_a3/short/E03-A3-EVAL-CANDIDATE-20261105 \
  --run-id E03-A3-COMPARE-20261105
```

若运行中断，训练 Run 不允许恢复 optimizer/checkpoint；应保存失败 Manifest 并停止。推理 CLI 支持同一身份 Run 的 `--resume`，例如在原评测命令追加 `--resume`。同一 Run ID 不可覆盖；再次执行实验时使用新 ID。Control 与 Candidate 应在同一硬件环境运行，保持默认相同 `hardware_label`。

## 评测口径与产物

评测器只接受冻结的 224 点 target-free 输入，生成端不读取 References。它逐一核对 ID、原始输出与官方 Submission Schema，并调用既有本地指标计算情绪、画像 33-label Micro/Macro-F1、逐维指标、三维 Exact Match、Raw JSON/A0、回复 BLEU-4/ROUGE-L、生成长度/耗时。按原始 history `1–4` 与 `5+` 分层计算画像错误；Candidate-128 对 Control-128 是主比较，E01-B Full 同 ID 预测是次要观察基线。

配对报告按 conversation cluster bootstrap，提供画像 Micro-F1/Precision/Recall、情绪 Accuracy、严格 JSON 和 Raw A0 的差值区间，并统计短/长历史及 Gold 空/非空组的 TP/FP/FN 变化。预注册门槛包括总体画像 Micro-F1 至少提升 0.03 且 TP 增长、短历史画像 Micro-F1 增长、FP 增加不超过 10%、非短历史及每个画像维度的 Micro-F1 下降不超过 0.01、情绪/Raw Schema 不下降超过 0.01、回复 BLEU/ROUGE 相对下降不超过 5%，以及不能出现两组都低于原始 E01-B 的情况。总体画像 F1 的聚类区间跨零、样本不支持或门槛失败时不宣布稳定改善；任何后续扩训仍须另行批准。
