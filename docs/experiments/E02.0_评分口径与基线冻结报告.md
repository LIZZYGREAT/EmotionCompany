## 1. 审计结论

本报告逐项核对了 `src/evaluation/metrics.py`、`src/evaluation/score.py`、`scripts/e01_b_evaluate.py`、Full B 评测配置、提交 Schema 和已完成 Run。仓库有可复现的本地计算定义与产物指纹；当前可用的赛事契约资料没有包含官方评分代码或逐项计算细则，因此本地指标一律保持 `local_proxy`，不能声称与官方分数等价。

| 指标 | 当前实现和分母 | 取值/解释 | 官方等价性 | 待补证据 |
|---|---|---|---|---|
| Emotion Accuracy | 16 个固定有效情绪标签；`正确样本数 / 全部样本数`。空字符串及任何非法预测均算错 | `[0,1]`；本地实现 | `unverified` | 官方对非法标签、缺失字段和宏平均的处理规则 |
| Emotion Macro-F1 | 对固定 16 标签逐类算 F1，再不加权平均；`zero_division=0`，标签即便无预测也保留在均值中 | `[0,1]`；不受各类 Support 权重影响 | `unverified` | 官方是否固定 16 类、如何处理零 Support/非法预测 |
| Profile Micro-F1 | personality/interests/style 合并为 33 个二元标签；跨维度合并 TP/FP/FN 后计算 F1 | `[0,1]`；三维标签合并口径 | `unverified` | 官方 33 标签的平均与空画像定义 |

### 画像空值基线说明

Full Dev Gold 中三维画像同时为空的样本为 `660/1,833`。恒输出三个空数组会得到 `36.01%` 三维 Exact Match，但没有命中任何 Gold 非空标签；因此该基线只用于解释 Exact Match 的空值敏感性，不应当作有效画像能力分数。Full B 指标仍以正式报告中的 33-label Micro/Macro-F1、逐维指标和非空 Gold Recall 联合解读。

## 2. 官方口径证据与待核实问题

仓库中的 [赛事文件边界与运行契约](../competition/赛事文件边界与运行契约.md) 固定了入口、输出文件和提交 Schema 的保护规则；该文件并未定义情绪/画像指标的完整算法。赛事提交 Schema 也只能证明输出形状，不足以推出官方计分公式。因此目前没有任何一项本地质量分数可以映射成比赛官方得分。

需要向赛事方取得或确认：

1. Emotion Accuracy/Macro-F1 的标签枚举、非法/空值、零 Support 类处理。
2. Profile Accuracy 的精确定义；三维是否分别计分、如何宏/微平均，空集合如何处理。
3. 回复 BLEU、ROUGE、BERTScore 的实现、版本、语言、tokenizer、平滑和语料/样本聚合方式。
4. Raw completion 与 Runner 归一化后的 Submission 哪一层进入评分；结构不合法时的分数规则。
5. 性能指标的设备、预热、并发、请求计时边界、失败/OOM 处理和官方吞吐口径。

在官方脚本或书面答复入库前，对照表的官方等价状态维持 `unverified`。不得用通用文献定义替代赛事实际执行规则。

## 4. BERTScore 与回复盲审的后续方案

### BERTScore 离线评测

继续复用 `src/evaluation/metrics.py::bert_score_optional()`，不新建重复实现。运行前需要确定本地模型目录、模型 ID、不可变 Revision、`bert-score` 版本与模型文件指纹；需在离线条件下完成加载预检。满足这些条件后另建只读评分 Run，输入复用已保存的 1,833 条 Base/Adapter 回复与 Gold，不重新生成。输出 Precision/Recall/F1 的本地代理值，并与模型/依赖/数据 Hash 一起记录。模型下载或额外 GPU 计算须由执行者单独确认；当前报告不虚构资源核验结果。

### 30～50 条盲审样本设计

后续由人工从固定的已保存配对预测中按回复长度、Gold 情绪类别、Raw 合法性分层抽取 30～50 个 ID；使用固定 Seed，并在脱敏副本中随机交换 Base/Adapter 的 A/B 身份。两位评审者分别按 1～5 分评价：

- 对当前用户诉求的相关性；
- 情感贴合与支持性；
- 自然度和可读性；
- 是否遗漏显式请求；
- 结构化输出缺陷（单独记为缺陷类别，不与语言质量混为同一分数）。

样本原文、Gold、匿名映射和评分表仅保存于本机忽略的 `outputs/evaluation/e02/`；Git 只记录抽样规则、评分表字段、评审人数和聚合一致性。没有评审者实际完成时，状态保持 `not_run`。
