## 一、任务背景和要解决的问题

D0.4.3 已生成基于 P0/F2/T1 的预编码 Completion-only SFT 数据，并用真实 Qwen Tokenizer、专用 Collator 和 TRL DataLoader 核对了数据、Padding 和 Labels；尚未让真实 Qwen3-1.7B 执行 `forward → backward → optimizer.step`。`src/training/training_sft.py` 当前为空文件。

E00.2 已验证同一个 `Qwen/Qwen3-1.7B` 基础权重在 NF4/BF16/CUDA 上可以完成联合 JSON 推理，但现有 20 条 Smoke 的分类与原始输出合规率较低。E00.2-D 的单情绪诊断也不足以证明模型经过监督训练后的能力上限。因此本次首先检验：**训练实现是否可靠、LoRA 参数是否真正更新、少量监督样本能否被拟合、已训练 Adapter 是否能独立重载推理。** 随后才使用全量 Train 建立标准 E01-B 基线并在独立 Dev 上衡量泛化。

冻结的主线：

- 基础模型：`Qwen/Qwen3-1.7B`，为已有后训练版本，不切换到 Base、3B 或 4B。
- 输入：`P0 + F2 + T1`，原生多轮 Chat Template，Non-thinking；训练与推理同源。
- 方法：冻结 NF4 基础权重，仅训练 LoRA；Completion-only SFT，标准 Token 交叉熵，不做字段加权。
- 输出：单次联合 JSON（情绪、用户画像、陪伴回复、固定空 `memory_refs`），暂不增加独立分类器。
- 数据：只从 D0.4.3 的有效 Train 构建训练集；Dev 仅用于独立评价；官方 Val 不用于调参。
- E01-A 与 E01-B **独立从相同基础模型和新初始化的 LoRA 开始**。E01-B 不继承 E01-A 的 Adapter 或优化器状态。

## 二、真实执行链与组件职责

### 1. 训练链路

```text
D0.4.3 有效 Train JSONL（预编码 input_ids、labels、prompt_length、completion_length）
  → 检查数据 Manifest、S/P、P0/Tokenizer/Template 指纹
  → Dataset（只选 Train；E01-A 固定少量 sample_id，E01-B 用完整有效 Train）
  → SFTDataCollator：右侧 Padding、attention_mask、保留预生成 labels
  → DataLoader
  → 已加载并冻结的 Qwen3-1.7B NF4 基础模型 + 新初始化的 LoRA
  → Forward：使用 Prompt + Gold Completion 做 Teacher Forcing
  → Completion-only Loss（Prompt、Padding 的 labels=-100）
  → Backward：只为 LoRA 参数积累梯度
  → Optimizer Step：更新 LoRA 参数；记录真实更新证据
  → 独立目录保存 Adapter / 必要 Checkpoint / 实验 Manifest
  → 释放模型 → 从同一 Base + 本次 Adapter 重载
  → 用 P0/F2/T1 生成 Raw JSON → 校验与评分
```

数据已具备 `labels`，不要在训练时再自己构造一套 Prompt 或用其他工具覆盖标签。Causal LM 在内部进行 next-token shift，不手工再移一遍 Labels。`memory_refs=[]`、字段顺序、模板 EOS 的监督边界沿用 D0.4.3。

### 2. 模型参数与实验独立性

LoRA 的等效参数关系为：

$$
W_{\mathrm{eff}}=W_{\mathrm{base}}+\frac{\alpha}{r}BA.
$$

基础权重在训练中冻结，更新仅作用于已声明的 LoRA 参数（矩阵 $A,B$）。`participant/model` 是**只读的基础模型来源**，不能被用作训练输出目录，也不能通过合并权重、`save_pretrained` 或自动保存覆盖其内容。训练时内存中的计算状态发生变化，并不意味着修改基础权重文件。

```text
                              participant/model（唯一固定 Base，原始文件不变）
                                            │
                          ┌─────────────────┴──────────────────┐
                          ▼                                    ▼
                   E01-A：新 LoRA A                     E01-B：新 LoRA B
                   少量 Train 拟合                      完整 Train 训练
                          │                                    │
                          ▼                                    ▼
                 outputs/training/E01-A-.../            outputs/training/E01-B-.../
                       adapter/                              adapter/
```

不得以如下方式启动独立 E01-B：先加载 A 的 Adapter，再继续训练。若将来确实研究续训，必须以新的实验类型、独立 Run ID 和 `init_adapter`/`resume` 来源记录，不得称为 E01-B 标准基线。

### 1. 版本与数据身份

以现有 D0.4.3 候选作为 E01-A 起点：

| 项 | 当前候选值 / 约束 |
|---|---|
| 基础模型 | `Qwen/Qwen3-1.7B` |
| 基础权重聚合 SHA-256（E00 已归档） | `005d20550c04f4e246e5b434448786b44a0196b47d758d0acc77aba279e5bbc5` |
| Tokenizer revision 配置值 | `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`（Hub revision 尚非独立在线核验） |
| P0 SHA-256 | `d427e4996d0075a3adfe03ae25881d093687a6565f5b037f605accecc84c70b2` |
| 完整训练序列预算 S | `2048`，**候选值** |
| 推理 Prompt 预算 P | `1280`，**候选值** |
| 训练 JSONL | `data/processed/sft/v1/train.jsonl`（16,192 条有效样本） |
| SFT Dev | `data/processed/sft/v1/dev.jsonl`（1,821 条，可用于监督 Loss） |
| 生成质量 Dev | D0.3 原始 1,833 条 Dev 的无标签推理输入（包含被 SFT 排除的 12 条） |
| 官方 Val | 不参与本任务训练和参数选择 |

开始前核对 D0.3、D0.4.3 Manifest 和文件哈希；模型与 Tokenizer 仅从本机已核准目录加载，不允许隐式联网下载。若本机缺少 `data/processed/` 或 `outputs/sft_data/v1/manifest.json`，按 `docs/workflow.md` 重建或核验，不能自行生成伪造的替代数据。

### 2. E01-A 初始超参数（先实验，非最终冻结）

| 参数 | 候选 | 说明 |
|---|---:|---|
| 量化 | NF4 / BF16 / Double Quant | 沿用 E00 已验证方案 |
| LoRA rank `r` | 8 | 先降低训练资源压力 |
| LoRA alpha | 16 | 固定以便复现 |
| LoRA dropout | 0.0 | 便于小样本拟合诊断 |
| LoRA target modules | `q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj` | 加载时检验实际匹配模块及参数量，不默默跳过 |
| 单设备 Micro batch | 1 | 适应 8GB GPU |
| Gradient accumulation | 4 | 4 次 micro-batch 反向累计为一个 Optimizer Step |
| 学习率 | `1e-4` | 初始探索值 |
| Precision | BF16 | CUDA 确认支持后启用 |
| Gradient checkpointing | 开启 | 降低激活显存，核对 k-bit + checkpointing 的梯度路径 |
| Packing / padding-free | 关闭 | 沿用 D0.4.3 |
| Micro-overfit 预算 | 最多 120 个 **Optimizer Steps** | 包含早停；不得混淆 micro-batch 数与更新步数 |
| Seed | 42 | 记录 Python/NumPy/Torch/CUDA、采样器状态及初始化 |
| 推理 | Greedy / Non-thinking | 生成长度 G 记录并与选定对照保持一致 |

采用项目已安装并通过数据通路验收的 TRL/PEFT/Transformers 组合；实际可调用的 API 以仓库固定版本和本机运行结果为准。优先使用 `SFTTrainer` + 已有 `SFTDataCollator`；需要实际验证 Trainer 是否跳过自动 Dataset Prepare、是否保留 `labels`、是否仍使用 `max_length=None`、`packing=False`、`padding_free=False`。训练必须能取得 LoRA 梯度与 Optimizer 更新的原始证据。

E01-B 的 Epoch、学习率调度、最大步数、保存间隔和资源预算先作为待确认配置；在 A 完成前不得由 Agent 擅自选定大规模训练策略并启动。

### 3. E01-A 固定训练样本

从 D0.4.3 **有效 Train** 中确定性选 8～16 条（建议先用 8 条，必要时扩到 16 条）参与 Micro-overfit。选样可读取同 ID 的 D0.3 Train 目标，仅用于确定训练诊断集合，条件建议如下：

- 覆盖至少 4～5 个不同的情绪标签，兼顾空画像与非空画像；
- 优先历史较短、完整序列较短、回复长度适中的样本，降低首次显存风险；
- 优先不同 `conversation_id`，避免高度相似的样本重复；
- 按固定规则与 `sample_id` 稳定排序，记录所有选中 ID、选样规则、数量和指纹；
- 不把 Dev 或官方 Val 的 Gold 用作样本选择依据。

不得为了更容易过拟合而修改任何 Gold 标签、Completion 内容或训练 Labels。需要更换小样本集合时建立新的 Run ID，保留之前结果。

## 五、E01-A 的实施与验收顺序

### A0. 启动前环境与数据预检（只读）

1. 查看当前分支与工作区，不覆盖使用者的现有改动。
2. 检查实际 `.venv`、PyTorch CUDA、BF16、Transformers/TRL/PEFT/bitsandbytes 版本、GPU 可用性。
3. 检查 `participant/model` 权重完整性及聚合 SHA、Tokenizer/Template/P0 指纹。
4. 检查 D0.4.3 Train/Dev 文件存在，Manifest、数据来源和样本数一致。
5. 检查 `outputs/training/<run-id>/` 不存在，禁止复用已完成实验的目录。
6. 检查 GPU 上实际加载的 NF4 模块及设备分布；训练禁止 CPU/disk offload 悄悄发生。

**预期：**输出机器可读的 `preflight.json`，写明所有核对结果；GPU 不可用时可完成 CPU 静态/合成测试，但 A 的真实训练状态必须写为 `blocked_gpu_unavailable`，不得假报成功。

### A1. 一次真实 Optimizer Step 验证（独立临时 Run）

通过 `SFTDataCollator` 取得真实 Train Batch，严格核对 `input_ids`、`attention_mask`、`labels` 与 D0.4.3 记录一致。加载原始 Qwen NF4 权重，通过 `prepare_model_for_kbit_training` 等必要步骤准备梯度，并注入新 LoRA。

在训练前列出所有 `requires_grad=True` 参数名称/数量，必须全部符合预期 LoRA 目标；基础权重冻结。对 LoRA 训练参数做轻量初态取样或摘要，真实执行：

```text
model.train()
for each micro-batch in accumulation window:
    forward(batch) → finite loss
    backward(scaled loss) → LoRA gradients
inspect gradients before clearing:
    finite, at least one nonzero LoRA gradient
optimizer.step() → at least one LoRA parameter actually changes
optimizer.zero_grad()
```

记录优化器实际执行次数、Loss、梯度范数/非零梯度数、参数变化证据、每步耗时、峰值显存、CUDA 放置。一个测试 Step 使用**独立临时 Run ID/Adapter**，不把它的参数当成后续 E01-A 正式 Micro-overfit 的初态。

**通过门槛：**真实 Qwen 参数参与前向，Loss/梯度有限，LoRA 有非零梯度并被真实更新；冻结参数不被更新；无 CPU/disk offload；未破坏 `participant/model` 原始文件。只看到 Loss 数值不能通过此门槛。

### A2. Micro-overfit（从干净 Base + 新 LoRA 重新开始）

1. 创建正式 `E01-A-...` Run ID，并固定 8～16 个 Train ID。
2. 再次从相同 Base 初始化**全新** LoRA，绝不读取 A1 的临时 Adapter。
3. 训练前对选中 Train 的无标签 History 生成一次 Raw JSON，保存初始状态指标。
4. 训练中记录每个 **Optimizer Step** 的有效 Loss、梯度状态、Token 数、步耗时与峰值显存；预定义少量检查点与生成评测间隔（例如每 20 个更新步）。
5. 评测时切换 `model.eval()` / 无梯度；训练继续时恢复 `model.train()`；评测只读取 History，不将 Gold 注入 Prompt。
6. 训练达到配置预算或满足预先定义的停止条件时保存 Adapter、最终配置及日志；不要自动增加 Epoch、修改 Prompt 或扩大模型。

训练集生成诊断应至少统计：情绪 Accuracy、画像三维集合 Exact Match/标签 F1、Raw 严格 JSON 合法率、Raw A0 Schema 合法率、输出为空或字段缺失数量、必要的回复质量抽样；可以额外记录 Teacher-forced Loss，但必须和自由生成结果分开报告。

**建议判定方式：**将“训练工程通过”和“任务拟合有效”分开：

- 工程通过：A1 的梯度更新、训练循环、产物和重载门禁全部满足。
- 拟合有证据：相同 Train ID 的后期 Loss 明显下降，且实际生成的合法性与情绪/画像正确性相对训练前出现可核对改善；建议以预先固定的约 75% Train 情绪正确、约 75% Raw A0 合法作为目标性诊断阈值，**不是模型性能保证，也不是一旦未达就自动替换模型**。
- 若达到最大预算仍不能拟合，记录 `engineering_passed_learning_inconclusive`，进入定位（标签边界/损失、梯度、生成加载、优化器、模型参数、训练样本复杂度），不直接进入 E01-B。

### A3. 保存、释放、重载与推理一致性

- 使用 PEFT 保存**仅属于本 Run 的 Adapter**，例如 `adapter/adapter_model.safetensors`、`adapter_config.json`；训练中间 Checkpoint 如需恢复还需有优化器、调度器、随机状态与 Trainer 状态，不能把只有 Adapter 的文件夹称为完整可恢复 Checkpoint。
- 完成训练后，在当前模型 `eval()` 且 Greedy 条件下，保存固定输入的一次生成 Token IDs/Raw 文本；释放模型实例并重新从 `participant/model` 加载相同基础权重与已保存 Adapter，再在相同环境、Tokenizer、P0/F2/T1 和推理配置下生成并比较。
- 如果运行时无法保证完全逐 Token 相同，先定位 dropout、随机性、加载差异和精度路径，保留差异；不得以“看起来差不多”冒充一致性通过。
- Adapter 加载必须绑定正确基础模型身份；故意传入错误 Adapter 路径、不同 Base 身份时应明确报错。
- 重算或比对基础权重文件的聚合哈希，必须与初始已核验值一致；检查 `participant/model` 没有新增训练产物。

### A4. 小规模独立 Dev 检验

用已有 E00.1 的固定 20 条 Dev Smoke（与 E00.2 Greedy 同 ID），通过原生 P0/F2/T1、Greedy 和已有评分器进行独立推理。**只使用 History 生成，评分阶段才读 References**。保留 Raw 与 Submission 两个口径；额外报告训练集拟合与 Dev Smoke 的差异，明确这 20 条仍不足以做广泛泛化判断。

特别注意：E00.1 `score.py` 对评测 Manifest、配置、权重、输入 ID 与运行元数据有严格校验；必须按现有协议生成 E01 的有效配置快照和带 Base/Adapter 双身份的运行元数据。若需扩展 Scorer，只扩展对 Adapter 的识别，不削弱已有 E00 核验，不伪造旧 Run 的权重身份，不通过跳过校验完成评分。

## 六、E01-B 的独立基线：实现准备与执行门禁

### 1. 训练初始化规则

E01-B 必须符合：

```text
Base Qwen3-1.7B（原始权重 SHA 与 E00/A 一致）
  + 从配置 Seed 初始化的全新 LoRA B
  + D0.4.3 全量有效 Train（16,192）
  → 标准 Completion-only SFT
  → 独立 Adapter B / Checkpoint / Metrics
```

**严禁：**从 E01-A Adapter 加载继续训练、自动挑选“最新 Checkpoint”开始 B、从 A 的训练后模型实例复制参数、将 A 的优化器状态导入 B。项目通用训练入口默认 `init_adapter: null`、`resume_from_checkpoint: null`，两项都为空才是新的独立 Run；未来的续训必须显式声明，且独立标记成非基线实验。

E01-B 的样本顺序、随机种子、Tokenizer、P0/F2/T1、Loss、模型身份和每项超参数都写入独立 Manifest。不得用训练样本、Dev 或 Val 的结果隐式改写 Prompt 文案与标签定义。

### 2. 本任务允许提前完成的 B 准备

- 建立 `configs/training/e01_b.yaml` 草案和可复用的全量训练入口，确保它仅选择有效 Train 且没有 A Adapter 依赖。
- 加入能拒绝误续训、误覆盖、错误数据版本或加载错误 Adapter 的测试。
- 准备支持配置冻结、Checkpoint 和 Adapter 独立输出的文件结构。

**完整 E01-B GPU 训练暂不执行。** 需要 E01-A 的实际报告确认真实可学习性、显存/速度、拟合表现后，再由使用者确定 E01-B 的 Epoch/Steps、评估间隔、保存策略、最大 GPU 资源预算并明确启动。

### 3. B 启动后的评价口径（供实现预留）

- 完整有效 Train 16,192 条用于更新；SFT Dev 1,821 条可用于验证 Teacher-forced Loss；两者不可混用。
- **生成质量评测使用原始 D0.3 Dev 1,833 条**，不因 12 条无法进入 SFT Loss 评估就剔除它们。
- 若要给出 E00→E01-B 完整泛化提升结论，先安排同 1,833 条、同 P0/F2/T1、同 G、同 Greedy、同后处理与 Scorer 版本的 E00.3 Base 推理作为配对对照；当前 20 条 E00 Smoke 不可冒充全量对照。
- BERTScore 仍为 `not_run`，除非另行固定离线实现与模型身份；不据此宣称官方总分。
- E01-A 训练集高分只是可学习性证明，不能并入 E01-B 的 Dev 泛化成绩。

## 七、Adapter 推理支持及身份追踪

为 `participant/run_inference.py` 增加可选实验配置字段（具体 schema 可按现有风格统一）：

```json
{
  "adapter": {
    "enabled": false,
    "path": null,
    "expected_base_weight_sha256": null
  }
}
```

设计要求：

1. `enabled=false` 或字段缺省时执行 E00 原有加载逻辑，生成结果与既有测试不变；不能自动搜索磁盘上的最新 Adapter。
2. 只有在 `backend=transformers` 且显式 `enabled=true` 时，先加载 Base（含原定量化），再使用 PEFT 加载本次 Adapter；不存在/不兼容则失败，不静默回退 Base。
3. 推理端必须记录：Base 模型 ID、Base 权重聚合 SHA、Adapter 路径/ID、Adapter 权重 SHA、Adapter 配置摘要、是否实际启用，确保 E00、E01-A、E01-B 结果不会被误标成相同模型。
4. 各次运行用 `EVALUATION_INFERENCE_CONFIG` 指向本 Run 的独立推理配置快照；保持 `participant/configs/inference_config.json` 的默认无 Adapter 行为。模型实际生成始终使用共享 P0/F2/T1。
5. `start.sh` 的官方两个位置参数、固定环境激活、输出文件名及 Schema 原样保留；本任务不实现 vLLM Adapter 部署，暂不宣称它已完成端到端验证。

## 八、实验目录、权限边界与产物

建议的本地目录（位于已忽略的 `outputs/`）：

```text

  E01-A-<id>/
    config_snapshot.yaml
    manifest.json                          # 数据/模型/协议/超参/Seed/Run 身份

```

正式 Run ID 唯一且不可覆盖；完成、失败和中断均应留下简洁的 `manifest.json`，标记 `passed / failed / blocked / not_run`。再次执行同一训练必须使用新 ID，只有显式 `--resume` 才允许恢复**同一个 Run**，并验证相同的数据、模型、Adapter 和 Checkpoint 身份。

基础模型、原始数据、预编码 JSONL、Raw 对话文本、GPU 日志大文件和 Adapter 不入 Git；版本化文档只记录证据摘要、SHA、指标和复现命令。日志避免含 Gold 回复、完整历史和敏感对话内容。

## 十、停止条件与异常处理

- GPU 不可访问、NF4/BF16 不匹配、模型权重/Tokenizer 指纹错误：停止 GPU 任务，仅交付已完成代码、CPU 测试和阻断记录。
- Loss/梯度 NaN/Inf、LoRA 实际未更新、基础参数意外变为可训练：立即停止，先排查训练实现。
- CUDA OOM：记录失败 Step、实测峰值显存、Batch/序列长度；优先排查显存与梯度检查点。若要改 S/P、batch 或 LoRA 配置，**新建配置/Run ID**，不得静默覆盖已有实验口径。
- Micro-overfit 拟合不佳：先比对 Train 前后自由生成、Teacher-forced Loss、Raw Schema、模型/Adapter 是否正确加载，避免直接转向大模型或 P1。
- 保存或重载失败、Adapter 身份不一致、训练前后基础权重 SHA 变化：停止进入下一阶段。
- 已存在 Run ID/Checkpoint：默认拒绝写入；不清理或重置不明来源的输出。
- Agent 在没有明确批准时**不得**自动运行完整 E01-B、完整 Dev 1,833 条 GPU 对照、模型下载、vLLM 或 Docker 构建。
