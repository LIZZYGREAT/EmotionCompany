## 一、项目判断与实验目标

目前模型使用 P0/F2/T1 协议，在完整 JSON Completion 上进行 Completion-only SFT。E01-B Full（16,192 条有效 Train、4,048 optimizer steps）在 1,833 条 Dev 上画像 Micro-F1 为 `0.4223`、Macro-F1 为 `0.2700`，Raw A0 合法率为 `98.09%`。A0/A0.1 表明相当一部分监督 Token 属于固定 JSON 结构，A1 的标签值 ×2 加权并没有提高完整 Dev 画像 Micro-F1；A3、A4 的短程候选也因为误报、稳定性或综合质量未达门槛而没有采用。**这些负结果不能直接证明 F3 有效，也不应作为继续搜索 Loss 权重的理由。**

A6 选择一个新的、可以单独检验的变量：**让语言模型生成更简洁、固定顺序的文本协议，Python 再把该文本确定性地转换为比赛要求的 JSON。** 目标包括：

1. **工程上**：所有合法 Gold 能无损转换；F3 的原始输出可以被稳定解析；最终 `submission.jsonl` 符合官方 Schema；现有 F2 路径仍可复现。
2. **训练上**：在同一 Qwen3-1.7B、同一训练样本、同一 LoRA 设置和训练步数下，检验更短的 Completion 是否使学习更集中、训练成本如何变化。
3. **质量上**：重点观察 33 标签画像的 TP/FP/FN、Micro/Macro-F1、Precision/Recall，同时保留情绪、回复和整体输出质量；不能以“输出格式更合法”代替画像提升。
4. **效率上**：利用已验收的前缀早停思想做小样本快速筛选，但保留少量完整回复测试和 Full 质量门禁。

**研究边界**：A6 首轮只改训练目标的**表达格式**及其必要提示词、解析器；不同时引入新的 T2、BCE 分类头、Replay、LoRA Rank 或加权 Loss。若后续希望把情绪或画像改成数字编号、独立分类头，需另立实验。

## 三、F3 内部协议设计

### 1. 固定模型输出顺序

默认候选 F3 文本格式：

```text
E=anxiety
P=introverted|sensitive
I=study_exam|programming_technology
S=direct
R=我理解你现在比较焦虑，可以先把复习任务拆成几步……
```

- `E=`：一个合法情绪标签；训练使用 Gold 原值，不能把官方错误哨兵 `""` 当成正常第 17 类。
- `P=`：`personality_traits`，多个标签使用 `|`；无标签为单个 `-`。
- `I=`：`interests`，语义同上。
- `S=`：`style`，语义同上。
- `R=`：完整回复文本，必须是第五个字段，`R=` 之后全部内容为回复（支持中文、引号、竖线、换行和字面 `E=`/`R=` 字符串）。
- `id` 始终来自输入样本，**不由模型生成**；`memory_refs=[]` 由 Python 固定补充；不得把另一条会话的记忆带入当前预测。

换行与标记使用严格语法：`E=...\nP=...\nI=...\nS=...\nR=<任意回复>`，在首四个字段只接受预期顺序；画像标签必须属于官方 33 标签集合，保持固定的官方枚举顺序、无重复。标准化后的 JSON 应采用官方维度名称。空数组用 `-`，不允许空白、`null`、`None` 等不同表示混用。

**关于损坏输出**：原始 F3 非法标签、重复标签、缺字段、字段顺序错误、提前 EOS 或 Token 截断都要明确统计；若某维出现非法标签，不能悄悄过滤并当作“格式全部正确”。可以在后处理采取确定性安全回退（该维变为空，或整条结构化部分失败），但必须同步保留原始失败类型和对固定分母评分的影响。不要为提高解析成功率启用 Gold 查表、语义猜测或二次生成。

### 2. 序列化必须满足无损往返

建立 `serialize_f3(target, official_schema)` 与 `parse_f3(raw_text, submission_enums)`。对合法 Gold `y`，应满足：

\[
\operatorname{ParseF3}(\operatorname{SerializeF3}(y))
=\operatorname{CanonicalTarget}(y).
\]

`CanonicalTarget` 延续现有 F2 的规范化语义：画像按官方枚举顺序排列、`memory_refs=[]`；**解析层必须保持 `response_text` 的原始内容及空白字符**，不依赖 `.strip()` 才实现无损。最终官方 Runner 现有 `normalize_prediction()` 对回复 `.strip()` 的行为可保留，但要单独记录“原始往返一致”与“提交后规范化一致”，不能混为一项。固定 JSON `[]` 和 F3 的 `-` 只表达同样的空标签，不额外暗示“所有未出现标签都是真负例”。

测试重点：Gold 完整 16,192 条有效 SFT Train、相应冻结 Dev 的合法目标（仅用于离线解析/评分测试，不进入训练），多标签、中文、多行回复、字面标记、控制字符、JSON 转义、首尾空格、空数组、标签重复与非法标签。

**不能通过对回复做全局字符串替换恢复结构**。解析器要先严格识别前四行，找到真实第五行 `R=`，再把后续全部内容视为回复。

### 3. 提示词与输入选择

新增隔离提示词，例如 `configs/prompts/p_a6_f3.txt`，协议身份可记录为 `P_A6_F3/F3/T1`，避免与成员 B 的 P1/P2 研究混淆。保持 P0 的任务定义、情绪及 33 画像标签、证据谨慎口径和回复质量要求，主要改变输出要求与示例；不能把旧 P0 的“必须输出 JSON”指令和新 F3 指令同时拼到 Prompt 中。

**公平对比的关键**：F3 提示词更短时，不能利用多出的 Token 空间多保留旧历史，然后把收益归功于格式。实验的 Train/Pilot/Full Dev 采用“**P0/T1 选择相同历史前缀 → 用该前缀构建 F3 Prompt**”的策略：

1. 用已冻结的 P0 和 Tokenizer 在同一原始 `history` 中复现 T1 选择，取得 `selected_start_index` / `selected_history`；
2. 再将**完全相同**的 `selected_history` 交给新提示词生成 F3 Prompt；
3. 要求 F3 的 Prompt 也满足 `P=1280`，完整训练序列满足 `S=2048`，Completion 保留 EOS；
4. 记录两种协议的 `prompt_tokens`、`completion_tokens`、历史起点及 Source Hash；如 F3 Prompt 超预算或原有样本无法有效编码，停止/列出阻塞原因，不静默裁剪更多历史、丢样本或修改上限。

保留 Qwen 原生多轮 Chat Template、`enable_thinking=false`、原有 assistant `reasoning_content` 安全语义。不得把 `id`、Gold、`target`、参考回复、未来消息或其他会话状态注入推理 Prompt。

### 4. Token 与训练数据边界

为了与 F2 Full B 做单变量对照，首轮沿用**原有 16,192 条有效 SFT Train ID**，即使 F3 更短，原先被排除的 120 条也**不在 A6 首轮追加**。Pilot 优先复用历史 E01-B Pilot 的**相同 512 Train ID 与训练顺序**；如果历史选择产物无法核验，用原始 `seeded_length_deciles_v1` 规则重算并证明身份一致，否则明确无法做到完全相同样本比较，不要伪称公平。

新建 `data/processed/sft/e03_a6_f3/` 与独立 Manifest / Summary；不要覆盖 `data/processed/sft/v1/`。对每个样本保持 Completion-only：Prompt 标签 `-100`、完整 F3 回复监督、EOS 监督、右 Padding、`packing=false`、`padding_free=false`。实际 Token 数变化是本次自变量的直接结果，要独立记录，不人为补足无用 JSON Token。

报告包含：F2/F3 总 Completion Token 差异、字段/样本长度分布、有效监督 Token 数、截断/超预算数量、各分层差异，以及 F3 提示词变化带来的 Prompt Token 差异。短 Completion 可能影响每步计算耗时，也可能改变每步预测目标数量；**保持相同步数比较不等于相同总 Token 预算**，应在结论中同时呈现。

### 阶段 A6-1：512 Train / 128 步 Pilot（GPU）

Pilot 质量评测分两层：

1. **同一历史 160 Dev ID 的 F3 画像快速评测**：采用 F3 前缀早停，仅生成至合法 `R=` 边界，记录固定分母的情绪、画像 TP/FP/FN、Micro/Macro-F1、Precision/Recall、三维 Exact、全空预测率及失败原因。对照历史 E01-B Pilot **相同 ID、同一解析层**的结果；历史 Submission 与 Raw 的差异需说明，不能与 Full B 的 1,833 点指标混算。
2. **Pilot 真实完整回复 Smoke**：从同一 160 ID 中冻结约 24–32 条有代表性的输入，执行**完整 F3 生成**，检查完整格式成功率、回复自然度、空回复、EOS/长度截断、最终 Schema 和可用的 BLEU/ROUGE 代理指标。该小组也用于确认 F3 Fast-only 前缀与完整生成的情绪、画像逐 ID 一致。

训练完成后，先进行 Full B 先前采用的**独立重载检查**（模型保存前后确定性 Token IDs、Base 不变、Adapter 权重/配置 SHA、dtype 与 LoRA 参数数目）。不通过则停止，不启动下一阶段。

#### Pilot 的阶段性“不过度乐观”门禁

这里的目标是证明 **F3 可以被稳定学习，工程链路正常，画像没有出现明显的灾难性行为**，不是在 128 步内证明其能够超过 Full B 的 4,048 步能力。建议在正式运行前把门槛冻结为：

- 工程：训练 128 步按计划完成，独立重载与 EOS/Token/Mask 校验成功；CPU Schema/数据/协议不变量保持通过。
- 格式：完整生成 Smoke 原始 F3 可严格解析的比例建议不低于 **95%**（初始可讨论阈值，训练开始前锁定）；任何解析失败、标签非法或回复截断需列明类型和 ID。
- 学习：微型拟合已证明非空标签可学习；Pilot 在 Gold 非空样本上的实际 TP/非空输出、误报、全空率要能被清晰解释。**如果 Pilot 仍接近“全空画像”，不可以只因为它与历史 F2 Pilot 同样全空就自动批准 Full。**
- 质量：情绪不出现明显无解释塌缩，完整回复并非普遍空白/无意义；画像 Precision 与 FP 不出现无法解释的灾难性变化。预先记录门槛及其适用样本量，尤其避免把 160 点极少数标签的单次 Macro-F1 当成确定结论。
- 实验身份：Pilot Train 与 Pilot Dev 的样本 ID、选取顺序、协议、Base/Adapter/Tokenizer 和 Scorer 均可追溯。

若 Pilot 质量信号不足（例如绝大多数预测仍为空、无法判断是欠训练还是方案缺陷），结果记为 `inconclusive`，**停止 Full 放行**。可以讨论一次有界补充 Pilot（例如冻结额外检查点或少量步数的单独授权），但不得自动转入 Full。若 Pilot 明确失败，标记 `failed` 并修正或结束候选。

### 阶段 A6-2：Pilot 审阅与 Full 启动授权

Codex 生成 Pilot 报告和一个**只读**放行摘要，给出 `passed / inconclusive / failed / blocked`，每项结论指向真实结果。至少列出：

- CPU 全量往返与 Token 节省；512/128 训练曲线、实际显存/耗时、模型保存重载；
- 160 Pilot Dev 画像/情绪质量、与同 ID 历史 F2 Pilot 的对应及其局限；
- 24–32 完整生成样本的 Raw F3、回复、Schema 和前缀一致性；
- 新训练协议与 F2 历史输入/样本身份是否可比；
- Full 训练风险、所需资源、预期输出路径、批准快照和禁止扩展的范围。

**Full 必须要求人工查看该摘要并显式批准 A6 Full**。批准回执绑定 Pilot Run SHA、数据/代码/配置/模型身份、Full 预算、选用的新协议及批准时间；任何变更使票据失效。开发脚本和配置默认不得通过 `--execute` 自动从 Pilot 链式启动 Full。

### 阶段 A6-3：条件式 Full 训练（获批准后）

研究目标固定为与 E01-B Full 的 F2 对照。

- **从 Qwen3-1.7B Base 初始化新的 LoRA Adapter**，不能从 Pilot Adapter 或当前 Full B Adapter 续训。Pilot 只负责验证工程与选定配置；这使 F3 Full 可以与 E01-B Full 的“从 Base 启动”训练路径对比。
- 使用与 E01-B Full **同样的 16,192 个有效 Train 样本 ID**，不加入之前排除的 120 条；1 Epoch、梯度累计 4、**4,048 optimizer steps**，保持原始超参数、Base SHA、LoRA Rank/alpha/modules、Tokenizer/Template、Greedy 和 T1 历史一致。只更换 F3 Prompt/Completion。
- 单独 `E03-A6-FULL-<RUN_ID>`，独立预编码数据、审批快照、Checkpoint、日志与 Adapter；不得覆盖 `E01-B-FULL-20261028-133805`。严格限制磁盘和 GPU；保留中断后**同 Run 且来源已核验**的恢复能力，不能静默降训练步数、更改 Batch 或偷换量化。
- Full 阶段的 SFT Dev Loss 可以在与原 E01 相同的 **1,821 条有效 SFT Dev**上计算，但注意 F3 与 F2 的监督格式不同，训练 CE 数值不宜作为直接采用依据；**生成质量仍用完整 1,833 条 Dev**。
- 输出记录训练 Token 总数、处理吞吐、总耗时、Dev CE、Checkpoint 空间、Adapter/Config/Source SHA、保存前后重载一致性。训练过程中若出现 OOM、非有限 Loss、参数不更新、Adapter 身份错误或越权访问数据，立即停止并保留失败证据。

**禁止“Full 训练结束 = 实验胜利”**。Full 训练完成只是模型产物可用；仍需以下评测和质量门禁才能决定是否保留。

### 阶段 A6-4：Full 后先做低成本门禁，再做完整 Dev

**A6-4A：224 点 Fast-only 同 ID 对照**

- 复用 A4 已冻结的 224 ID / 101 会话、Gold 物理隔离和 Source preflight，F3 用自己的前缀解析器在 `R=` 后早停。
- 以 E01-B Full **Raw 画像前缀**作为同口径基线：Micro-F1 `0.425787`，TP/FP/FN `142/152/231`；若改用历史 Submission 口径，必须单独展示并解释差异，不混用。
- 成功/非法/未闭合/预算耗尽/未知标签全部计入固定分母；执行逐 ID 配对并按会话聚簇做 Bootstrap。观察 Micro/Macro-F1、Precision、Recall、TP/FP/FN、空预测率、三维 Exact、情绪，以及短长历史与 Gold 为空/非空分组。
- 参照 A4 的经验，**显著 FP 增长、Precision 明显退化不能被小幅 Micro-F1 上升掩盖**；应在 A6 Full 开跑前冻结采用门槛和允许的差异范围。Fast-only 能筛掉明显不合格候选，但不取代完整回复评测。

**A6-4B：小规模完整生成与前缀一致性**

- 在同一冻结集合选取约 24–32 条，完整生成 F3 回复、记录 `R=` 之后的有效中文回复、输出完成率、EOS/截断、最终 Schema 和耗时。
- 必须做成对的完整 vs 早停生成前缀比较；不能简单假设模型换了格式仍满足 F2 早停的 Token 等价性。
- 如 Fast-only 和完整生成在前缀情绪/画像上不一致，或者完整回复质量明显退化，暂停进入完整 Dev。

**A6-4C：完整 1,833 条 Dev 同 ID 质量评测**

仅当 224 点快速门禁、完整生成 Smoke、独立重载和授权条件均满足，再使用 1,833 条 D0.3 Dev **target-free** 推理输入完整生成，之后由分离的 Gold References 评分。采用和 E01-B Full 相同的本地 Scorer 口径，比较：

| 指标 | 对照方式 |
|---|---|
| 画像 33 标签 Micro/Macro-F1、三维 Exact | 同 ID 配对；重点看 TP/FP/FN、Precision/Recall、短长历史 |
| 情绪 Accuracy / Macro-F1 | 保留既有能力，监测特定情绪类别退化 |
| 回复 BLEU-4 / ROUGE-L、空回复、长度、人工代表样本 | 不把格式简化等同于回复质量提高；本地代理不冒充官方得分 |
| F3 Raw 协议严格解析、最终 Submission Schema | 分别统计；任何通过 fallback 形成的空值必须计入质量结果 |
| Prompt/Completion Token、响应延迟、峰值显存 | 统一后端与测量口径，不把原 F2/当前 F3 运行环境差异算成格式收益 |

官方 Val 和隐藏 Test 不用于 A6 试错；已有 Dev 被多次使用，完整 Dev 结果是本地代理结论，不证明隐藏 Test 泛化。最终是否采用，应根据完整质量与性能综合判断，**不自动覆盖 E01-B Full**。

## 五、F3 快评适配的技术细节

现有 F2 `ProfilePrefixStopper` 只识别 JSON 的 `emotion_label`、`user_profile` 两字段。A6 不允许把 F3 字符串伪装为 F2 JSON 再交给旧解析器；新增 `F3PrefixParser` / `F3PrefixStopper` 或等效隔离实现。

**前缀闭合定义**：已完整解析 `E/P/I/S` 四行，且确认第五行的 `R=` **标记完整出现**。Stopper 只针对模型实际生成的累计 Token IDs 解码和校验；若 `\nR=` 跨多个 Token，则等待完整标记，而不是看到 `R` 就提前结束。输入中出现伪标签文本、重复 `R=`、非法枚举、错误字段顺序、EOS 提前结束时，应返回 `invalid/incomplete/unsupported_order` 等明确状态。该早停仅应用于隔离的 **画像快评**，正常官方推理必须完整生成回复。

**等价性检查**：在同一模型、同一 Prompt Token IDs、同一 Greedy 配置下，对冻结少量样本运行“完整生成”和“前缀早停”。比较前缀 Token IDs、情绪和三维画像 **逐项一致**，并记录耗时与峰值显存。通过后再做 160/224 点 Fast-only；即使先验上 Greedy 应保持相同前缀，也不能在未实测时宣称实现等价。

**无偷看 Gold**：Stopper / Parser 在生成期间不读取参考画像，只使用格式、合法枚举及当前累积 Token；Gold 仅在推理运行结束后的评分器可见。失败样本继续保留在选定 ID 分母中，按照事先冻结的规则转为空画像或解析失败，不许用完整生成结果替代有问题的 Fast-only 结果。

**Fast-only 适用边界**：F3 提前停止于 `R=`，不能用于评估回复自然度、BLEU/ROUGE、完整 EOS 或赛事端到端性能；这些必须单独完整生成。

## 六、训练、推理和官方程序的接入要求

### 1. 训练侧

优先复用已有数据、Collator、Tokenizer、QLoRA 及 CPU/GPU 预检机制。`src/training/training_sft.py` 对 `experiment_id/version` 有白名单；A6 可以增加清晰隔离的训练 Runner，或在**不影响旧 E01/A1 路径**的前提下增加明确协议版支持。不得仅删除历史白名单或伪造 E01 实验 ID 绕过检查。

已有 `src/training/experiment_spec.py` 目前的验证接口明确**不能直接启用训练**。可复用其 CPU 合同但必须建立独立的 A6 训练授权回执、Run Manifest、Dry-step 及 GPU 执行入口。Pilot 和 Full 使用不同 `training_scope`、不同输出根、不同审批条件。**除 Full 人工审批外，不得自动追加训练。**

独立重载校验要显式保持 Adapter 存储 dtype，例如 A3 验证过的 `autocast_adapter_dtype=False`，并同时核对前后权重、配置 Hash 与有限固定 Greedy Token IDs，避免把 dtype 自动转换造成的输出变化误判为训练失败或忽略真实问题。

### 2. 推理侧 / 官方入口

官方运行合同不变：

```bash
bash /root/participant/start.sh TEST_FILE RESULT_DIR
```

保留两个位置参数，保留 `conda_env` 的激活逻辑，正常运行写 `RESULT_DIR/submission.jsonl` 与 `RESULT_DIR/performance_report.json`。模型的 F3 输出在 `participant/run_inference.py` 中经显式 `format_version=F3` 解析，构造官方规定的五个顶层字段，再由现有 `validate_submission_prediction()` 校验。官方 `participant/templates/submission_schema.json`、官方 Train/Val Schema 不得修改。

对于两种已支持的推理后端：

- **Transformers**：沿用 `model.generate()` 的输出字符串和已有计时/状态记录，在 `parse_prediction()` 所在的逻辑点对 F3 增加独立解析分支。
- **OpenAI-compatible/vLLM**：继续使用 `chat/completions` 的文本 `message.content`，保留 `enable_thinking=false` 和服务端 Prompt Token 校验；拿到字符串后调用同一 F3 Parser。初版不依赖 vLLM Structured Outputs/Regex/Grammar，以免引入第二个实验变量。

本次小样本与 Full 质量实验以 **WSL `.venv` 中的 Transformers/NF4** 为统一环境。Full Adapter 通过本地完整评测之后，可使用现有 `conda_env` + vLLM `0.11.1` 做**独立 10–20 条 F3 真实生成 + 提交 Schema Smoke**，验证服务端 Prompt Token IDs、LoRA 路由、模型身份、输出解析与双文件合同。若 vLLM BF16 与 Transformers NF4 的预测不同，不能据此宣称 F3 质量退化或提高。Docker 封装与官方提交保持另案。

### 3. 失败、恢复与评分口径

保留已有 `run_inference.py` 的失败隔离、`--resume`、Raw 日志显式开启机制、结果目录保护和前 100 条性能口径。F3 应有自己的 `format_parse_failure`、`invalid_emotion`、`invalid_profile_label`、`truncated_before_R`、`response_truncated` 等状态计数；无法解析的输出要按确定性回退生成**合法 JSON**，同时在质量报告中体现失败及漏报。禁止让后处理在不知道原始预测是否合法的情况下自行“补全猜测标签”。

## 七、必须锁定的公平比较与实验身份

| 项目 | A6 约束 |
|---|---|
| 模型 | 固定 Qwen3-1.7B Base 与原 LoRA `r=8/alpha=16/target_modules`，不升级模型规模 |
| 数据 | 冻结相同 Train ID；Pilot 尽量同 512 ID/顺序，Full 同 16,192 ID；不加 120 条历史排除样本 |
| 上下文 | 依据 P0/T1 选取完全相同的 `selected_history`，再构造 F3 Prompt；记录并核验 Prompt 不越 1,280 Token |
| 输出 | 唯一主要变化：F2 JSON Completion → F3 简单文本 Completion + 必要的 P_A6_F3 指令 |
| 训练 | 与相应历史 Pilot / Full 相同的 Base 初始化、Seed、Optimizer、步数、梯度累计和硬件预算；额外 Token 差异如实报告 |
| 推理 | NF4/BF16、Greedy、同一批 ID、同 Scorer；F3 Raw 解析层与最终 JSON 层分别统计 |
| 快评 | F3 格式专用的 `R=` 前缀早停；同一 ID/固定分母/独立 Raw 前缀对照；失败不消失 |
| 评测隔离 | Train 仅用于参数更新、微拟合与诊断；Dev 只做评测；官方 Val、未来用户消息和其他会话不进入训练 |
| 资产和协作 | 新分支、新实验 ID、新配置和输出目录；历史 F2/A1/A3/A4 不覆盖；不修改队友 B 线代码 |
| 决策 | CPU → microfit → Pilot → **人工 Full 审批** → Full train → 224 快评 → 完整 Smoke → 1,833 Dev；失败在本阶段停止 |

### 不可混淆的四类“通过”

- `engineering_passed`：解析、数据、训练、重载和 Schema 没有技术错误。
- `pilot_quality_passed`：小样本表现足以支持继续投入，**并非**证明优于 Full B。
- `full_training_completed`：4,048 步、保存和重载结束，**并非**质量验收通过。
- `candidate_adopted`：完整 Dev 质量与稳定性确有可靠收益，并满足预定保留门槛；需要人工最终决定。

## 八、报告、测试与提交验收

建议每个阶段形成独立 Run Manifest，文档集中在 `docs/experiments/E0.3-A6_F3协议与Pilot验收.md`，Full 后再形成 `docs/experiments/E0.3-A6_F3_Full对照验收.md`（没有执行的阶段明确 `not_run`，不预填数字）。本地忽略目录保存逐条 Raw、预测及带真实 Gold 的对照明细，Git 只提交聚合统计、协议定义、日志摘要、源码和测试。

最低测试覆盖：

1. **F3 serializer/parser**：Gold 往返、完整字段顺序、中文/Unicode、多行/转义、标签合法性、空值、重复、非法输入及明确失败分类。
2. **F3 SFT**：完整序列、Token IDs、Prompt Mask、EOS、右 Padding、1280/2048 预算、与 F2 的 ID/T1 历史对齐。

5. **训练与模型身份**：独立 Base+LoRA 初始化、梯度更新、保存/重载 dtype 及 Token IDs；Checkpoint 恢复来自同一 Run；批准 Full 与 Pilot 票据匹配。
6. **评测**：样本 ID 一致、会话分组、TP/FP/FN、Precision/Recall、失败计入分母、历史 Raw/Submission 区分及 bootstrap 统计。

## 九、执行决策与优先级

按实际研究目的，这次先完成 **A6-0 + A6-0.5 + A6-1 Pilot**，形成能被人工审查的报告。**Pilot 是否放行 Full 是整条方案最重要的人工决策点**：如果格式可学、保存重载正确、合法率稳定，画像和情绪具有合理学习信号且没有灾难性副作用，再独立批准 Full；否则收敛修正或停止。

A6-3/4 的实现设计可以提前准备、做 CPU 测试，但不得以“方案已覆盖 Full”为由提前运行 Full 训练或完整 1,833 Dev 生成。Full 成功之后也不自动替换 E01-B；必须经过同 ID、同口径完整 Dev 和质量稳定性审查。
