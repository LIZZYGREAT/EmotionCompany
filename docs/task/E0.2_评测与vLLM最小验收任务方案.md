## 五、E02.1：vLLM + Full B Adapter 最小部署与协议验收

### 1. 先纠正现有代码的部署认知

现有 `participant/start.sh` 有 `transformers` 与 `openai_compatible` 两条路径，后者通过 `vllm serve "$MODEL_DIR"` 启动**基础模型**。它目前没有显式传递 `--enable-lora` 和 `--lora-modules`；`participant/run_inference.py` 的 API 分支还把 `adapter_identity` 标记为 `enabled=false / not_enabled`，同时把 Base 权重身份设为服务器侧 `unverified`。

因此当前不能仅凭 `start.sh` 能启动 vLLM 或 `/health` 成功，认定服务用了 Full B Adapter。**本项是 E02.1 的第一优先级**。

### 3. 建立可选 LoRA 的服务启动与身份门禁

修改范围（仅在兼容性预检通过后实现必要部分）：

- `participant/start.sh`：新增显式启用的 **LoRA 部署配置通路**，保持默认 `transformers` 行为、官方入口、两个位置参数和其他现有默认行为。可选参数名可取 `VLLM_LORA_ENABLED`、`VLLM_LORA_NAME`、`VLLM_LORA_PATH`、`VLLM_MAX_LORA_RANK`；仅启用后将对应 `--enable-lora --lora-modules name=path --max-lora-rank 8` 传给服务。拒绝不存在的路径、空别名、错误的 Adapter Base 身份或 rank 超限。
- `participant/run_inference.py`：API 路径必须正确指定请求模型名称 **LoRA 服务别名**（不是基础模型名）。清楚区分 `configured_adapter`、`locally_verified_adapter_file`、`server_route_observed`、`server_weight_identity_unverified` 等状态；不能因为本地验证 Adapter 文件 Hash 就宣称 vLLM 内部每层参数已独立校验。

必须测试两类防混用情形：①服务只加载 Base 却请求 `e01-full`，应明确失败；②服务加载 Adapter，但请求仍指向 Base，身份门禁应提示配置错误，不能记录成 Full B 结果。

**关于 `start.sh`：**若要让官方固定入口启动带 Adapter 的 vLLM，相关参数应从经审阅的配置/环境安全取得，不应依赖手工修改脚本源码。首次实现后为 Legacy Transformers 和旧 vLLM Base-only 路线都加回归。

# BASE_DIR、ADAPTER_DIR 必须是已核验的绝对路径。
vllm serve "$BASE_DIR" \

这些命令只证明可启动与列出路由，不证明实际 Prompt Token ID 一致、Raw JSON 合法或推理结果与 Transformers 逐 Token 相同。

### 5. 必须验证的四层等价性

| 层级 | 验证什么 | 验收边界 |
|---|---|---|
| A. 模型身份 | 本地 Base SHA、Adapter SHA、服务加载参数、`/v1/models` 存在正确别名、每次 API 请求 ID | 不能靠 `/health` 或别名文字独自证明服务权重来源 |
| B. 输入协议 | P0 SHA、原生 roles、T1 选取历史、`enable_thinking=false`、Tokenizer 文件与服务端 Chat Template、EOS、实际 Prompt Token IDs | `usage.prompt_tokens` 数量相等只能算初筛；若无法得到服务端完整 Token IDs，`exact_ids=not_verified` 并提供后续可观察方案 |
| C. 输出行为 | 固定 Greedy、G、EOS、Raw JSON/A0、Submission Schema、解析错误分类与生成上限 | 浮点/量化/推理后端差异可能让 Greedy 输出不同；不能要求文本逐字相等作为通用硬门禁 |
| D. 性能/资源 | GPU allocated/实际占用、预热/启动耗时、样本数、生成 Token、平均/P50/P90/P95 延迟、失败与 OOM | 仅 5～20 条小样本用于可行性；不能宣称官方分数，也不能对照完整 Dev 统计做性能结论 |

只有在所有可观测层级实际通过时，才把 E02.1 记为 `passed_minimal_smoke`。有不可观测但重要的 Token IDs/权重路径，需标注 `partial / not_verified`，不可写成全部验收通过。

### 6. 异常停止与恢复策略

- vLLM 在 8GB 上 OOM、启动失败或不支持目标量化 + LoRA：记录真实错误、环境、版本；清理服务进程。不能自动降 K、改 LoRA Rank、切换模型大小或改推理协议并继续称为同一次实验。
- `start.sh` 的固定 `conda_env` 不存在于当前开发机器：先用独立服务/客户端小样本验证，官方入口的 conda 与 Docker 路径在 E02.2 才完整集成；不得为本地方便删除固定激活命令。
- API 返回成功但未挂载 LoRA：直接判 `failed_identity`，不记录任何 Full B 质量分数。
- 服务端 Prompt Token ID 无法直接观测：记录 `not_verified` 和可复核证据，禁止用 Client 端 token 数代替。
- 返回结构不合法或语义异常：保留本机 `outputs/evaluation/e02/` 下的 Raw，记录 ID 与错误类型；不要修改 P0 或后处理兜底掩盖错误。
- 每次运行创建新的 Run ID，不覆盖 E01-B Full / 已完成 Dev 产物；禁止自动开始 1,833 条 Dev 或 100 轮正式性能测试。
