### 2. 本研究要区分三个不同问题

**问题 A：标签监督是否清楚？** 即 Train 的 `target.user_profile` 怎样转成 33 维正负监督，缺失标签在数据中代表“标注未选中”还是“没有完成标注”；这决定 BCE 是否合理。必须先审计，不允许训练器自行猜测。

**问题 B：已有表示是否可被简单分类器读取？** 冻结 E01-B，提取用户历史对应的隐藏状态，仅训练 33 维线性分类头。这回答表示中是否有可线性读取的画像信息，不更新 Qwen/LoRA，也不产生新参赛模型。

**问题 C：BCE 训练信号能否帮助最终 JSON 生成？** 在相同 SFT 样本、相同参数初始化和训练条件下，对比纯 SFT 与 SFT+BCE。即使问题 B 成功，问题 C 仍需独立验证。

这三个问题不应混写为“BCE 训练”。**A5.0（监督审计）→ A5.1（冻结表示探针）→ A5.2（联合训练）→ A5.3（正式生成验收）**为主线；各阶段在门禁处决定是否推进。

## 二、A5.0：多标签监督与数据血缘审计（CPU）

### 1. 监督的来源与标签索引

从官方 Schema 按固定维度拼接标签：

- `personality_traits`：10 标签，索引 `0…9`；
- `interests`：12 标签，索引 `10…21`；
- `style`：11 标签，索引 `22…32`。

定义 `label_order` 为该顺序得到的 **33 个带维度的键**，例如 `personality_traits:open`、`interests:games`，避免未来不同维度同名标签造成歧义。模型分类头输出的第 `j` 列永远对应该键；正式 JSON 仍只使用原字段中的标签字符串。

对于一个训练样本，`y_j=1` 表示对应 Gold 数组明确包含该标签；`y_j=0` 表示对应维度已经按现有任务的封闭标签集完成标注，但该标签未被列出。额外定义 `m_j∈{0,1}`：该样本的此标签是否允许参与 BCE。

**最重要的语义区别**：在当前官方 Schema 中，`user_profile` 的三个维度是必填数组；`[]` 是合法的“当前 Gold 未选中任何标签”，**不等于字段缺失或标注状态未知**。因此在遵循官方 Gold 的 *closed-world* 训练解释下，应默认将已完成标注维度中的所有 33 项设为 `m_j=1`，正例为 1、未选中为 0。这样既有正例也有负例信号。

但是自然语言中“没有被 Gold 选中”不保证用户客观上没有该特征。必须在报告中把 `0` 称为**监督负例**，而不是现实世界的确定否定。对可能存在的漏标、含糊边界做噪声诊断。

现有 `src/training/experiment_spec.py` 要求 `bce.missing_label_policy == "masked_unknown"`，这是先前留下的通用防护约定，不可直接解释成“所有未出现的标签都不参与监督”——那会使 BCE 缺少可靠的负例约束。建议在**A5 新版本实验规格**中新增明确的：

- `target_policy: closed_world_gold_v1`：完整三维数组时，`y` 为 33 维二进制向量，`mask` 全 1；
- `target_policy: explicit_unknown_mask_v1`：**仅当真实来源带有可核验的未知标注字段时**，才允许特定位置 `mask=0`；当前数据没有这类字段时不得伪造；
- 保留旧规格的行为与历史测试；若需要修改校验器，新增 `E03-experiment-spec-v2` 或 A5 专属兼容分支，不把 A3/A4 旧配置静默改义。

不得把 Gold 全空样本丢弃，也不得只训练正例。默认不设置 `pos_weight`、Focal/ASL，也不重采样。先建立无额外权重的 BCE 可解释基线。

### 2. 样本对齐：原始 target 与 SFT Token 必须相互核验

实际数据路径：

```text
D0.3 normalized Train (16,312)
  ├─ sample_id / conversation_id / history / target.user_profile
  └─ 与 D0.4.3 有效 SFT Train（16,192）按 sample_id 精确 JOIN
        ├─ input_ids / labels
        ├─ prompt_length / completion_length
        ├─ source_split = train
        └─ 派生 33维 y 与 mask；不写回旧 Train/SFT 文件
```

**严禁**按 JSONL 行序号、`conversation_id` 单独连接，也不允许把 16,312 条都当成可训练数据。对 120 条 SFT 不可用样本仅审计排除原因，不补生成、不突破 `S=2048`、`P=1280` 预算。

每条新监督记录仅包含 `sample_id`、`conversation_id`、`prompt_length`、`label_order_version`、`y`、`mask`、来源 Hash、必要的诊断统计；完整历史和 Gold 文本仍留在已有受控文件，不复制进 Git。确认：

1. SFT 的每个 `sample_id` 在 D0.3 规范化 Train 中**恰好匹配一次**，来源均为 Train；
2. 33 维 `y/mask` 的次序、形状和二进制约束正确，三维空数组形成全零 `y` 和全一 `mask`；
3. `labels[:prompt_length]` 全是 `-100`，`labels[prompt_length:]` 对齐 Completion；Prompt 结束位置不是答案 Token；
4. 原始 Gold 未改变，所有正例来自合法枚举，禁止额外标签名、去重重排、默默丢弃错误行；
5. D0.3、D0.4.3、Tokenizer、P0、F2/T1、Schema Hash 均匹配已有 E01-B/A4 记录。

### 3. 统计要具体到能指导下一阶段

由 **Train-only** 输出 33 标签的正例数、负例数、正例占比、每维标签密度、三维全空比例、不同历史消息数下的标签数量，以及同会话不同预测点的标签标注演化。指出正例极少或完全没有正例的标签，以及哪些标签可能存在语义重叠。单纯“同一会话不同轮画像不同”不一定是错误；只有严格相同证据与目标的冲突才能认定为矛盾。

另外统计 Train 内部按会话切分后，各标签在拟合集、校准集、内部留出集的正例覆盖；如果某标签在训练分区没有正例，该标签探针只标为 `insufficient_support`，不得凭空给出阈值效果。

建议在真正提取 GPU 表示之前冻结三个 Train 内部集合，按 **conversation_id 分组**，例如 Fit/Calibration/Internal Holdout 约 `70%/15%/15%` 的会话（比例可按实际覆盖修订，但须在看模型结果前锁定）。会话不跨分区，`sample_id` 不重复。另保留已冻结的 Dev 224 点/101 会话用于同协议外部诊断；不可拿它训练分类头或调阈值。Dev 其余会话也不得隐式混进 Fit。

**A5.0 验收门槛**：所有来源和数量对齐、无泄漏、33 维目标与 Mask 的真实语义确定、至少可构建一个具备正负实例的监督问题；未通过则只提交错误报告，不进入 GPU 探针。

## 三、A5.1：冻结 E01-B 的 33 标签线性分类探针

### 1. 为什么必须先做这个实验

我们需要辨别：“模型表示里已经有画像信息，但 JSON 生成没有充分利用”与“表示本身不利于判别”这两个可能原因。

固定 E01-B 的全部 Base 和 LoRA，不做任何参数更新。对每条用户历史，提取一个向量 `h∈R^d`，再训练一个独立线性层：

$$
\mathbf z=W\mathbf h+\mathbf b,\quad W\in\mathbb R^{33\times d},\quad
\mathbf p=\sigma(\mathbf z)
$$

对于第 `j` 个标签，`p_j` 是辅助分类器估计该标签为正的概率。它不是最终生成模型的 Token 概率，也不是需要在比赛推理中额外调用的第二个模型。

### 2. 唯一允许的特征读取位置：Prompt 结束位置

现有 SFT 的序列是：

```text
[input_ids: system+history+assistant generation prefix][Gold JSON completion + EOS]
  0 ... prompt_length-1                       prompt_length ... end
               ↑
         读取 h[prompt_length-1]
```

- Train 特征输入首选现有 SFT 行的 **`input_ids[:prompt_length]`**，与 E01-B 的训练 Token 完全一致；
- Dev 224 特征则由**无 target 的** `id + history` 经现有 `prepare_sample_messages` / P0/F2/T1 得到 Prompt Token，不能先拼入 Gold；
- 取模型最后一层在**最后一个 Prompt Token**位置的隐藏状态；这个 Token 通常属于 assistant generation prefix，仍发生在输出答案之前；
- 批次右填充时按每条样本 `prompt_length-1` gather，不能直接取 `hidden[:, -1, :]`；
- 严禁用完整序列最后一个 Token、`response_text` 后的 Token 或 Gold 标签自身作为特征。也不使用未来对话轮次。

这里依据 Decoder 的因果 Attention：在位置 `t=prompt_length-1` 计算的隐藏状态无法读取后续 Gold Completion Token。为了防止工程实现中的错位，必须在 CPU 小模型上验证“向相同 Prompt 后附加不同 Gold，读取的 Prompt-end 隐藏状态应一致（误差按浮点容差）”，还必须比较仅 Prompt 前向与完整序列前向在相同位置的结果。

为提高效率，实际 A5.1 **直接对 Prompt-only 输入前向**，在 `model.eval()` 与 `torch.inference_mode()` 下提取最后层特征，禁止生成正文。使用原 Qwen3-1.7B + E01-B Adapter 的 NF4/BF16 路径，`autocast_adapter_dtype=False` 保持历史保存 dtype；对 Base/Adapter/Tokenizer 的 SHA 校验必须通过。可先用 `output_hidden_states=True` 验证模型输出结构，再采用只保留最后一层所需向量的内存友好实现；如果用 Hook，需要测试没有捕获错误层或截断梯度（A5.1 此时无梯度）。

特征以 `float16`/`bfloat16` 或 `float32` 缓存在本机忽略目录，记录**实际 dtype**，分类头计算使用 `float32`。文件只需 `{sample_id, feature_vector}` 及 Manifest，不含 Prompt 文本、Target、生成回复。不得一次把 16,192 条长序列全部送入 GPU。特征生成可断点续跑，但必须保证每个 ID 恰好一次，按清单校验全体 SHA。

### 3. 线性分类器训练、阈值与对照

将已冻结的 Train-Fit 特征与 `y/mask` 对齐，仅更新 `W,b`；E01-B 全程 eval/frozen。损失用第 4 节定义的 BCE（不使用类别权重），优化器学习率及训练轮次只在 Train 内部校准，不看 Dev。为避免“大部分标签都预测 0”形成虚假的低 Loss，评估必须包含 Precision、Recall、33 标签 Micro/Macro-F1、每维指标、TP/FP/FN、非空率和分标签支持度。

探针至少设置三个参照：

1. **频率/常量先验**：按 Train-Fit 标签正例率输出固定概率，用来识别是否只是学会热门标签；
2. **相同特征的线性 BCE 探针**：研究主对象；
3. **可选的 CPU 文本稀疏基线**（例如 TF-IDF + 逻辑回归）：用于判断难度，不作为正式系统功能；依赖缺失时标为 `not_run`，不能阻塞主线。

报告两个明确分开的预测口径：

- `threshold=0.5`：最朴素的 sigmoid 决策结果；
- **仅根据 Train-Calibration** 选定的一个全局阈值（或在拟合前明确固定的三维阈值方案）：在内部留出集和 Dev 224 上只应用、不重调。小样本稀有标签不单独搜索阈值；如果做每标签阈值，必须放在探索性附录，并标注支持度。

阈值选择若使用 F1 目标，应明确该阈值是为 F1 调过的，因此还需报告 Precision/FP；不可把它与 E01-B 的 JSON 生成结果当作完全同质的部署模型比较。

**必须做一项防泄漏对照**：使用相同特征但打乱 Train-Fit 的标签对应关系，在独立 Internal Holdout 上通常不应保持原来分类效果。若打乱标签后仍出现异常高的成绩，应排查 ID 顺序、Gold 混入、会话重叠及缓存文件错配。

### 4. 探针的解释边界和 A5.1 决策

探针成功表示：已有 E01-B 表示可以支持一定质量的**线性读出**，值得考虑通过辅助监督改善表示。它**不证明** BCE 更新会改善 JSON 生成。

探针失败也不能严格证明“模型完全没有相关信息”，因为表示可能是非线性可分、位置选择不合适或正例过少。本阶段应记录这些限制，而不是直接得出容量不足、必须扩大 Rank 的结论。

建议将 `probe_supported` 的门槛定为：在会话隔离的 Internal Holdout 上，对比频率先验有稳定的标签判别收益，且在目标 Precision 或 FP 约束下仍有非平凡 Recall；多个有足够正例的标签/维度有信号，而非靠一两个高频标签拉动。然后在冻结 Dev 224 上做**一次**描述性核验。不把纯探针分数的任何上升当作正式比赛得分提升。

若 `probe_unsupported`：分析是数据目标/Mask、稀有支持、特征提取还是特征可分性问题；不得自动进入 A5.2。可以形成明确的继续/停止建议供用户决策。

## 四、A5.2：SFT + BCE 联合 LoRA 训练

### 1. 模型结构与真正需要更新的参数

在 **A5.1 得到有用信号**、且单独通过新运行授权及 GPU dry-step 后，建立以下多任务训练路径：

```text
输入：同一份 P0 + T1 用户历史、同一份 Gold Completion、33维 y/mask
                │
     Qwen3-1.7B NF4 冻结 Base
                │
       E01-B 初始化的 LoRA
                │
         单次因果前向计算
         ┌──────┴────────┐
         │               │
  完整序列 LM logits   Prompt-end hidden h
         │               │
  Completion-only CE   Linear(d, 33) + BCE
         │               │
         └──────┬────────┘
                │
       L_total = L_sft + λ L_bce
                │
       反向传播更新 LoRA + 分类头
   （Base 量化权重全程冻结）
```

联合阶段与探针阶段的区别：**探针仅训练分类头**；联合训练中 BCE 的梯度必须从 `Linear` 经过 Prompt-end 隐藏状态流回 LoRA。否则即使分类头 Loss 下降，也没有实现对 JSON 生成模型的辅助训练。

辅助头作为独立 `aux_head.safetensors` 保存并可复载用于分析；**正式参赛推理默认不加载辅助头**，继续原来的 P0/F2/T1 JSON 生成路径。最终成功只能由“仅加载新 LoRA Adapter”的真实生成评分决定。今后若考虑在推理时使用分类头融合输出，属于另一项新实验，**本 A5 不实现**。

### 2. BCE 计算及 Mask 归一化

对每个输入的分类 logits `z∈R^33`，目标 `y∈{0,1}^33`，Mask `m∈{0,1}^33`，采用稳定的 `BCEWithLogitsLoss(reduction="none")`，不要先显式 sigmoid 后再求 log：

$$
\ell_j(z_j,y_j)=-y_j\log\sigma(z_j)-(1-y_j)\log(1-\sigma(z_j))
$$

$$
L_{\mathrm{BCE}}=\frac{1}{B}\sum_{i=1}^B
\frac{\sum_{j=1}^{33}m_{ij}\ell_j(z_{ij},y_{ij})}
{\max(1,\sum_{j=1}^{33}m_{ij})}
\qquad
L_{\mathrm{total}}=L_{\mathrm{SFT}}+\lambda L_{\mathrm{BCE}}
$$

只有在**明确的标注缺失证据**下才有 `m=0`；主实验应使用完整三维标注的 33 个已知监督位置。`sum(m)=0` 的样本必须作为坏数据停止或显式跳过并记录，不能假装 BCE 有效。BCE 在 `float32` 计算；SFT 继续保持原 Completion-only 标签掩码，不覆盖已有 `labels`。

第一轮训练不引入 `pos_weight`、ASL、Focal、样本 Replay 或标签顺序增强，避免同时改变多个因素。`λ` 必须在正式短程对照前冻结，可先以 `λ=0.1` 作为**待 dry-step 验证的候选初值**，不是已证实的最佳超参数。dry-step 要报告 `L_sft`、`L_bce`、`λL_bce`、LoRA 的 SFT/BCE 梯度范数、分类头梯度、总梯度、非有限性以及显存。若辅助梯度相对 SFT 异常主导，停止并重写配置/重新审批，**不得在跑过 Dev 结果后临时改 λ 追指标**。

### 3. 一个非常容易犯的错误：用错隐藏状态位置

在联合训练时，模型输入通常是完整 `[Prompt | Gold Completion]`。如果直接取最终 Token 的隐藏状态，BCE 头可能读到 Gold 画像标签和回复，轻松学会分类，但**推理时模型根本拿不到这些内容**。这就是严重的目标泄漏。

必须从 `input_ids` 的 **`prompt_length - 1`** 位置取 `h`，并用真实的 causal Attention 实现及断言核验。至少写四种测试：

- 同一 Prompt 换成互相矛盾的两个 Gold Completion，取到的 `h` 不变（容差范围内）；
- 同一完整序列仅改变后续 `response_text`，`h` 不变；
- 同一 Batch 进行不同长度右填充时，gather 的位置仍是各自 Prompt 结束，而不是 padding；
- 人为将 `h` 错取为最后 Token 时，防泄漏测试**必须能够抓到差异**（防止测试本身没有检测力）。

实现时优先复用同一次前向用于 SFT 和 BCE，但 RTX 4060 8GB 上 A4 最坏长序列 dry backward 已达到约 `7.47GB allocated / 7.63GB reserved`，**不能假定开启 `output_hidden_states=True` 后还有足够显存**。允许 CPU 小模型先验证完整 hidden-states 实现；真实 GPU dry-step 分别测准确性和峰值。如必须改为仅捕获最终层输出的 Hook，需确保它对应模型实际最终 hidden state、保留梯度、不会额外执行第二个完整模型前向；必须有数值等价和梯度等价测试。禁止靠偷偷把 `S=2048` 改短、CPU Offload、变更精度或减少目标标签来绕过资源门禁。

### 4. 配对实验设计：必须同时有 Control 与 Candidate

**起点相同**：两组都从同一个只读 E01-B Full Adapter 加载，保留 LoRA Rank 8、alpha 16、七个 target modules、Base NF4/BF16、Tokenizer/P0/F2/T1、Completion-only SFT。各组新建独立 AdamW 状态，绝不恢复 A4 或 E01-B 优化器。

| 组别 | 唯一区别 | 用途 |
|---|---|---|
| `A5-Control-SFT` | `λ=0`，仅原始 SFT CE；新独立 Run | 测量同样短程训练本身可能造成的质量漂移 |
| `A5-Candidate-SFT-BCE` | `λ>0`，同一 SFT CE 额外加 33 标签 BCE，更新 LoRA+辅助头 | 测量新增 BCE 是否带来增量效果 |
| `E01-B Full` | 不训练、不修改 | 判断新候选是否在绝对质量上优于稳定基线 |

两组的 Train 样本 ID、顺序、有效 batch、optimizer step、学习率、seed、scheduler、模型初始化、模型前向和 SFT Loss 归一化尽可能一致；记录不可能完全相同的项目（例如辅助头参数）。**不得直接拿 A4 的 64 步结果当作 A5 Control**：A4 的样本 schedule、实现、损失处理和随机数状态未被证明与 A5 完全一致。

推荐首轮做固定 `128 optimizer steps × microbatch=1 × grad_accum=4` 的两组受控对照；在此之前可做各自 1 个无 optimizer update 的 GPU dry-step。若 128 步计划需要进一步缩为 64 步，可以在获取任何候选 Dev 结果前重新冻结新的预算。要扩到 256 或更多，创建新实验规格与授权，不得把新建优化器的第二次续训说成一次无缝连续训练。

学习率可用与 A4 可比的 `2e-5`，但必须说明这是实验控制值，**A4 的负面结果并未证明该学习率必定不可用**；必要时基于无 Dev 的梯度与稳定性预检另选一个值，两组同时使用并记录理由。训练标签与采样优先使用 A5.0 的自然 Train Fit（含正负）而非附加高比例 Replay，确保主要变量是 BCE。

**损失口径硬核验**：不只对比两组打印出来的 Loss 值。用 CPU toy model 比较 `λ=0` 的 A5 实现与独立标准 Completion-only CE 的梯度（同 Token、Mask、Reduction、梯度累积）一致；然后验证 `λ>0` 时 BCE 梯度确实作用到 LoRA，同时原 SFT Loss 未被修改。特别注意不同长度样本上 `mean(loss)` 与“把全部 Token 拼一起求均值”并不必然等价，控制和候选必须使用同一口径。

### 5. 训练执行过程（补充伪代码，非现有仓库 Algorithm）

```python
# INPUT: frozen Train schedule; original E01-B Adapter; y[33], mask[33]
# Two separate runs: control(lambda=0), candidate(lambda=frozen_lambda)
for group in ["control_sft", "candidate_sft_bce"]:
    verify_all_identities_and_authorization(group)
    model = load_base_nf4_and_readonly_source_adapter(
        trainable_lora=True, autocast_adapter_dtype=False)
    head = Linear(hidden_size, 33)  # classifier; isolated checkpoint
    optimizer = fresh_adamw(lora_parameters + active_head_parameters(group))
    schedule = load_same_frozen_train_schedule()

    for step in range(1, max_steps + 1):
        optimizer.zero_grad()
        for row in schedule.next_fixed_microbatches(accumulation):
            batch = collate_existing_sft_input_and_labels(row)
            y, mask = lookup_train_only_33_label_targets(row.sample_id)
            assert prompt_and_completion_masks_are_valid(batch)

            # FULL causal forward for teacher-forced SFT
            output, prompt_end_hidden = forward_with_prompt_end_hidden(
                model, batch.input_ids, batch.attention_mask,
                position=row.prompt_length - 1)
            sft_loss = completion_only_ce(output.logits, batch.labels)
            bce_loss = masked_bce_logits(head(prompt_end_hidden), y, mask)
            lam = 0.0 if group == "control_sft" else frozen_lambda
            total_loss = sft_loss + lam * bce_loss
            (total_loss / accumulation).backward()

        assert_finite_gradients_and_expected_trainable_parameters()
        clip_grad_norm_if_configured()
        optimizer.step()
        append_optimizer_step_manifest_and_timing()
        save_only_at_predeclared_checkpoints()

    save_new_lora_and_separate_aux_head()
    independently_reload_and_compare_saved_parameters()
    verify_e01b_source_adapter_and_base_unchanged()
```

实现中 `control_sft` 即使计算 `bce_loss` 也**不应该**让它更新 LoRA；是否创建但冻结辅助头、是否计算只用于可比性审计的 BCE 值应在配置和测试中固定。不得将训练时真实 `y` 拼入 Prompt，也不得在推理代码中读取真实 Gold。

### 6. 运行身份、保存与 GPU 保护

严格沿用仓库的不可变 Run：`outputs/training/E03-A5/<run-id>/`。每条 Run 固定并保存：Git Commit/dirty status、配置 SHA、Train/Dev ID 清单 SHA、Schema/P0/Tokenizer/Base/Adapter SHA、头结构与初始化 Seed、`label_order`/Mask 版本、数据与 schedule Hash、step 数、LR/λ、优化器状态范围、NF4/BF16/设备事实、实际训练总时长、显存、每步 SFT/BCE/Total Loss、Gradient norm、参数变更检查、Checkpoint SHA、保存重载结果及失败状态。

A4 GPU dry-step 的显存利用已经接近设备上限，因此在 A5 里**先进行最大长度 2048 Token 的无更新 dry backward**；如果基础 forward + BCE 已经 OOM，必须保留失败证据并停止。不得悄悄使用 CPU/Disk Offload、自动更改模型、调小长度或直接重新启动一条有不同身份的训练。

保存/重载需满足：Base SHA 前后相同；E01-B Adapter 文件 SHA 前后相同；新 LoRA 的每一个 tensor 使用与本地推理等效的 dtype 方式独立重载（PEFT 加载应显式检查 `autocast_adapter_dtype=False` 对保存 BF16 tensor 的影响）；辅助头独立重载得到同一输入 logits（浮点容差）；正式 Fast-only 只加载新 LoRA，而不需要辅助头。

## 五、A5.3：模型筛选、生成质量和最终决策

### 1. 两条评价线不可混淆

**线 A：分类头本身的 BCE/Probe 分数。** 用于解释新增监督是否让逐标签判别更好。特征、概率、阈值及校准只能使用 Train 内部分区做拟合；在 Dev 上只能做已锁定阈值的评分，不能为提升数字临时挑选阈值。

**线 B：正式生成路径的画像分数。** 这是是否保留新 Adapter 的**主要标准**。对 Control、Candidate、E01-B 使用已对齐的 `gpu-fast-only`，同一个冻结 224 ID/101 会话、同一 P0/F2/T1/Greedy/G=1200、同一 Base/量化与解析评分器进行配对。不将分类头概率替代最终 JSON 标签，也不允许“直接改输出标签数组”混入实验。

Fast-only 对比必须覆盖：33 标签 TP/FP/FN、Micro/Macro-F1、Precision/Recall、三维 F1、短/长历史、Gold 空与非空、预测标签数量、无效率、前缀情绪、Latency/显存，以及按 **conversation** bootstrap 的配对区间。报告中明确区分 `Candidate-Control`、`Candidate-E01B`、`Control-E01B`。不能只显示 Candidate 相对 Control 的收益而隐去它比原 E01-B 更差的事实。

### 2. 观察是否发生了“再一次变得更敢输出标签”

特别报告：

- Candidate 与 Control 相比新增的 TP/FP 分别多少？新增标签的 Precision 是多少？
- Gold 全空样本的 FP 是否上升？
- 每个维度的 FP/FN 迁移，哪个维度贡献最大？
- Rare labels 是否只是训练过程的少数偶发预测？
- 画像 F1 增长是否仅靠 Recall 增长，而 Precision 明显降低？
- 高 BCE 分类准确率与实际 JSON 预测集合之间有多少不一致？

对预测差异保留**仅在忽略目录中的**最小 `{id, gold标签, Control标签, Candidate标签, status}` 表，聚合报告只留数量与匿名 ID，不提交敏感原文。

### 3. 建议的分阶段决策门槛

将门槛作为**工程决策规则**在第一次完整候选对比前冻结，不宣称为统计显著性检验：

| 关口 | 放行条件 | 不通过怎么办 |
|---|---|---|
| A5.0→A5.1 | 来源 JOIN、标签次序、正负/Mask 语义、会话隔离全部可复验 | 修正数据派生或明确 `blocked_label_semantics` |
| A5.1→A5.2 | 线性探针对频率先验有非平凡、跨标签的可重复判别收益；无答案泄漏；FP 可控 | 输出 `probe_unsupported/indeterminate`，默认停止训练 |
| A5.2 GPU dry-step | LoRA 与 head 均有正确梯度、SFT Loss 语义未变、没有 OOM、Base/Adapter 只读 | `gpu_preflight_failed`，不训练 |
| A5.2 训练完成 | Control/Candidate 都满足固定步数、独立状态、相同 schedule、Hash、保存/重载 | 不进入比较；不得把部分 Run 当完整模型 |
| A5.3 初筛 | Candidate Micro-F1 对 Control 有实质改善（建议先看 `+0.015` 绝对值以上），并且相对 E01-B 不显著劣化；Precision 下降不超过 `0.02`、FP 相对 E01-B 不增加超过 `10%`，情绪不下降超过 `0.02` | `candidate_rejected`；无自动延长训练 |
| A5.3 最终保留 | 在独立扩大验证和完整 JSON/回复验收中也改善，且无严重格式、情绪和响应质量退化 | 不替换 E01-B |

`+0.015`、`10% FP` 等属于建议门槛，可在实验生成前经用户审阅冻结；不等于模型真实的收益保证。224 点已被 A3/A4 多次使用，**属于 development proxy，不是独立未见测试集**。若初筛良好，另从尚未用于该轮阈值/候选决策的完整会话中冻结补充评测，最终再考虑 1,833 点完整 Dev 的 **完整 JSON** 多指标对比；此前全 Dev 曾被诊断过，因此仍不得标为全新独立测试。官方 Val 不得在本任务中用于反复调参。

最终的完整生成验收至少包括情绪 Accuracy、画像 33 标签 F1 与三维 Exact、Raw 严格 JSON、合法率、回复质量（已实现的 BLEU/ROUGE 代理等）、延迟和显存；依照仓库正式评测脚本，不能用 Fast-only 替代。辅助头即使表现优异，只要最终 JSON 没有提升，也不采用新 Adapter。

## 七、关键失败情形与处理办法

| 现象 | 最可能涉及的环节 | 必须做的检查/处理 |
|---|---|---|
| BCE Loss 很低，但所有标签都预测 0 | 严重不平衡或错误 Mask | 检查标签正负总量、每类混淆、Recall、Mask 是否把正例屏蔽；不以 Loss 判成败 |
| BCE 预测全部为正，FP 暴涨 | 负例监督缺失、`pos_weight` 或 λ 过大 | 核对 closed-world 标签和 BCE reduction；先恢复无加权 BCE，不通过改阈值掩盖 |
| 冻结探针成绩异常接近完美 | Gold 泄漏、Train/Dev 同会话、特征取到 Completion | 执行换 Gold 不变性、Prompt-only 测试、标签打乱对照及会话去重 |
| 探针有效，但新 JSON 不提升 | 判别表征不转移到生成决策 | 核验 BCE 梯度流进 LoRA、控制组相同；若真实生成不改进则拒绝候选 |
| 仅分类头更新，LoRA 梯度为零 | 从 hidden 到 LoRA 的图断开或错误 detach | CPU toy + GPU dry-step 检查参数组与梯度；修复后重开新 Run |
| GPU OOM | `output_hidden_states`/双次前向/长序列/梯度存储 | 停止，保留峰值和配置；先测试只捕获最后隐藏状态的等价实现，不偷改协议 |
| Adapter 重载结果不同 | `autocast_adapter_dtype`、Base 准备路径或量化差异 | 逐 tensor 与数值对齐，保存 dtype/hash，禁止将不一致的权重用于评测 |
| 画像 F1 上升、FP 也大幅上升 | A3/A4 已见过的高召回低精确风险 | 分维和 Gold 全空 FP 分析，按预设阈值拒绝；不据此自动延长训练 |
| 224 点看起来提升，但完整 JSON 失效 | 前缀评分不覆盖回复/后续字段 | 以完整 JSON 和正式多指标验收为准，不修改历史基线 |
| 训练器测试通过、CI 也通过 | 仍不等于 GPU 成功 | 必须独立核验真实 CUDA NF4/BF16 梯度、显存、权重变化及保存重载 |

## 八、实现边界、交付状态与最终要求

1. 继续使用 Qwen3-1.7B 和已冻结 E01-B Full；**不**在 A5 中同时改变 LoRA Rank、训练样本重采样、解码策略、P0/F2/T1、标签顺序或官方输出 Schema。
2. 不修改 `participant/start.sh`、官方数据、D0.3 切分、现有 E01/A1/A2/A3/A4 Run 与模型资产。辅助头只在研究训练/诊断中使用。
3. 新设计必须忠实反映**真实执行阶段**：Train 的监督如何与 Token JOIN → Prompt-end 特征怎么提取 → Probe 只训练分类头 → 联合训练如何把 BCE 梯度传回 LoRA → 保存后不带头的 JSON 怎么评 → 如何与 Control/Baseline 比较。
4. 每份报告明确区分 `implementation_passed`、`cpu_audit_passed`、`gpu_probe_passed`、`joint_training_completed`、`fast_eval_passed`、`candidate_quality_passed/rejected`。GPU 或评测未执行时写 `not_run`，不得以配置存在代替结果。
5. **禁止自动推进**：任何失败不得自动变更分母、样本 ID、阈值、λ、学习率、Batch、序列长度或 GPU 预算重新跑。产生语义调整时创建新实验版本、重新固定证据。
6. 完成 A5 后，Codex 应提供：修改文件清单、每阶段命令和退出码、GPU 与内存事实（如已运行）、训练/评测身份 SHA、主要 TP/FP/FN 与会话簇统计、失败和未运行项、是否建议保留候选、能否保持原正式 JSON 推理协议，以及实际 GitHub CI/PR 状态。

### 外部实现参考（仅用于技术语义，不代表仓库已实现）

- PyTorch `BCEWithLogitsLoss`：https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html —— 直接对 logits 求稳定 BCE；`reduction="none"` 后才能应用有效 Mask 与自定义归一化。
- PEFT `PeftModel` 文档：https://huggingface.co/docs/peft/main/package_reference/peft_model —— `autocast_adapter_dtype` 默认可能转换 LoRA dtype；本仓库已有 A3/A4 相关真实问题与修复记录，必须沿用冻结 dtype 复验。

**最终交付定义**：不是“增加一个 33 标签 BCE Loss”，而是交付一套能够独立回答 *监督是否可靠、表示是否可判别、BCE 是否真正改善最终生成且不恶化 FP* 的完整、可复现、可随时停止的实验链。只有最后一项经完整 JSON 指标证明，才有资格提出替换 E01-B 的建议。
