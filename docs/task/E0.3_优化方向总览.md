## 二、E03 候选优化方向

### 1. 用户画像多标签预测（最高关注）

当前画像存在较明显的非空 Gold 被整体预测为空、部分高频标签过度预测，以及低频标签召回不足。可探索：

- **非空画像召回与误报平衡**：重点改善三维全空预测偏多的情况，同时避免简单增加预测标签造成大量 FP。
- **逐维优化**：分别诊断 `personality_traits`、`interests`、`style` 的学习差异；`style` 和人格维度的长尾表现值得优先关注。
- **标签证据与边界**：检查数据标注口径、含糊标签的语义界限、单轮与多轮上下文中可提取的画像证据。
- **多标签学习目标**：探索标签均衡采样、训练样本配比、任务加权或分阶段学习对画像质量的影响。

### 2. 情绪类别识别与长尾泛化（高关注）

总体 Accuracy 已明显提升，但 `mixed` 等类别召回较低，`fear`、`helplessness` 等常混淆为 `anxiety`。可探索：

- **易混淆类别边界**：专门关注 `fear / anxiety / helplessness / shame / mixed` 的区分。
- **稀缺类别的学习**：研究类别不平衡、稀缺情绪样本的覆盖及训练分布调整；低支持类别不能只根据几个 Dev 样本作结论。
- **情绪与上下文关系**：检查模型对转折、混合情绪、隐含情绪及多轮变化的理解。
- **辅助监督与课程安排**：在不破坏原有输出协议的前提下评估更清晰的情绪监督形式。

### 3. JSON / A0 格式稳定性（高关注、低训练成本优先）

现有结构格式已经较好，但长输出截断仍会造成整条原始结果失效。可探索：

- **受约束生成**：评估 vLLM 0.11.1 的 Structured Outputs / JSON Schema 约束及其兼容性。
- **生成终止与长度控制**：关注异常长回复、到达 `G=1200`、JSON 未闭合和缺少停止条件的问题。
- **格式错误的训练侧原因**：检查 SFT 输出样本的结构一致性、标签合法性和回复长度分布。
- **推理后处理边界**：继续区分 Raw 合法率与归一化后 Submission 合法率；避免后处理掩盖模型原始缺陷。

受约束生成可能改变模型的输出分布和速度，因此只能作为新实验候选，不能替换已有基线结果。

### 4. Prompt 与输入历史管理（中高关注、可先低成本验证）

已有 P0/F2/T1 和 Tokenizer / Chat Template 身份经过验证。后续如有语义改动，应建立新协议版本：

- **系统指令 P1 候选**：关注情绪、画像、回复三个任务的指令清晰度和优先级，避免冗长提示挤压历史空间。
- **历史选择策略 T2 候选**：探索最近对话、长期画像、重要事件等信息的不同选择方式及 Token 预算。
- **输出组织策略**：调整字段顺序、约束描述、回复长度指引，检验对生成质量、结构稳定性及延迟的影响。
- **训练—推理一致性**：新 Prompt / History 方案需要验证是否偏离既有 SFT 分布，必要时配套新的训练数据版本。

### 5. SFT 数据与训练配置（中高关注，需要训练成本）

- **数据质量与分布**：检查情绪/画像标签、错误或模糊标注、重复样本、极长回复和稀缺场景覆盖。
- **数据采样与混合策略**：探索类别均衡、难例覆盖、情绪/画像/回复任务的样本比例。
- **LoRA 与优化超参数**：比较 rank、alpha、target modules、学习率、训练轮数、调度和正则化策略。
- **多任务目标权衡**：研究情绪、画像和回复在共享 Completion-only SFT 中是否存在优化目标竞争；必要时尝试分阶段或加权训练。
- **基线续训与重新初始化**：对比从 Full B 续训和从 Base 新建 Adapter 的收益、成本和遗忘风险。

此类方向必须由新实验单独验证，不能仅依据 Dev 错误直接认定是数据不平衡或损失竞争造成的。

### 6. 回复质量与情感陪伴能力（中高关注）

- **回复的贴题与情感支持**：避免泛泛安慰、重复表述、忽视情绪转折或与画像不一致。
- **语言与风格**：探索更自然的中文回复、适度细节、用户偏好的表达方式以及多轮连贯性。
- **长度与文本指标的平衡**：减少无效长输出，同时防止过短导致信息不足、BLEU/ROUGE 或人工体验退化。
- **质量评测补全**：在固定样本上增加人工盲审维度和可复现的 BERTScore，辅助判断文本指标是否与真实效果一致。

### 7. 模型规模与整体结构（探索性、高成本）

- **1.7B 与更大模型**：评估 3B/4B 等候选在情绪、画像、回复上的潜在收益及训练/推理成本；8GB 显存是实际限制。
- **两阶段生成**：探索先完成情绪/画像判断，再生成回复；可能提升任务隔离性，但会增加推理调用与延迟。
- **任务专用辅助模块**：讨论独立小型分类器、多标签模块或蒸馏方案是否值得额外复杂度。
- **参数高效方法**：在 LoRA 之外研究其他轻量微调或量化策略，但应先证实简单方法无法满足目标。

这组方向暂列后备方案；当前没有证据表明必须立即更换 Qwen3-1.7B。

### 8. 推理性能与资源优化（中关注）

- **生成速度与长尾耗时**：控制冗余 Token、降低长样本和异常输出引起的 P95 / 最大延迟。
- **vLLM 配置与量化**：比较 KV Cache、显存利用率、批处理、并发与量化策略的成本和收益；区分部署收益与模型能力变化。
- **推理链路开销**：审查 Prompt 构造、历史裁剪、API 往返、解析和服务初始化等阶段的耗时。
- **模型与缓存占用**：建立磁盘和显存预算，不在每次效果实验后重复打包 Docker 或复制 Base 权重。

## 三、优先级与阶段安排

| 顺序 | 候选工作流 | 主要理由 | 资源等级 |
|---|---|---|---|
| **P0** | 冻结 Full B 基线；整理统一的误差分类和评测指标 | 确保后续每个改动可以独立判断有效性 | 低（CPU/只读分析） |
| **P1** | 画像漏报与标签分布；情绪易混淆类 | 当前已观察到的核心质量短板 | 低→中（先诊断，后小试） |
| **P1** | JSON 约束生成、输出长度与停止行为 | 格式错误会影响多项指标，且可先不训练 | 低→中（小规模 GPU） |
| **P2** | 新 Prompt / History 版本和回复质量控制 | 有机会改善多项任务，但需关注训练分布偏移 | 中（配对推理） |
| **P2** | 定向 SFT、采样与 LoRA 超参数 | 可能带来系统性质量提升，但需要 GPU 训练 | 中→高 |
| **P3** | 3B/4B、更复杂的两阶段或模块化结构 | 成本与部署风险较高，保留为对照候选 | 高 |
| **并行约束** | 推理延迟、显存、磁盘、评测可靠性 | 作为所有 E03 候选共同的资源与质量门禁 | 按实验测量 |

这里的 P0/P1/P2/P3 是**本文件的工作优先级**，不等同于项目的 Prompt 协议版本 P0。

## 四、E03 实验管理的共同约束

- **基线独立**：保留 E01-B Full Adapter、1,833 Dev 配对结果、E02 的 100 条性能结果和已经验证可运行的 Docker 实现。新方向使用新的实验 ID、配置和结果目录。
- **一次只验证有限变量**：优先采用只读统计、无训练对照、小样本推理和小规模训练；确认有可信收益后再扩大样本或训练规模。
- **评测分层**：训练集用于学习，Dev 用于方案比较；官方 Val 与正式提交额度不参与高频试错。优先使用情绪 Macro-F1、画像 Micro/Macro-F1、非空召回、Exact、Raw A0、文本质量和延迟的联合判断。
- **权衡副作用**：某项指标提升若同时导致画像误报、文本退化、响应变慢或显存超限，需要显式记录，不能只看单一最高分。
- **磁盘预算**：避免重复复制约 4GB Base 模型、重复生成 Docker 上下文和 30GB 级镜像。实验优先保存小体积 Adapter、配置、指标、必要日志和文件指纹；清理旧资产前先审计大小、复现依赖及是否已有唯一副本，**不得自动删除**。
- **提交额度**：在本地固定对照取得明确、稳定的改进之前，不进行新的官网提交。正式提交留给经过复核的少数候选模型。
- **交付延期**：最终镜像导出、tar SHA、独立环境重新导入和赛事提交文档均移至模型候选确定之后，不列为当前 E03 的前置任务。

## 五、目前建议先讨论的三个决策

1. **先优化画像还是情绪？** 画像的非空漏报、低 Macro-F1 更突出；情绪的混淆类别可能更直接影响情绪识别得分。两者均可从零训练成本的诊断开始。
2. **先尝试无训练推理改动，还是定向补训？** 约束生成和长度管理成本较低；画像/情绪的系统性误差可能更需要数据与 SFT 调整。
3. **保持 1.7B，还是考虑更大模型？** 建议先把现有模型的可改善空间与性能预算量化，再决定是否承担模型迁移、8GB 显存和磁盘成本。

> **本文件只确定候选方向和先后顺序。** 不批准具体修改 Prompt、数据、Loss 或训练配置；下一步从最优先的 1–2 条方向中挑选一条，再单独制定 E03 的实验设计、成本预算与验收标准。
