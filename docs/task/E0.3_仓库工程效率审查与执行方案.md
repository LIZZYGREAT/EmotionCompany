## 一、审查结论及边界

仓库基础工程不是从零开始：D0.4.3 的预编码 Completion-only SFT、P0/F2/T1、QLoRA、完整 Trainer Checkpoint/Resume、Adapter 重载、Full Dev 配对评分及 E02 Docker 可行性都已有实际验收。E01-B Full 画像 33 标签 Micro-F1 为 `0.4223`；E03-A1 `label_value_x2` 为 `0.3839`，已决定不替换基线。E03-A2 当前没有证明概率回收可以带来收益。**这些已通过的链路都应保留，不应为了“代码更优雅”推翻重写。**

当前最有价值的工程整改不是更改模型计算逻辑，而是：

1. 建立**画像快速生成评测**，使短程候选不用生成长回复才能知道画像 F1；
2. 建立**阶段耗时与 GPU 资源账本**，定位真实瓶颈后才改动训练回调或审计频率；
3. 让新增实验的**核心测试进入 CI**，避免“unit-cpu 通过”但训练新增代码没有被测试；
4. 修正**复现实验、输入身份和代码归档**的薄弱点，避免 A2 式导出遗漏当前 user 的问题再次出现；
5. 在不破坏 E01/E03-A1 的前提下，明确后续三种专项训练方案所需的**最小扩展契约**。

本任务以上述提交中的跟踪文件为静态基准，同时可读取本机已存在的忽略目录 Run 产物进行只读汇总。历史表格中的结论是待复核的审查线索，不自动视为当前代码缺陷；没有独立阶段计时数据的开销判断仍标记为“待测”，不得据代码结构推断提速幅度。

## 三、第一批任务：先解除实验迭代最严重的阻塞（必须完成）

### T1：构建可独立验收的画像快速评测（P0，主要投入）

**问题与原理**：在现有标准序列化中，模型先输出 `emotion_label` 和 `user_profile`，才输出很长的 `response_text`。当本次实验只需比较画像指标时，可以尝试在**完整关闭顶层 `user_profile` 对象后**停止生成，从已生成的前缀中取得情绪与画像。但模型自由生成时不保证严格遵循键顺序，故需要“可靠识别前缀 + 出错即拒绝”的机制，而不是简单 `str.find('}')` 或截取固定 Token 数。

**建议新增**：

```text
src/evaluation/profile_prefix.py        # 前缀状态机、解析、校验；尽可能纯 Python
scripts/e03_profile_fast_eval.py         # 隔离的可执行 CLI；复用现有 Runner/模型配置
configs/evaluation/e03_profile_fast.yaml # 只读研究配置，固定样本/预算/来源
tests/test_e03_profile_prefix.py         # 合成边界测试（实际文件不应含前置空格）
tests/test_e03_profile_fast_eval.py      # 对齐、状态、选择与对照测试
```

**执行步骤**：

1. 先从已有 `src/shared/prompting.py`、`participant/run_inference.py` 复用真实 P0/F2/T1 及 Greedy 参数，建立固定样本集与对应完整推理基线的 Run 身份。样本选择先按会话去重、固定 Seed、记录 ID SHA；不可根据当前候选的预测表现临时改样本。
2. 写一个只处理模型**实际生成文本前缀**的 JSON 结构状态机。跟踪字符串引号、反斜杠转义、括号层级以及顶层字段位置；仅当确认 `emotion_label` 是合法字符串且 `user_profile` 三维数组对象闭合时才返回可用画像。碰到重排、缺字段、结构错误、提前 EOS、Token 上限等返回有原因的 `invalid`/`incomplete`/`unsupported_order`，不得默默补 `[]`。
3. 本地调试模式用模型生成的真实 Token 逐步喂给停止器；停止发生在画像字段真正结束后。即使生成文本恰好出现花括号或字符串中包含 JSON 字面片段，也不得误停。停止器不应窥视 Gold。
4. 首先用已有完整 Raw 文本做**纯 CPU 前缀解析**，统计能从多少条既有完整生成中无歧义地截出画像。该统计只验证解析适用范围，**不能证明提前停止时的 Token 一致性**。
5. 接着在同一固定 16 条（如有条件再扩至 32 条）Dev 输入上做两次 Greedy：完整生成与提前停止。核验停止前生成的 Token IDs、`emotion_label`、三个画像维度**逐项相等**；记录两次总耗时、GPU 峰值显存和有效率。GPU 预算总计不超过 **900 秒**，超过立即 `budget_exhausted`，不继续扩大。
6. 对失败或无法提前停止的样本，统一记录覆盖率并从快速指标的分母中显式标记；如果提供“完整生成回退”模式，其成本与成功率必须单独报告，不能用回退掩饰快速模式失败。
7. 快速评测仅输出 `profile_fast_metrics.json`，包括样本覆盖、有效/无效、TP/FP/FN、Micro-F1、Macro-F1、三维非空 Recall、样本/会话数、时长、相对完整生成的节省及一致性。**不把只生成画像的半截 JSON 冒充完整赛事 Submission**。

**验收**：合成 JSON 字符串、Unicode、转义、字段重排、重复键、数组、截断、跨 Token 结束标记通过；已完成全输出的可解析前缀复算准确；16 条以上双跑中**凡标为 `valid` 的全部与完整生成逐标签一致**；任何不一致不得发布为 `passed`。若速度优势不明显、正常 JSON 覆盖太低或显存上升，则直接标为 `not_adopted`，不在赛前继续优化停止器。

**注意**：为了减少不必要的耗时，允许先做一轮 CPU 解析和合成测试；GPU 校验应在代码通过门禁后一次性进行，不要反复加载模型并多次执行相同测试。

## 四、第二批任务：测量后再优化训练通路（条件执行）

### T5：受控减少重复核验开销，不牺牲安全性（P1）

**先执行 T2 测时，不要先改性能代码。** 若实测显示某阶段开销明显，Codex 才可以在新实验模式下实现下面的局部优化，并与原路径做逐项对照：

- **梯度证据**：对新的实验配置引入 `audit_policy=full|sampled`。`full` 保留原行为；`sampled` 仅允许减少非关键 Step 的全参数梯度范数/数值同步及参数复制频率。首步、末步、每个 Checkpoint 前、指定间隔及出现异常时均需执行完整核验；每步仍需基本 Loss 非有限值检测，且任何异常都应停止。必须留下 `audit_checked_steps`、覆盖范围和不可覆盖的风险说明。不能偷偷改变历史 E01/A1 的 `full` 口径。
- **A1 双 Loss 复算**：`independently_recomputed_weighted_causal_lm_loss()` 每训练 micro-batch 运行一次是已证实的重复计算。允许将这种“深度一致性审计”参数化为 `first_N + every_K + last_N`，但仅作用于未来新版本训练目标。必须用合成 Logits、实际短 batch 验证新/旧 Loss 值、有效梯度和重载不变；模型全程不得因为关闭审计而无条件继续容忍 NaN/Inf。**本轮不修改历史 A1 checkpoint 的重现实验结果或其代码身份解释。**
- **Checkpoint 与身份**：`_write_checkpoint_manifest` 会 Hash Checkpoint 内文件；这一机制是恢复可靠性的基础，原则上不能取消。可测量写盘和二次校验的耗时、避免无谓的重复 `stat`/解析/身份计算；任何缓存须采用内容 SHA 和原子写入，不允许只看 mtime/size 认定权重未变。
- **Progress 写入**：`on_step_end` 每步原子写 `progress.json`；如测量证明 I/O 是瓶颈，可以在新实验中按时间或步数节流**非权威 UI 进度**，但 `train_log.jsonl`、完成的 Checkpoint Manifest、异常与恢复原子性必须保持。
- **Dev CE 频率**：短程筛选改成预设少量 Checkpoint 检查，避免随每个新的 Candidate 重复完整 1,821 条 Dev Teacher-forced CE；允许抽固定子集，但必须明确是短程探针，不能替换最终全量 Dev 结果。

**门槛**：任何测不到实际收益，或导致训练步数、抽样顺序、`labels`、Checkpoint/Resume 或重载差异的修改，直接撤销，不为追求“理论优化”保留代码。测试默认仅 CPU 合成；单机 GPU 如需确认只批准短运行前向/最多 2–4 步专用测试，不批准新的正式训练。

### T6：为专项训练建立最小扩展契约（P1，当前只实现接口和测试，不跑实验）

**已确认的结构性问题**：`load_config()` 固定实验版本集合；`_select_real_samples()` 固定 E01/A1 的全量/选样；`_validate_staged_budget()` 将 E03-A1 锁定于 `r=8`、全量 Train、128/4048 步、`init_adapter=null`。这保证了历史复现，但新方案不能直接借用 E03-A1 的实验 ID 来绕过约束。

建议以**新实验版本**而非改写 E01/A1 为前提，做最小的可审计扩展设计：

| 后续能力 | 新接口要表达什么 | 本任务只做什么 |
|---|---|---|
| 合理重采样 + Replay | `sampling_strategy`、`sampling_seed`、Train 派生样本来源、每会话曝光数、采样结果 SHA、Replay 比例、各维空/非空分布、实际 micro-batch/optimizer step 对齐 | 设计独立 CPU sampler 及合成测试。**Replay 指重放原始 Train 中的合法样本，不是重复使用 Dev，也不是复制模型权重。** |
| 33 标签 BCE 辅助分类 | `objective=sft|sft_plus_bce`、33 标签官方顺序、`label_mask`、辅助头来源、目标 token/hidden-state 位置、`λ`、损失分项与梯度路径、保存/重载格式 | 输出接口说明与 CPU shape/Mask 测试设计。**本任务不加载训练头、不增加模型权重，也不擅自把缺失标签视作确定负例。** |
| LoRA Rank 对照 | `r`、`alpha`、target modules、显存预检、从 Base 新建 Adapter 的 Run 身份与限制 | 输出实验配置模板和合法性校验。`r=16` 不能视为对现有 `r=8` Adapter 的无损续训，必须是另一个独立 Run。 |

**实现限制**：

1. 不要把完整 `training_sft.py` 拆成十几个文件，也不要改旧分支的 config SHA/批准记录。可以先加独立的 `src/training/experiment_spec.py`（配置合法性）和 `src/training/sampling.py`（纯 CPU 采样）；只有新 Experiment 使用该接口，历史路径不变。
2. 不把用户讨论的三个未来方向一次性实现为可启动的完整 GPU 训练器；本阶段只实现**真正可以测试的通用最小逻辑**，例如采样索引生成、分组守恒与身份校验，以及新配置门禁。
3. 若发现任何扩展必须改变已验证的 E01/A1 训练和 Resume 语义，先在任务报告中写出兼容方案和风险，等待确认，不执行高风险重构。
4. 未来训练启动必须继续要求用户明确批准；独立 Train/Dev/Val 权限，加载 Base/Adapter 的选择，随机种子与训练步骤、保存空间及最长时间都要显式写进 Manifest。

**验收**：纯 CPU 给定相同 Train 元数据与 Seed 可复现同一采样 ID 序列和哈希；无 Dev/Val 输入；会话/标签/正负分布统计守恒；一个采样 ID 可被有意重放但必须记录次数；更换 r 的 config 与原 Adapter 身份冲突会在 GPU 加载前拒绝；现有 E01/A1 原配置仍按旧规则接受或拒绝。
