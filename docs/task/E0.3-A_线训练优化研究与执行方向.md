# EmotionCompany E03-A：训练侧优化研究与执行方向

> **工作范围**：Qwen3-1.7B 的 QLoRA 训练、监督目标、画像标签学习、训练数据质量与实验评测。<br>
> **当前基线**：E01-B Full Adapter，P0/F2/T1，Completion-only SFT。<br>
> **文档定位**：A 线后续研究与实验的方向依据，可据此拆分 Codex 任务；具体训练方法、权重与实验规模在取得诊断证据后再确定。<br>
> **协作边界**：成员 A 负责训练侧，成员 B 负责对话内记忆、T2/P1 与生成策略。E03 暂不开展最终 Docker 离线打包与赛事提交。

## 一、现有基础与本阶段目标

项目当前使用 `Qwen/Qwen3-1.7B`，通过 NF4 量化基础模型、BF16 计算及 LoRA Adapter 进行监督微调。E01-B Full 使用 16,192 条有效 Train 样本训练了 4,048 个优化步，并在 1,833 条 Dev 预测点上完成 Base 与 Adapter 的配对生成评测。E01 的训练、数据构建及本地评测链路已经可运行，E03 不需要从头搭建这些基础设施。

| 指标 | E01-B Full 本地结果 | E03-A 关注点 |
|---|---:|---|
| 情绪 Accuracy / Macro-F1 | 65.36% / 0.4972 | 保持能力、监测退化；不优先追求大幅提分 |
| 画像 33 标签 Micro-F1 / Macro-F1 | 0.4223 / 0.2700 | 主要优化目标 |
| 三维画像 Exact Match | 32.08% | 在控制误报的同时提升完整匹配 |
| Raw A0 合法率 | 98.09% | 作为训练改动的质量约束 |

画像问题较为突出：1,833 条 Dev 中有 950 条被预测为三维全空，其中 427 条的 Gold 实际非空；整体画像 TP/FP/FN 为 1,130/1,271/1,821。若干标签已有一定训练支持量，推理时仍几乎不输出，例如 `conservative`、`emotionally_stable`、`indirect` 和 `high_emotional_expression`。这些现象值得研究，但尚不能据此断言原因一定是 Loss 权重、类别频率或标注错误。

E03-A 的主要研究问题是：**现有联合 SFT 是否充分训练了用户画像判别能力；如果没有，瓶颈究竟来自监督目标、标签可学习性、样本分布，还是它们之间的相互作用？**

基础模型继续固定为 Qwen3-1.7B。现阶段不将升级 3B/4B、引入独立分类器、重构推理服务或重新打包 Docker 作为 A 线目标。

## 二、研究方向与优先顺序

### 1. 监督结构与字段级 Loss 诊断（优先开展）

目前 `Completion-only SFT` 使用完整 JSON 作为训练目标，Prompt 部分 Mask 为 `-100`，有效 Completion Token 按语言模型交叉熵参与优化。输出包含情绪标签、三维画像、回复和固定的 `memory_refs=[]`。现行设计对有效 Token 使用统一基础损失权重，**没有显式为情绪、画像、回复设置独立任务权重**。由于字段 Token 长度不同，三项任务对总体 Loss 的实际影响可能不均衡。

值得先分析：

- 在现有 SFT Train 中，三个任务的内容 Token、结构 Token、结束 Token 各占多少；不同样本和不同画像状态（空/非空）有何差异。
- 在冻结 Full B Adapter 下，各字段的 Teacher-forced Loss 分布如何；画像维度和具体标签之间有无明显差异。
- 对少量有代表性的 Train 样本，字段损失对 LoRA 可训练参数的梯度范数与方向有什么特征。
- 标准 Token 平均对回复较长的样本是否形成额外的样本权重；不同长度样本进入梯度累计时，实际缩放方式是否符合预期。

一个重要区分是：**监督 Token 数量较多，并不能直接推出该任务的梯度更强或已学得更好。** 因而建议同时观察 Token、Loss 与梯度，而不是仅凭字段字数确定优化权重。

这部分可以主要通过现有数据和有限 GPU 前向/反向诊断完成，不需要重新训练整套模型。

### 2. 字段级多任务 Loss 设计（第一轮重点候选）

在明确字段边界和当前 Loss 构成后，可以研究把单一 Token 平均改为按字段聚合。对于情绪、画像和回复三个监督集合，先分别计算平均交叉熵，再赋予任务权重：

$$
L = \frac{\lambda_e L_e+\lambda_p L_p+\lambda_r L_r}{\lambda_e+\lambda_p+\lambda_r}
$$

其中 $L_e,L_p,L_r$ 为各字段有效监督 Token 的平均损失；$\lambda_e,\lambda_p,\lambda_r$ 为非负任务权重。

可能的对照包括：原始 Token 平均、字段平均等权、适度提高画像权重。**字段等权不等于原有 Token 等权**，因此它本身就应当作为一个独立实验条件。先用简单、可解释的静态方案验证假设，再考虑 GradNorm、任务不确定性加权等自适应方法。

具体工程设计有几个需要提前注意的点：

- 字段划分应明确处理 JSON 键名、标点、标签值、空数组、回复正文和 EOS。若目标是增强画像判别，可探索重点调整画像内容值的监督权重，而不只是增加固定键名的 Loss。
- 字符串边界和 Tokenizer 分词边界未必严格重合。新的分段权重或 Mask 应通过真实 Tokenizer 验证，避免遗漏或重复计权。
- 当前预编码数据、Collator、TRL Trainer 已有严格输入不变量，新增 Loss 不能破坏 Prompt Mask、Label/EOS、Padding、梯度累计和 Checkpoint 恢复机制。
- 三个字段之外的结构 Token 可以采用明确、固定的归属或独立处理策略；不同方案的定义必须写入实验配置，便于复现。

研究重点不在于寻找一组看起来“合理”的数字，而在于观察画像改善与情绪、回复质量之间是否存在可接受的权衡。

### 3. 画像标签的可学习性与 Train 数据审计（与前两项并行）

现有画像不仅存在长尾类少样本问题，还存在**有较多 Train 正例却几乎不输出**的标签。它可能反映标注语义模糊、上下文证据不足、标签之间重叠，也可能是模型已经学到保守预测策略。

可以重点研究三维画像中不同标签的训练支持量、Gold 非空率、共现情况及证据类型，并选取有代表性的 Train 样本审查。尤其需要区分：

- 明确陈述的兴趣或交流偏好；
- 需要跨多个消息推断的稳定特征；
- 仅凭短时情绪难以确认的人格判断；
- Gold 为空时，究竟表示没有对应特征，还是当前证据不足。

这些区别可能解释为什么 `interests` 明显好于 `personality_traits` 和 `style`。目前没有证据可以直接认定存在系统性错标；人工审查应围绕 Train 的真实标注说明和可见历史开展，留下证据及分歧，而不是凭模型一次预测擅自修改 Gold。

这项工作与成员 B 的对话内记忆研究有联系，但职责不同：成员 A 研究**有合法输入证据时模型能否学会标签**；成员 B 研究**较长历史中的证据能否被保留并送入模型**。

### 4. 画像专项监督与数据采样（依据前期结果选择）

如果字段加权仍不能有效改善画像，可研究对画像更有针对性的辅助监督。可选方向包括：

- 从现有 Train 记录构造单独的三维画像预测任务，训练时与完整 JSON 任务混合；
- 将单个画像标签表示为“当前历史是否支持该标签”的判断任务，强化正负边界；
- 将性格、兴趣与交流风格分成不同辅助任务，观察不同维度的学习难度；
- 根据 Train 标签频率、证据清晰度或难例类型调整样本构成。

这类辅助任务可以使用**同一个 1.7B 模型和 LoRA Adapter**。其目的在训练阶段增强画像判别，正式推理时仍保持完整联合 JSON 输出，不必增加第二个分类模型。

需要关注两个风险。第一，多标签数据中的未出现标签并不一定具有与明确负例完全相同的含义，尤其当标签来自有限的观察证据时。第二，过度提高辅助任务比例可能使模型偏向单字段输出，削弱联合生成能力。因而更适合研究适量混合或独立续训的价值，不宜一开始同时改造监督形式、采样比例和 Loss。

可以借鉴 Asymmetric Loss、Class-Balanced Loss、Focal Loss 关于不平衡、难例的思想。但它们多面向显式分类 Logit；本项目当前是自回归生成标签，不能未经改造就直接替换现有语言模型 CE。

### 5. 梯度竞争与动态权重（中后期研究）

如果已观察到画像与回复的梯度持续冲突，可以进一步研究多任务梯度平衡。例如分别计算三个任务对 LoRA 参数的梯度，观察范数及余弦相似度，判断提高画像权重是否会与回复目标产生明显竞争。

GradNorm、PCGrad、CAGrad 等方法可作为文献参考，但它们对训练循环和计算开销的要求更高。当前更适合先做少量诊断，再根据是否出现真实冲突决定是否采用。没有必要仅为了使用复杂算法而重构 Trainer。

### 6. LoRA 与优化超参数（后备方向）

E01-B Full 当前使用 LoRA `r=8`、`alpha=16`、`dropout=0`、七个投影模块、AdamW、学习率 `1e-4`、一个 Epoch。后续可在监督目标稳定后比较学习率、调度、正则化和少量 LoRA 配置；LoRA+、rsLoRA、DoRA 等作为进一步探索的参考。

由于现有失败尚未证明来自 Adapter 表达容量不足，不建议先进行大规模 rank/alpha 网格搜索。对于当前显存和训练时间预算，优先研究**能够解释画像质量变化**的少量变量。

## 三、建议的实验组织方式

A 线实验可以按研究问题形成逐步收敛的阶段，而不必一次性安排所有候选算法。

| 阶段 | 主要问题 | 可选择的工作 | 形成的认识 |
|---|---|---|---|
| **E03-A0：只读诊断** | 当前联合监督的偏差在哪里？ | 字段 Token/Loss/梯度统计，画像标签与样本证据审计 | 是否有必要优先改 Loss，哪些画像标签值得重点关注 |
| **E03-A1：基础 Loss 对照** | 字段平均、画像加权是否有效？ | 小样本工程验证与有限训练，对照原始 SFT | 画像改善幅度、副作用、训练稳定性 |
| **E03-A2：画像专项学习** | Loss 调整以外是否存在可学习性瓶颈？ | 辅助任务、样本选择、有限续训等单变量研究 | 哪种监督信息更有价值 |
| **E03-A3：候选整合** | 收益能否稳定复现并与 B 线兼容？ | 扩大验证范围，必要时进行正式新 Adapter 训练 | 可保留的训练候选及其适用条件 |

其中 A0 不要求启动新的全量训练，A1 也不需要一开始就运行完整 4,048 步。训练时间与磁盘有限，应先验证输入、Loss、梯度和运行行为正常，再衡量扩展训练的价值。

同一轮实验尽量只改变一个核心因素。例如，比较字段加权时固定基础模型、原始训练集、P0/F2/T1、训练步数和其余超参数；研究采样时则保留已经选定的 Loss 方案。若确实需要同时改变多个因素，应明确将其记录为组合方案，避免把收益误归因于某一个改动。

## 五、评测与结果判断

E03-A 关注画像，但不能仅根据某一个 Macro-F1 或 Exact Match 选择模型。建议同时观察：

- **画像**：33 标签 Micro-F1、Macro-F1；三维 Exact；各维非空 Gold 的命中率；TP/FP/FN；全空预测率；重点标签的 Precision/Recall。
- **情绪**：Accuracy 和 Macro-F1；主要用于监测训练修改是否破坏既有能力。
- **回复**：已有本地 BLEU-4、ROUGE-L 及必要的固定样本人工观察，关注是否因画像训练而变短、空泛或重复。
- **输出与资源**：Raw A0/JSON 合法率、生成长度、训练显存、训练时间和产物大小。

当前已完成的质量评测属于 `local_proxy`，不能直接等同赛事官方成绩。SFT Dev Loss 使用 1,821 条有效 SFT Dev；生成质量使用全部 1,833 条 Dev 预测点，两者分母不同，不应混用。

完整 Dev 适合对已形成的少数稳定候选作最终配对比较；日常诊断可以优先使用 Train 内部样本与小范围开发集合。避免根据 Dev 的逐条 Gold 反复修改规则、采样和权重，官方 Val 也不用于高频试错。对极低 Support 标签，应记录样本数及不确定性，不能只看单次 F1 波动。

实验结论宜明确区分：**观察事实、原因假设、实验改动、指标收益及副作用**。例如，画像 FN 减少若伴随 FP 大幅增加，或者回复明显退化，就不能简单记作综合提升。

## 六、协作与保护范围

成员 A 在训练与数据研究中，可以新增独立的 E03 脚本、配置、测试和研究报告。成员 B 主要维护 T2/P1 与推理生成相关实验，双方在公共 Prompt 构造器、评分器或 Runner 接口上需要对齐变更。

原始 Train/Val、官方 Schema、冻结基线 Prompt、E01 训练产物和现有实验报告不应被新方案覆盖。训练数据和带真实对话的 Raw 输出保留在 Git 忽略区域；文档仅写可共享的统计、方案与实验身份。更改既有 Trainer/Collator 的公共逻辑时，优先以新增版本或明确开关保持 E01-B 复现路径，避免使历史实验失去可解释性。

项目的分支、PR 和 CI 约定继续适用。A 线的研究方向可以在个人分支推进，形成可复核证据后再考虑合并公共基础设施；尚无明确收益的实验不必直接修改默认训练路径。

## 八、近期最值得形成的成果

对于 A 线，优先值得拿到的不是一个立即替换 Full B 的新模型，而是三项能够支撑训练决策的成果：

1. **字段监督诊断**：明确当前 SFT 的 Token、Loss、梯度与画像空/非空学习情况。
2. **画像标签诊断**：解释若干有训练支持却很少预测的标签，区分学习不足、标注不确定与输入证据限制。
3. **最小化 Loss 对照**：判断字段平均或适度画像加权是否存在可信收益，以及是否损害情绪、回复和格式。

基于这些证据，再决定下一项是数据采样、辅助画像任务、梯度平衡，还是继续改进已有 Loss。这样能够把有限的 GPU 时间集中在真正有解释力的方向上，并为之后与成员 B 的 T2 研究进行组合提供基础。
