# E0.3-A1 Loss 对照实验任务书

> **状态**：用户已批准；`token_mean` 项目预检通过并完成 128 步。两次最终化尝试分别发现 Dev 区域汇总和评估未关闭梯度的问题，训练 Checkpoint 未受影响；评估现改为 inference mode，等待从 `checkpoint-128` 重试最终化，两个加权短程组尚未开始。<br>
> **批准时间**：2026-11-03。<br>
> **依据**：[E0.3-A0 监督结构诊断](../experiments/E0.3-A0_监督结构诊断报告.md)与[E0.3-A0.1 画像标签诊断](../experiments/E0.3-A0.1_画像标签与细粒度监督诊断报告.md)。<br>
> **目标**：检验加强画像监督是否改善画像学习，以及收益是否只是把更多 Loss 分给 JSON 键名和标点。

## 一、诊断依据与判断边界

E0.3-A0.1 全量统计中，精确画像标签值占画像 Token 的 21.69%，固定 128 条 CE 子集里却占画像 CE 的 48.67%；画像结构占画像 Token 的 59.14%。因此只提高整个画像字段的权重，可能同时放大较多结构监督。本轮先比较完整画像区域加权与标签值加权。

84 个证据“样本—标签”组合已由三个 Agent 完成判断，其中 48 个为 `uncertain`、18 个为 `insufficient`。这提示部分画像标签的定义或证据边界可能不稳定。Agent 判断不是人工核验、Gold 真值或错标率；不得将模糊标签的 Loss 变化解释为修正了 Gold。

## 二、实验对照

所有条件使用同一 Base、同一批预编码 Train 数据、同一 P0/F2/T1、Tokenizer、随机种子、样本顺序、LoRA 初始化方式和优化器。每次只改变 Loss 权重规则；不改 Gold、采样比例、Prompt、输出格式或推理参数。所有实验都从原始 Base 新建 LoRA，不从 Full B Adapter 续训。

使用有效监督 Token 的加权平均交叉熵：

`L = sum(weight_i * CE_i) / sum(weight_i)`

Prompt 和 Padding 仍为 `-100`，不参与损失。因果移位后，权重跟随被预测的目标 Token。权重只用于训练；Dev 评估始终报告普通、未加权的 CE。

| 条件 | 训练 Loss 权重 | 用途 |
|---|---|---|
| `token_mean` | 全部有效 Completion Token 权重为 1 | 同配置短程对照 |
| `profile_x2` | A0 顶层归属为 `user_profile` 的全部 Token 权重为 2，包括画像内部的混合边界 Token；跨越顶层字段的 `boundary_mixed` 仍为 1 | 检查整体画像监督增强效果 |
| `label_value_x2` | 仅精确落在 33 个 Gold 标签字符串内容中的 Token 权重为 2；键名、标点、空数组、混合边界和其他字段权重为 1 | 检查标签值定向加权效果 |

权重因子 2 在运行前固定，不根据 Dev 逐条结果调整。细粒度区域复用 A0/A0.1 的 Token 对齐规则；任何 Prompt、EOS、Padding、标签顺序或 `input_ids` 改变都视为实现错误，停止 Run。

## 三、两阶段执行

### 阶段 1：128 步短程对照

三个条件各训练 128 个 Optimizer Step；micro batch 为 1、gradient accumulation 为 4，共约 512 次样本访问。使用种子 42 和相同的随机样本顺序。该阶段用于确认 Loss、梯度、保存/重载和评估流程，并做有限的 Teacher-forced 对照；不据此宣布模型质量提升。

三个条件在同一固定的 128 条 SFT Dev 子集上记录普通 Token 平均 CE、画像 CE、标签值 CE、情绪 CE、回复 CE，以及 Loss/梯度是否有限。Dev 子集按 `sha256_seeded_sample_id_order_v1`、种子 `20261103` 选择；样本 ID 和 Dev 子集 SHA 必须写入 Run Manifest。Dev 不参与训练，也不用于改权重。

**短程通过条件：**

- 三组都完成 128 步；Loss、梯度和 Adapter 权重均有限且可复载。
- `token_mean` 复现普通 Token 平均目标；加权组每个训练 micro-batch 的 Loss 都要与独立重算的公式一致。
- 至少一个加权组的普通 Dev 标签值 CE 比短程对照低 2% 或以上，且普通总 CE 上升不超过 1%；否则停止，不扩展训练。
- 任一条件出现 NaN/Inf、CUDA OOM、数据或 Token 对齐不一致、Base 权重变化，立即停止该条件并保留失败记录。

短程指标只用于决定是否值得做完整对照，不能替代自由生成评测。若通过，优先扩展满足条件的加权方案；若两个都通过，两个都进入完整对照，以免凭短程波动选优。

### 阶段 2：完整训练与配对评测

每个入选条件从相同 Base 和新 LoRA 开始，训练 1 Epoch、4,048 Optimizer Step；对照使用已冻结的 E01-B Full 标准 Token 平均 Adapter 及其完整 Dev 结果。数据、seed、学习率、LoRA、Batch、训练步数和其他设置与 Full B 对齐。

对每个完整候选使用全部 1,833 条 Dev 生成并配对比较；SFT Dev Loss 的分母为 1,821 条，不与生成指标混淆。报告至少包括画像 33 标签 Micro/Macro-F1、TP/FP/FN、逐维非空召回、全空预测率、三维 Exact、重点标签 Precision/Recall；情绪 Accuracy/Macro-F1；Raw A0、严格 JSON、回复 BLEU-4/ROUGE-L、生成长度和运行成本。官方 Val 不参与本轮调参。

**完整候选保留条件：**画像 Micro-F1 或 Macro-F1 至少提升 0.01 绝对值，且画像 FP 数量相对基线增加不超过 10%；情绪 Accuracy/Macro-F1、Raw A0 和严格 JSON 相对基线下降均不超过 0.01；回复 BLEU-4 与 ROUGE-L 相对下降都不超过 5%。未同时满足时记录为未通过或有权衡，不直接替换 Full B。所有数值均为本地代理指标，不等同官方成绩。

## 五、实现与运行

独立实现已完成；E01 默认 Loss 和历史产物未改。实现使用现有 A0/A0.1 对齐规则生成权重映射缓存，训练样本从 D0.3 Train 对齐，Dev 样本从 D0.3 Dev 对齐；缓存只存样本 ID 与 Token 区域编号，不存对话文本。A1 加权 Loss 在因果移位后按目标 Token 加权，并分块计算 FP32 交叉熵；每个训练 micro-batch 还会用独立的 log-softmax 公式复算并核对 Loss，避免一次性复制整段大词表 logits。

```text
configs/training/e03_a1_loss_contrast.yaml
scripts/e03_a1_loss_contrast.py
src/training/e03_a1_loss.py
scripts/e03_a1_evaluate.py
tests/test_e03_a1_loss.py
docs/experiments/E0.3-A1_Loss对照实验报告.md
outputs/training/E03-A1-*/
```

先在 WSL 项目根目录恢复 `token_mean` Run。它的 128 步 Checkpoint 已完成；此命令会重新核对输入与 Token 映射、载入该 Checkpoint，补完 Dev 分项统计、保存 Adapter 并完成重载验收，不会再执行优化步骤：

```bash
set -euo pipefail
source .venv/bin/activate
python scripts/e03_a1_loss_contrast.py \
  --mode resume --stage short --variant token_mean \
  --run-root outputs/training/E03-A1-short-token_mean \
  --checkpoint outputs/training/E03-A1-short-token_mean/trainer/checkpoint-128 \
  --allow-e03-a1-training
```

确认该 Run 状态为 `passed` 后，再运行两个加权短程组。每组独立预检并从 Base 初始化新的 LoRA；相同 seed 和随机行序保证比较条件一致：

```bash
set -euo pipefail
source .venv/bin/activate
for variant in profile_x2 label_value_x2; do
  preflight_id="E03-A1-short-${variant}-preflight-retry2"
  run_id="E03-A1-short-${variant}"
  python scripts/e03_a1_loss_contrast.py \
    --mode preflight --stage short --variant "$variant" --run-id "$preflight_id"
  python scripts/e03_a1_loss_contrast.py \
    --mode train --stage short --variant "$variant" --run-id "$run_id" \
    --preflight-run-root "outputs/training/$preflight_id" \
    --allow-e03-a1-training
done
```

预检会检查 D0.3 Train 与 Dev 的来源文件和 Manifest；预检失败时 `set -e` 会立即停止，不会继续调用训练。失败的预检 Run 目录会保留，重试时必须换一个新的 `preflight_id`。

全量 Run 只允许 `profile_x2` 或 `label_value_x2`，且短程门槛会由程序再次检查。以 `profile_x2` 为例：

```bash
variant=profile_x2
short_run="outputs/training/E03-A1-short-${variant}"
token_mean_run="outputs/training/E03-A1-short-token_mean"
preflight_id="E03-A1-full-${variant}-preflight"
run_id="E03-A1-full-${variant}"
python scripts/e03_a1_loss_contrast.py \
  --mode preflight --stage full --variant "$variant" --run-id "$preflight_id" \
  --short-run-root "$short_run" --token-mean-short-run-root "$token_mean_run"
python scripts/e03_a1_loss_contrast.py \
  --mode train --stage full --variant "$variant" --run-id "$run_id" \
  --preflight-run-root "outputs/training/$preflight_id" \
  --short-run-root "$short_run" --token-mean-short-run-root "$token_mean_run" \
  --allow-e03-a1-training
```

另一个通过门槛的加权组，将 `variant` 改为 `label_value_x2`，并把 `short_run` 指向对应短程 Run。完整训练后，对候选 Adapter 执行完整 Dev 评测并与既有 E01-B Full Adapter 配对：

```bash
variant=profile_x2
python scripts/e03_a1_evaluate.py --mode run \
  --training-run-root "outputs/training/E03-A1-full-${variant}" \
  --run-id "E03-A1-EVAL-${variant}" \
  --hardware-label "RTX 4060 Laptop GPU / WSL" --allow-full-dev
python scripts/e03_a1_evaluate.py --mode compare \
  --baseline-run-root outputs/evaluation/e01_b/full/E01-B-EVAL-20261028-223105 \
  --candidate-run-root "outputs/evaluation/e03_a1/full/E03-A1-EVAL-${variant}" \
  --output-dir "outputs/evaluation/e03_a1/comparison-${variant}"
```

`label_value_x2` 也通过短程门槛时，单独运行相同的完整训练、评测和比较命令并替换 variant/Run ID。训练 Run ID 不能复用；若中断，按原 variant、stage 和配置使用同一 Run 根目录显式恢复最近 Checkpoint。所有命令均不使用官方 Val。
