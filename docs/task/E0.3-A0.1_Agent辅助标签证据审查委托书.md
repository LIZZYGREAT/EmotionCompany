# E03-A0.1 Agent 辅助画像标签证据审查委托书

## 任务目标

对固定的 84 条 Train 审查样本逐条判断：当前标签在预测时刻之前的 history 中是否有证据支持、证据消息是否被 T1 保留。Agent 负责完整初筛；只有证据不确定、审查不完整或可能存在 Gold/证据不一致的项目才进入人工队列。

本任务是**证据审查和分流**，不改 Gold，不判断模型预测，也不改数据、Loss、训练流程或比赛协议。Agent 结果必须标为 Agent triage，不能称为人工核验。

## 输入和可读取范围

使用已生成的最小化输入文件：

```text
outputs/diagnostics/e03_a0_1/E03-A0-1-PROFILE-FULL-20261103-02/agent_review/input_minimized.jsonl
```

该文件共 84 行，每行只含：

- `sample_id`：仅用于与原审查模板对应的不透明 ID；
- `focus_label`：本行唯一要审查的画像标签；
- `gold_positive`：该标签是否出现在此样本的 Gold 画像中；
- `original_history`：该预测时刻之前的完整合法 history；
- `t1_history`：实际进入 SFT Prompt 的 T1 history；
- `t1_start_index`：T1 后缀在 `original_history` 中的起始消息序号。

标签定义只可查阅受保护的官方输入文件：`configs/prompts/p0.txt` 和 `data/train/train_public.schema.json`。若标签在这些文件中没有足够清楚的定义，应标 `uncertain` 并交给人工，不得仅凭标签英文名自行扩展含义。

**只读取上述最小化 JSONL、本委托书、P0 和 Train schema。** 不读取完整审查 JSONL、未抽样 Train、Dev、官方 Val/Test、模型预测、生成回复、Loss/性能报告或其他样本的 Gold。不要通过外部 API、联网工具或第三方服务处理对话；所有操作限本地环境。

`original_history` 已止于当前预测点，不得访问或推测未来轮次。history 中可以有 user 和 assistant 消息；assistant 单方面提出的用户偏好或性格判断，未经 user 确认，不算明确用户证据。不得把整段原始对话复制进日志、报告或人工队列。

## 逐条审查规则

对每行执行以下步骤：

1. 先看 `focus_label` 的官方定义，再完整阅读 `original_history`，记录支持或反驳该标签概念的具体消息。不能只看 T1 或只看命中的一句话后就断言没有矛盾。
2. 查看 `gold_positive`，把它当作训练目标的正负状态。它不是标签真实性证明，也不代表用户曾说过标签本身。
3. 记录支持消息在 `original_history` 中的**零起始消息序号**。序号按所有消息连续编号，user 与 assistant 都占位置；例如 `2, 5` 指第三和第六条消息，不是用户消息专属编号。没有支持消息时，完整审完填写空数组 `[]`；没读完且尚未找到消息时填写 `null`。
4. 根据记录的证据消息和 `t1_start_index` 判断裁剪情况。索引 `i >= t1_start_index` 表示 T1 保留，`i < t1_start_index` 表示 T1 裁掉。分别保存保留与裁掉的消息索引；若两类都有，必须同时保留两份列表，不能只记其中一边。
5. 用简短、非引用式说明写清为什么支持/不支持、是否有冲突或定义歧义。不得复制长段对话原文。

证据分类限定为：

| 分类 | 使用条件 |
|---|---|
| `explicit` | user 消息直接表达与官方标签定义相符的事实、偏好或自我描述；必须有准确消息索引 |
| `inferred` | 需要由多条 user 消息或跨轮稳定模式作出解释性推断；必须指出相关消息，并说明推断链 |
| `insufficient` | 已完整阅读全部 `original_history`，仍没有足够的 user 证据；这不表示 Gold 一定错误 |
| `conflicting` | 存在相互矛盾、变化或正反信号并存的证据；应记录两侧消息索引 |
| `uncertain` | 官方定义、证据边界或语义映射难以稳定判断 |

审查完整度单独记录：`complete` 或 `not_fully_reviewed`。只要有消息因长度、上下文限制或其他原因未被检查，就必须用 `not_fully_reviewed`、低/中置信度并交人工；不得把未读部分当作“没有证据”，也不得标 `insufficient`。

## 置信等级与人工分流门槛

置信度使用 `high`、`medium`、`low` 三档，不要伪造小数概率。**只有 high 且与 Gold 状态一致的结果可以不进入人工队列。** 以下规则同时满足才可判 `high`：

- `explicit`：至少一条明确的 user 消息直接支持官方定义；含义具体、无实质歧义、完整 history 中没有相反证据。
- `inferred`：至少两条相互独立的 user 消息/不同轮次呈现一致模式；推断与官方定义直接相关、完整 history 无明显反例。单句语气、单个词或泛化的性格推断不够。
- `insufficient`：已完整检查每条原始 history 消息，标签定义清楚，且没有找到任何支持性 user 证据。只因没在 T1 看到证据不能判 `insufficient`，须先查原始 history。

以下情况**一律进入人工队列**，即使 Agent 主观上觉得比较确定：

- `conflicting` 或 `uncertain`；
- `not_fully_reviewed`、缺少有效消息索引，或无法完成 T1 对照；
- Gold positive 但证据分类为 `insufficient`；
- Gold negative 但发现 high-confidence `explicit` / `inferred` 证据；
- 仅有未经 user 确认的 assistant 断言；
- 标签需要临床、人格诊断或其他官方定义之外的推断。

以上 Gold/证据不一致项目可能反映标注问题，也可能是证据分类问题；队列只能提出待人工复核，不得宣布 Gold 错误或修改它。Gold 与证据一致但置信度为 medium/low 的项目也必须交人工。

## 输出文件

所有输出写入下列 Git 忽略目录，不要修改输入文件：

```text
outputs/diagnostics/e03_a0_1/E03-A0-1-PROFILE-FULL-20261103-02/agent_review/
```

至少生成三个文件：

1. `agent_triage.jsonl`：输入 84 行必须逐行对应输出一条，不能抽样遗漏。每行包含：
   - `sample_id`、`focus_label`、`gold_positive`；
   - `evidence_classification`、`confidence`、`review_status`；
   - `support_message_indices`；
   - `t1_retained_support_message_indices`、`t1_removed_support_message_indices`、`t1_retention`（沿用 `retained_by_T1` / `removed_by_T1` / `not_identified`）。若支持消息同时有保留和裁掉，两个索引列表都填；`t1_retention` 作摘要填 `retained_by_T1`，人工队列中注明 mixed；
   - `rationale`、`ambiguity_or_conflict`；
   - `needs_human_review`、`human_review_reason`；
   - `reviewer_type: "agent"`。
2. `human_review_queue.md`：只列 `needs_human_review=true` 的项目。每项写 `sample_id`、标签、Gold polarity、分类/置信度、消息索引、待人判断的问题；**不包含原始消息全文或长引用**。人可用随附的 `private_review_browser.html` 搜索样本 ID 查看原文。
3. `agent_manifest.json`：Agent/模型名称和版本、处理时间、输入行数与 SHA-256、输出行数、high/medium/low 计数、人工队列计数、未完整阅读数、允许读取的文件列表，以及运行过程中是否发生截断或解析错误。

若输入解析失败、输出少于 84 条、Agent 读不完整，必须明确报告；不得把未处理项静默丢弃。拒绝分类的项目留在人工队列。

## 不允许的动作与报告边界

- 不得改动 `gold_positive`、原始 history、T1 history、标签名称、抽样顺序或样本集合。
- 不得扩展到其他 Train 样本，不能读取 Dev/Val/Test 或模型输出来“佐证”当前例子。
- 不得为满足高置信度而推断、补写缺失事实；找不到消息索引的正向判断不能自动通过。
- 不得将 Agent 结果称为人工审查、Gold 真值或标签错误率估计。
- 不得将逐条对话、Gold 或可识别的原文提交到 Git、PR、共享报告、外部服务或未授权日志。
- 不训练、不运行模型预测、不改 Loss、Schema、P0、P/F/T 协议或官方入口。

人工只需优先处理 `human_review_queue.md`；high-confidence 且与 Gold 一致的样本作为 Agent 初筛结果留档。汇总报告必须分别报告自动通过数、人工队列数、未完整审查数和 Gold/证据不一致数，并说明 Agent 判断仍有模型偏差风险。
