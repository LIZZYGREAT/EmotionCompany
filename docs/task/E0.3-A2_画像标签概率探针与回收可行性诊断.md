# EmotionCompany E03-A2：画像标签概率探针与回收可行性诊断（Codex 执行方案）

> **任务性质**：冻结模型、只读数据的机制诊断与有限 GPU 前向实验。Agent 可在资源门禁下自行执行 Smoke、Pilot 和满足条件的有界诊断；本轮不训练、不修改正式推理协议、不部署任何回收策略。<br>
> **研究问题**：当 E01-B Full 在某个画像维度输出 `[]`，但 Gold 存在标签时，模型是否仍能够在受控探针下区分正确标签与错误标签？这种能力能否在**不额外训练**的前提下产生可验证的恢复价值？<br>
> **研究参考**：[Ma et al., *Large Language Models Do Multi-Label Classification Differently*, EMNLP 2025](https://aclanthology.org/2025.emnlp-main.126/)。该论文的 Compare-to-None、Unary Breakdown 与跨生成位置概率聚合是不同方法；本任务根据项目的 JSON 协议提出适配探针，不宣称复现原论文算法。<br>
> **研究基线**：E01-B Full Adapter；E03-A1 `label_value_x2` 是可选的对照，不是基线。**现阶段不因探针结果直接替换 Full B**。

## 一、已有证据与本轮目标

当前画像完整 Dev 代理指标：E01-B Full 的 33-label Micro-F1 为 `0.4223`；E03-A1 `label_value_x2` 为 `0.3839`。后者完整训练并通过重载，却出现 TP 减少、FN 增加。这说明仅靠提高 Gold 标签字符串权重，没有改善最终多标签召回。

成员 B 已在 `chore/e03-b-p1-design` 的 `docs/experiments/E03-P1-A-adapter复验.md` 中记录一批 **209 个官方 Val 预测点**，来自按对话抽取的 **78 段会话**，使用 E01-B Full、P0/F2/T1、NF4/BF16、P=1280、G=1200、Greedy 完成生成。本地 P0 画像 Micro-F1 为 `0.3541`，与 1,833 条 Dev 的 `0.4223` **不是同一数据分布和分母**，不可混作对照或用它宣称已接近/远离 50%。这批 209 点已经参与过 P1 方案比较，属于**探索集**，不是未触碰的独立测试集。

成员 B 的 `docs/experiments/E03-T1-短历史普查判定.md` 明确记录：在 **T1 未截断、历史不超过 8 条消息、Adapter P0 三维均预测为空，但 Gold 对应维度非空** 的条件下，有 **37 个「点×维度」漏报案例**，它们来自 **30 个预测点、21 段会话**。此前盲判认为 17 个有直接证据、16 个有间接证据、4 个没有证据；该判断不是可替代 Gold 的独立真值。

原 Agent 提议值得保留的核心是：**优先在这些真实漏报案例上检测模型的潜在标签辨别能力，不重跑完整训练。** 本任务要检验以下假设：

- H1（原 JSON 中的标签可辨别性）：在不改变 P0/F2/T1 和既有模型权重的条件下，模型对正确标签的条件序列分数是否通常高于同维错误标签？
- H2（另一任务格式下的标签可辨别性）：将任务改为「候选标签是否受到历史支持」后，同一个冻结模型是否能够区分正、负标签？
- H3（可回收性）：若有判别信号，它在**按会话隔离的离线评价**中是否能带来 TP 净增加，且 FP 增长可接受？探针准确，不自动等于可以低延迟地部署。

要严格区分：原模型“根本不会识别”、原 JSON **生成机制**使其不输出、换任务提示才学会识别、原始历史不足以支持 Gold。这些是待证假设，不预填结论。

## 三、探针 A：原生 P0 JSON 语境中的候选标签条件分数

### 1. 目的与固定输入

探针 A 保持原来的 P0、F2、T1 和 E01-B Full Adapter。对每个预选「点×维度」案例，使用该点**已有的模型原始生成结果**构建至目标维度数组开始处的**模型自己生成的前缀**，然后在相同前缀下比较候选标签的后续序列分数。对于原输出 `[]` 的维度，这个位置应位于合法数组内容开始之前。前面已经生成的情绪和其他字段保持原模型输出；不使用 Gold 构造前缀。

必须说明这是一种**给定自生成前缀后的条件概率测试**。即使 Gold 标签的分数偏高，也不能直接推断完整生成路径中它一定会被模型选择。

### 2. 为什么不能直接取 `logit_label - logit_']'`

当前 JSON 数组标签形如 `"direct"`、`"high_emotional_expression"`。在真实 Qwen Tokenizer 下，某些标签会拆成多个 Token；引号等首 Token 还可能在多种标签间共享，并且数组结束时 `]` 可能与邻近标点共享 Token 边界。

先针对每个维度枚举（10 / 12 / 11 个标签）进行**真实上下文相关的 Token 预检**：记录标签候选、空数组结束、共同 Token 前缀、不同候选第一个分叉位置及是否跨越 JSON 边界。不得把所有标签都假定为单 Token。

仅在**同一前缀、同一预测位置、候选确实由不同的单个 Token 表示**时，才可计算 `sigmoid(logit_a-logit_b)` 作为两候选的条件相对偏好。即使数值在 `[0,1]`，也**不是校准的画像标签存在概率**。对其余样本，不允许使用“首 Token 相对 `]`”填充主指标。

### 3. 主测量与正确的记录口径

- 对同维每个标签构造明确且合法的候选延续，至少对标签字符串内容及其边界计算**完整序列的 teacher-forced 条件 log probability**；另对「直接关闭空数组」计算可比的续写概率或序列分数。候选扩展必须从**完全相同的模型前缀**开始。
- 同时报告 `logp_sum`、预测 Token 数、`logp_mean`；由于候选长度不同，**不能直接把完整标签序列与一个 `]` 的 logp 差当作归一化二元后验概率**。可将其作为描述性的生成路径竞争得分，并明确长度偏差。
- 对标签间排名，报告 `sum` 与 `mean` 两种口径的敏感性。若长度偏差导致结果不一致，标为 `length_sensitive`，不选择表现最好的一种冒充原始定义。
- 可选地做基于完整候选的 prefix trie / cache 共享以减少相同前缀重复计算；优化不得改变数学对象。
- 原始 P0 结果如果没有保存生成 Token IDs：可以在严格验证 Prompt Token IDs 的基础上，从原始 **raw text** 重建条件前缀并以 Teacher Forcing 计算；应标为 `reconstructed_text_prefix`，不能声称逐 ID 复原了原始贪心生成路径。若无法验证这个前缀是一个有效 JSON 部分或无法确定数组边界，记录 `prefix_unavailable` 并从有效分母排除。
- 对照点中模型原本已经输出标签的维度，应区分**第一个标签的条件位置**与**生成后续标签的条件位置**；不要将不同比较位置混合成一个“首标签概率”。

**A 的主要结果不是一个漂亮的 `p` 数字，而是同维 Gold 与非 Gold 标签是否可区分、其分数是否对选取位置和候选长度稳定。**

## 四、探针 B：单标签判别问答（独立任务提示）

探针 B 不延续原 JSON，而是用同一个 E01-B Full 模型，对相同已选历史和指定候选标签进行一个**单标签**判断，形如：

```text
给定以下对话历史，判断其中是否有足够证据支持候选画像标签：<合法标签名>。
只回答两个固定答案中的一个：支持 / 不支持。
```

输入模板、答案字符串、模型 F2 Chat Template、Greedy/条件评分口径应在看任何新 Gold 统计前冻结。问题中只允许出现该候选标签，不得出现 Gold，也不得附加针对单条案例编写的解释性例子。候选标签词表仅使用官方三维枚举；不擅自创造中文标签释义并视为原协议中的监督信息。

- 对两种完整候选答案计算同前缀的条件序列 logp，记录 `score_yes`、`score_no`、差值及二者的归一化偏好。若候选答案为多 Token，仍需计算完整序列，不直接取首 Token。所得到的分数仅是**固定问答提示下两答案的相对偏好**，不是原始 P0 下的真实独立概率。
- **B 更接近文献中的 Unary Breakdown，而不是 Compare-to-None。** EMNLP 2025 的 Compare-to-None 使用标签生成分布里的 `none` 作为参考；本项目原输出不存在这个标签，因此不宣称直接复现。参见原论文方法定义。
- B 的 Prompt 与 P0 不同，即使 F2/T1 策略相同也可能改变实际历史选择。必须尽量直接复用同一条 **P0 已选历史**，并验证新提示的 token 预算是否允许容纳；若无法完全容纳则标记 `context_mismatch`，不悄悄裁剪后称为“相同上下文”测试。
- B 的调用成本可能随「点×标签」数量线性增长。优先采用同样历史和标签集合的前缀缓存及批处理；如果 GPU 上一次请求一个候选，需要统计每个有效判别得分的 GPU 耗时和平均 Forward 次数。

**解释边界**：如果 A 不可分而 B 可分，较合理的结论是**换任务表达后能提取出一定的标签判别信号**；尚不能归因于原 JSON 生成通道“压住了”已有的同条件概率，也不能认定可以零成本部署。

## 五、阶段门禁：不把诊断升级成另一次半天实验

### 阶段 0：仅 CPU，对齐、抽样与候选编码

读取已存在的 209 点与 37 案例；生成冻结选择清单、Tokenizer 候选差异清单和 Manifest。核验 `209/78`、`37/30/21`，以及是否有生成截断、损坏 JSON、缺失原始前缀。明确冻结三种**不同角色**的集合：Gold 筛出的 37 条机制漏报、最多 30 个预测非空对照点、最多 30 个从 P0 空预测中 **不看 Gold** 抽取的回收可行性样本。它们可能重叠，去重后记录关系与各自分母，不重复算作独立样本。此阶段不得加载模型、不得启用 GPU。

**通过**：身份可复核、目标案例定义一致、候选 Tokenization 可解释、所有输入 Hash 与前缀来源有记录。否则输出 `source_blocked` / `tokenization_blocked`，停止后续计算，不猜测缺失数据。

### 阶段 1：最小 GPU Smoke（建议 6 个点×维度，跨至少 3 个会话）

只使用 E01-B Full。测试模型的 NF4/BF16、CUDA 放置、Forward 数值、Prefix 构造、A 的完整候选序列得分、B 的两个答案得分。覆盖短标签、长标签、中文历史、原始空数组和一条对照案例。与 CPU 独立算式校验可在合成 Token 上进行。此阶段的指标只用于查测量错误，不用于性能结论。

**通过**：结果有限且可复算、至少一条多 Token 标签完整计算、同候选重复 Forward 数值在规定容差内、无越权读取/写入。若发生 OOM，不自动改模型规模、量化方式、Prompt、Batch 语义；保存失败状态。

### 阶段 2：小样本 Pilot（建议 12 个漏报点×维度 + 12 个匹配对照点×维度）

样本与候选维度按会话分组冻结，不允许临时挑选高分样本。A 对每个待测维度评估全部合法标签候选；B 先对相同维度的全部合法候选做单标签判别，但必须服从下述 GPU 硬上限。Pilot 判断的是排序是否有信息、两类探针是否退化成常数、成本是否可接受。

**通过至扩大诊断的条件**：有效前缀占比较高，候选分数有非平凡差异，数值和分母一致，运行成本在预算内。不要单凭 12 个漏报案例的 Top-3 好坏过早宣布成功或失败；若 B 明显不可用、所有 Yes/No 输出都偏向同一答案或预算已满，可停止 B，仅记录 A 结果。

### 阶段 3：有界扩展与回收模拟（仅前面通过且 GPU 预算允许）

分析全部有效的 **37 个漏报点×维度**，以及固定的至多 **30 个非空预测对照点**及其对应维度；如预算允许，优先补齐 Gold-blind 抽取的**空预测对照单元**，避免只看 Gold 已知非空的案例。先补齐 A，再根据 Pilot 的方向性与剩余时间决定是否运行 B。不得扩展到整个 209 点 ×33 标签，更不得自动扩大到完整 1,833 Dev 或未使用的 Val。

## 六、冻结评价指标与合理判断

### 1. 评价分母与基线

按 `dimension` 独立统计；对同维候选标签构造 Gold 二值表，不把其它维度标签纳入负例。维度候选数分别为 personality 10、interests 12、style 11。Top-3 随机排序下，**单个指定 Gold 标签**命中概率为 `3/K`，约为 30.0%、25.0%、27.3%。一条案例可含多个 Gold，统计须明确采用 **逐 Gold 标签的 Recall@3**、**任一 Gold 命中率**还是 **整组 Gold 覆盖率**；不能互换。

至少对照：随机排序、Train 中标签先验频率排序、原始 P0 空/非空预测。标签先验来自 Train，不使用这 209 个 Val 的 Gold 估计先验。

### 2. 排序与判别质量

- 每维及总体的 `Recall@1/3`（按 Gold 标签计），候选分数的 Gold/non-Gold 排名百分位，适用时的 ROC-AUC 与 Average Precision；不具有正负两类的子组标 `not_applicable`。
- `A` 的完整候选序列 `logp_sum`、`logp_mean` 的一致性；`B` 的支持/不支持条件偏好；分数不是校准概率，不得用 `p > 0.5` 自动宣称合理阈值。
- 正负标签平均值或中位数、非空对照点中的行为，以及按维度、历史长度、证据类型（直接/间接/无证据，仅描述性）分类。
- 统计模型已有非空标签是否在各自候选列表排名靠前；此项检验探针是否与已有生成行为相关，防止漏报案例被过拟合式挑选。
- 对同一 conversation 的多点数据进行分组 Bootstrap 或给出按会话汇总结果；样本量与置信区间很小时，结论标为探索性，不使用“显著提升”空话。

### 3. 仅用于验证「可能回收」的离线模拟

如果 A 或 B 的标签排名优于先验/随机基线，可在**事先不看 Gold 抽取的空预测对照单元**上进行有限回收模拟：保留原 P0 输出，只对这些预登记的单元应用候选标签选择规则。**绝对不能仅对 37 个 Gold 已知非空的漏报案例执行回收，再将结果称作可以部署的画像 F1 提升。** 那是带有 Gold 选择条件的案例研究，必然低估空画像误报风险。

为避免使用同一批 Gold 选择阈值再给同一批样本报分：按 **conversation_id** 做确定性的分组交叉验证，阈值或 Top-k 规则只能从其它折选择，当前折只计算结果，并报告 Out-of-Fold（OOF）合并指标。极小子组无法稳健调阈值时，优先展示阈值无关排名结果与固定规则，不强行报告“最优 F1”。若 Gold-blind 空预测样本数量或正负组成不支持分组评估，则直接标记 `recovery_evaluation_inconclusive`。

本轮有限覆盖只允许报告“被预登记抽中单元上的局部恢复”或“其余预测不变时的 209 点**局部干预**分数”；这**不等于**对 209 点全部空预测运行同一策略的真实性能。对全部空预测单元的效果与额外推理成本，必须在未来独立授权的 Gold-blind 扩展试验中检验。

必须同时报告：

- 原始 P0 的 209 点画像 Micro-F1（历史报告为 0.3541，应由逐样本评分复算）。
- 仅在同一固定、**Gold-blind** 探针覆盖集上的 P0 基线，以及 OOF 回收候选的 TP/FP/FN、Micro-F1 与非空预测率；若另给出 209 点局部干预分数，必须明确仅抽中的单元发生更改。
- 新增标签中 TP 与 FP 各多少；每多增加 1 个 TP 伴随多少 FP；每段会话新增的推断调用或算力估计。
- 不带任何 Gold 的真实推断逻辑是否可复现；若只有 Gold 引导的 Oracle 恢复有效，记为 `oracle_only`，不是可部署改善。

**不存在“37 条里 Gold Top-3 超过随机就证明回收可用”的捷径。** 排名好只是下一步候选选择的必要线索，不是充分条件。要支持推理侧回收，至少需要在 OOF 框架下有一致的正向 F1 / TP-FP 权衡，而且新增调用代价有明确边界。209 点已被用于既往探索，OOF 仍不能替代未见数据验证。

### 4. 必须使用的结论分类

| 结果标签 | 何时使用 | 能得出的结论 |
|---|---|---|
| `protocol_or_measurement_blocked` | 原始数据、Token 边界、Forward 对照无法核验 | 尚不能讨论模型能力 |
| `no_separation_observed` | 有效样本里标签区分能力不优于简单基线，且结果稳定 | 该探针未观察到可用信号；不代表证明模型完全没有能力 |
| `B_only_separation` | 独立问答有效，但原 JSON A 不可分 | 换任务格式后存在判别信号；不能直接归因于原生成通道 |
| `A_separation_no_recovery` | 原 JSON 条件排名有信号，但回收模拟无净收益 | 可能存在潜在排序能力，但尚无低成本恢复证据 |
| `recovery_candidate` | 排序优于基线，Gold-blind 样本的 OOF 回收净改善，FP 与成本可控 | 值得另行研究推理侧实现；**非自动批准部署** |
| `inconclusive_or_budget_limited` | 样本/会话/成本不足、分组结果不稳 | 保留事实，停止扩大断言 |

这些是决策类别，不预先给出不存在统计依据的“显著高于随机”主观门槛。输出总体和逐维分子分母，并说明所用的随机/先验基线。

### 最低测试要求

1. 合成的两个多 Token 标签共享首 Token 时，程序不得使用首 Token 分数假装已经区分标签；候选概率与 Causal LM 的 Shift 对齐正确。
2. 对 JSON 中 `[]`、多标签数组、Unicode、转义引号、缺失字段、同名字段文本和 token/字符边界混合都有测试；损坏输入必须计入拒绝分母。
3. 未受支持的 Gold、不在枚举内的模型输出不能泄漏到候选词表；抽样和 OOF 按 conversation 分组，训练/评分阶段严格禁止读 Gold 生成 Prompt。
4. OOF 选择阈值时不能读取待评分折；给出合成数据证明泄漏会被测试捕获。
5. 模拟只有“问答 B 有信号、原 JSON A 无信号”时，结论应是 `B_only_separation`，不能自动成为 `recovery_candidate`；若只挑 Gold 已知非空的 37 条计算回收增益，评测必须拒绝将其标为 OOF 部署收益。
6. 预算超限、CUDA OOM、源 Hash 不一致、重复 Run 名或条件前缀不可靠时安全停止并保留原因；输出不能因为缺失观测而将得分补为零。
7. 执行已有 E03 相关 CPU 回归、`python -m compileall -q`、`git diff --check`。由于当前 GitHub `unit-cpu` 未包含新 E03 测试，Agent 应明确记录本地测试结果；若要增加 CI，先确认 CI 的最小依赖，不要让 PyTorch GPU 测试跑入轻依赖 Job。

## 八、完成标准与下一步决策

本任务的成功不是让某个概率指标“变好看”，而是可以用证据回答：

1. **A 能不能在原 JSON 语境下区分 Gold 标签与非 Gold 标签？** 如不能，是分数接近、样本少、Prefix 取不到，还是 Tokenizer 首 Token 退化？
2. **B 能不能在另一种问答任务下区分它们？** 若能，相较 A 改善多少，计算代价多大？
3. **是否出现低成本回收线索？** 若只有需 33 次独立判断才会恢复，是否不值得比赛部署？是否存在单次前向可提取的候选信号？
4. **当前可以进入哪一类后续研究？** 原 JSON 推理侧概率回收、独立判别辅助训练、标签顺序研究，或明确停止此线。

Agent 可自行执行阶段 0–3，条件是每阶段身份、正确性和资源门禁通过；不能因为一次 Pilot Top-3 看似不错就扩大到全部 Val、启动 A1 新训练或改正式输出。若结果不理想，应保留负面实验结论，不重选样本、不修改 Gold、不借机调 Prompt。

**建议本轮只批准冻结模型的概率诊断，不批准后续任何完整训练。** 当 `E0.3-A2` 的指标、分组结论和资源账本完整后，再决定是否继续模型训练侧的多标签辅助监督，或研究一次生成中的概率聚合机制。
