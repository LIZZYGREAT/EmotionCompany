## 一、先明确要解决的实际问题

当前模型接收用户历史，依次生成包含情绪、画像、回复的完整 JSON。画像属于 33 标签的多标签预测：每个标签可以独立地出现或不出现。然而 Full B 的完整 Dev 上仍有 1,821 个 Gold 标签漏报（FN），并有 1,271 个错误预测（FP）。简单扩大画像 Token 的训练权重并未改善最终 Micro-F1，因此不能继续以“降低画像 CE”为主要实验目标。

另一条线索来自成员 B 对 209 个 Val 点的研究：历史很短时，存在模型明显不愿输出画像的案例。在“历史 1–4 条消息且 Gold 有标签”的 13 个点中，有 11 个三维预测全空；但样本数量小、对话点不独立，而且这些 Val 点已用于此前探索，不能直接据此认定短历史是全局主因。A2 的 209 点数据还曾存在导出历史遗漏当前 user 的问题，虽已隔离修复，但不应作为 A3 的主要输入来源。

**A3 需要先回答三件事，而不是直接训练：**

1. **缺陷是否真实、足够普遍？** 在 E01-B 的 1,833 条 Dev 全量结果中，画像漏报是否集中于短历史、某些标签、某些维度或特定 Gold 密度？这种现象在 Train 标签分布中是否也存在？
2. **缺陷是否有足够大的改进空间？** 即使完全修复某一类漏报，其贡献是否足以让整体 Micro-F1 明显接近 0.50？如果机会空间不足，就不要为该子集单独进行大规模训练。
3. **有没有可控的训练干预？** 若数据支持特定假设，能否通过少量、配对的 Full B Adapter 续训，实际增加 TP，同时不显著增加 FP、破坏情绪/回复或导致画像“乱猜”？

贯穿全程的顺序是：

```text
现有 Train / Dev / E01-B / A1 产物
    ↓ 身份校验与样本对齐
按历史长度、画像维度、标签、Gold 密度还原 TP/FP/FN
    ↓ 判断是否有集中且可证伪的缺陷
对缺陷计算可恢复的 FN 数与 F1 机会空间
    ↓ 如果没有可靠机会：停止，不训练
定义唯一的定向数据/采样候选 + 同步数标准续训对照
    ↓ 合成测试、资源检查、固定评测集合
小步数续训 → 少量真实 JSON 生成 → 配对 F1、TP、FP、FN
    ↓ 若无稳定收益：停止，不扩大
独立审批后才可能中程验证 / 完整训练
```

## 四、阶段 1：画像漏报机制全量诊断（CPU，不训练）

### 1.1 对 Train 与 Dev 使用一致的长度与 Gold 统计

先划分原始历史长度（1–4 / 5–8 / 9–16 / 17+ 条），另对 T1 实际保留历史长度作同样划分。这两套长度需要分别报告，避免长历史经过 T1 后被误分为真正的短会话。

Train 数据以有效 SFT 16,192 条对应的 D0.3 历史和 Gold 为母体；Dev 以 1,833 条完整 Dev 为母体。按如下维度统计，并提供每个比例的分子和分母：

- 点数、独立 conversation 数、目标 turn 位置、T1 裁剪率、平均/中位 Prompt Token 数。
- Gold 三维全空比例、至少一维非空比例；三维分别非空比例；Gold 每点平均标签数，按 0/1/2/3+ 分组。
- 对 Dev 另统计预测三维全空率、逐维空率、预测平均标签数、Micro Precision/Recall/F1、TP/FP/FN、三维 Exact Match。
- **关键：Gold 非空条件下预测为空的比例**。必须用 `Gold 非空点` 作分母，不能用全部点作分母；点级与维度级各算一份。
- 对每个标签，统计 Train Gold Support、Dev Gold Support、Pred、TP、FP、FN、P/R/F1；按历史长度交叉统计重点标签。少样本给计数和置信度限制，不仅展示百分比。

避免仅比较“短历史 F1 低、长历史 F1 高”就归因于长度。历史长度也会改变用户画像证据量、Gold 密度、标签类别与对话阶段。至少对 Gold 标签数、维度和 T1 裁剪状态进行分层，并区分描述相关性与因果结论。

### 1.2 画像错误集中度与 A1 的变化

直接从 E01-B 与 A1 的同一批 1,833 个 Dev 预测对比：

- 对每个样本/每个标签的四种转变：`FN→TP`、`TP→FN`、`FP→TN`、`TN→FP`。
- 两模型在短/长历史、Gold 空/非空、三个维度及高 FN 标签上的变化。
- 判断 A1 的“更保守”是否跨所有长度存在，还是只在少数组明显。**A1 的输出不得被选作更优基线，也不得与 E01-B 的结果混合拼接**。
- 识别主要机会群：优先看 `rational`、`sensitive`、`direct`、`high_conscientiousness`、`conservative`、`career_development`、`high_emotional_expression`、`brief`、`detailed`，同时全量扫描 33 标签，避免只依据预选名字做结论。

### 1.3 计算“如果能修复这类错误，最多能改善多少”

不要仅根据某子组漏报很多就安排训练。对于每个候选子组（例如“原始历史 ≤4 且 Gold 正确标签可观察”），设该组包含 `FN_group` 个漏报；从现有全量基线 `TP=1130`、`FP=1271`、Gold 正标签 `P=TP+FN=2951` 出发，作**理论机会空间**测算：

假设该组漏报中有 $k$ 个可被完全正确恢复、其他预测完全不变、没有增加 FP，则

$$
F_1^{\mathrm{optimistic}}(k)=\frac{2(1130+k)}{2(1130+k)+1271+(1821-k)}
=\frac{2(1130+k)}{5352+k}.
$$

这一数值**只是数学上限/理想情形，不代表实际方法能做到**。分别报告该组 $k=25\%\, FN_{group}$、$50\%\, FN_{group}$、$100\%\, FN_{group}$ 时的乐观 F1；再报告如果新增 FP（例如每找回 1 个 TP 同时多 0.5、1 个 FP）时的敏感性。注意各组可能重叠，不能将两个组的机会空间直接相加。

全局目标 Micro-F1 0.50，在 FP 保持 1,271 不变时，需要至少把 TP 从 1,130 提升到 1,408，即新增 **278 个 TP**。若某一候选子组的全部 FN 远少于 278，该组**不可能单独达成 0.50**，但仍可能是低成本增量；报告必须定量说明预期用途与上限。

> 机会空间计算中 `P` 保持不变，因为 Gold 标签总数不随预测变化；如果产生新的 FP，必须进入分母。报告同时给绝对 TP、FP、FN 和整体 Micro-F1，不用单一子组 Recall 代替全局收益。

### 1.4 形成诊断结论，不预设“短历史就是主因”

最终将候选问题按证据分成：

- **可支持**：多个会话中重复出现，Gold、预测与错例聚集均有明确计数，且机会空间与全局目标有关。
- **可能但不足**：信号依赖少数会话、极少正例、T1/Gold 密度混杂，或只来自已用过的 209 Val 点。
- **不支持**：完整 1,833 点并未呈现预期趋势，或可修复 FN 少到无法形成值得训练的收益。

输出每项假设对应的可证伪预测：例如“若短历史是主要问题，则在 Gold 非空且长度/维度分层后，短历史组的 `FN/Gold标签数` 应明显高于可比长历史组；适当调节训练样本构成后，短历史真实生成的 TP 应有所增长，并不明显增加空 Gold 的 FP”。若不符合，不能继续把短历史当主要优化理由。

### 本阶段决策门禁 G1

Codex **必须先生成真实诊断报告和一页决策摘要**。只有满足下列要求，才允许进入阶段 2 的候选实现设计：

1. 目标错误有明确的 Dev 漏报分子、分母、独立会话数，主要数字可从现有 Run 复算；不能来自 209 Val 探索点的单独结论。
2. 同时有 Train 支持统计，且说明其分布与 Dev 的异同；不能把标签频率直接解释成标注质量。
3. 量化可恢复 FN 的规模，报告如果只修这类错，能否对整体 F1 有实际贡献。
4. 明确预期失败模式：例如短历史正例过采样导致 FP 增加、性格标签定义含糊、回复质量退化、过拟合或遗忘。
5. 最终只推荐 **一个首选、可测量的低成本候选**；若没有可靠问题或收益空间，则输出 `no_training_recommended`，到此结束。

不凭一两个漂亮百分比自动批准训练。

## 五、阶段 2：确定单一候选与公平对照（CPU，实现与预检；不启动训练）

### 2.1 候选只能从阶段 1 的结果中选择

优先级不是预设结论，而是以下顺序：

**情况 A：短历史确实存在明显过度空预测，且 Gold/Train 数据支持该现象。** 首选研究“短历史、有支持证据的画像正例与对应空标签负例的平衡采样”。不改 P0/F2/T1、不改 JSON 字段、不重新编码 Gold。使用原本 16,192 条 SFT Train 的 ID/Token 序列，仅改变被访问样本的顺序/重复频率。采样强度不在 Dev 上反复搜索，先固定一个温和候选（例如每一轮候选访问中，基础随机抽取与预定义的短历史平衡子集各占约 50%；短历史子集再按 Gold 是否非空等概率分层），具体参数应在 G1 报告中先冻结，并记录会话/样本重复率。**不可以只提高非空画像样本概率，而忽略空 Gold 对照。**

**情况 B：短历史假设不成立，但少量高 FN 标签贡献了主要可修复错误。** 暂不直接训练；先检查这些标签在 Train 的有效正例、负例样本规模、共现、是否涉及证据模糊。若有明确证据，提出一份单一的标签机会样本采样候选，保留维度和 Gold 空样本配比；若证据不清，则 `no_training_recommended`，不凭某标签 FN 很高就扩大训练。

**情况 C：没有足够聚集的问题或数据不支持。** 不实现训练候选，不再开启新一轮盲目 QLoRA。给出后续单独研究方向（标签语义/标注口径，或多标签辅助监督），等待另行立项。

本任务**不把“辅助二分类 SFT”“更换模型”“增加 LoRA rank”“改变 Loss 权重”混入第一次 A3 小实验**。这些属于不同的研究问题，必须独立设计。

### 2.2 对照实验：都从同一个 Full B Adapter 开始

为隔离“额外训练步数”与“定向采样”的影响，准备两组实验：

| 组别 | 初始化 | 训练数据顺序 | 损失函数 | 训练步数 |
|---|---|---|---|---|
| Control | 冻结 E01-B Full Adapter 的**副本/只读加载** | 按原始 Train 分布的等价随机抽样 | 原始标准 Completion-only Token CE | 与 Candidate 相同 |
| Candidate | 相同的 Full B Adapter、独立的新运行目录 | G1 冻结的唯一目标采样方案 | 与 Control 完全相同 | 与 Control 相同 |

两组都新建优化器/调度器且采用相同配置、相同 seed、相同 LR 和显存预算；不能一组从 Base 全新训练、另一组从 Full B 续训。记录初始 Adapter 指纹、每步样本 ID、会话分布、样本重复率和最终权重 SHA。是否能通过现有 `src/training/training_sft.py` 的安全恢复逻辑实现“**仅从 Adapter 权重初始化，而不是恢复旧优化器状态**”，需先审查；如接口不支持，新增独立 A3 runner，不要直接放宽 E01/A1 的训练审批或破坏旧 Resume 语义。若无法可信地恢复并对照，则阶段 3 直接 `blocked`。

> 特别注意：**配对对照不是要求两个组访问完全同一批样本**，因为采样本来是唯一变量；它要求除了样本选择策略以外，其余条件完全相同，包括总优化步数、初始权重、优化器/随机性设置、Gold、Loss、模型和生成协议。

### 2.3 评测样本：先冻结，再训练

- 为兼顾短历史问题、Gold 空样本与其他维度，固定种子，预先记录选取机制、分层规模、抽中会话数和 ID SHA。可以采用整会话分层，但**不可根据已知模型改进幅度挑有利样本**；Gold 仅用于预定义分层和评价，不能把 Gold 写入生成 Prompt。

## 六、阶段 3：有界短程续训 + 小规模真实生成（仅获授权后运行）

### 3.1 严格约束成本

首轮只允许一种 Candidate 与一种 Control：

- 两组均从 Full B Adapter 初始化；首先各自运行 **最多 128 个 Optimizer Steps**，在第 64、128 步记录检查点。单组达到时间/显存/磁盘限制即停止并记录。
- 建议配置 `per_device_micro_batch_size=1`、`gradient_accumulation_steps=4`，其他超参数沿用兼容的 Full B 设定；额外续训的 LR 是否保留原值必须在 G2 中单独审查并锁定，不能边跑边改。不得直接把 A1 的新 Loss 或优化器变化带进来。
- 两组累计训练预算首轮上限 **256 个 Optimizer Steps**；不因某一组效果差就给另一组加步数。
- 每组完成独立 Adapter 保存/重载一致性检查，记录 Base SHA 不变、loss/gradient 是否有限，检查没有修改已有 Full B Adapter。

### 3.2 不再依赖 CE 放行：先做真实 JSON 生成

在同一个已冻结的 192–256 点 Dev 子集上，为 Control 和 Candidate 分别执行 **Greedy、P0/F2/T1、G=1200** 的真实完整 JSON 生成。可先选固定的约 64 点分层 Smoke（两组同 ID）以检查格式与非空倾向，再进行冻结全集；不要先依据 64 点调参再把 64 点当独立检验。尽可能复用评分基础设施，但必须保留两组身份和完整 Raw/Submission 区分。

记录：

- 总体画像 33-label Micro/Macro-F1、TP/FP/FN、Micro Precision/Recall、三维 Exact Match。
- 短历史和非短历史分别的 TP/FP/FN、`Gold 非空 → 预测空` 率、Gold 全空的 FP；逐维和预选标签的召回及误报。
- 情绪 Accuracy / Macro-F1、Raw A0、严格 JSON、回复 BLEU-4 / ROUGE-L、预测标签数、平均输出长度和运行成本。
- 按 conversation 聚类 bootstrap 的差值区间，以及改善来源的分布；样本太少或 CI 极宽时不输出“稳定提升”结论。

**主要比较：Candidate-128 vs Control-128，而不是 Candidate-128 vs 没有额外训练的 Full B。** 原始 Full B 同 ID 结果作为第三个观察基线，以发现“两个续训方案都退化”。

### 3.3 明确的短程停止/继续判据

以下为预设的**保守放行标准**，不是科研真理；其作用是避免像 A1 一样用小幅 CE 改善换来大成本的完整训练。

1. Candidate 相比 Control 在冻结 Dev 短程集上，画像 **Micro-F1 至少绝对提升 0.03**，并且 TP 有实际增长，而不是单纯减少 FP；若数据波动导致差值区间不能排除零，判 `inconclusive`，不能自动升级为成功。
2. 与 Control 相比，整体 FP **增加不超过 10%**，画像 Precision 不明显退化；不能仅以 Recall 上升为依据。
3. 目标子群改善的同时，非目标子群、三个维度无明显全面性退化；情绪 Accuracy、Raw A0、严格 JSON 相比 Control 的下降均不得超过 **0.01**。回复 BLEU-4、ROUGE-L 相对下降不得超过 **5%**。若样本支持量不足以判定，必须报告 `inconclusive`，不视为通过。
4. Candidate 相比**原始 Full B**也不能出现整体画像明显退化；若 Control 与 Candidate 都比原始 Full B 差，报告“额外续训不适合当前条件”，停止。
5. 训练、保存/重载、样本身份、生成参数、评分数值与 Hash 检查全部通过。

达到数值门槛只是**申请下一阶段资源的必要条件，不是自动允许扩大**；还必须结合按会话重采样的不确定性、样本数和 A3.0 的机会空间判断。若未满足，记录负面结果、保留原基线，并停止。

## 七、阶段 4：仅作为未来可选路线，不在本次授权范围内

如果且仅如果阶段 3 的真实生成评估具有一致收益，另行提交**一页扩大验证申请**，内容必须包含：已通过的短程指标、剩余可改进 FN、风险、GPU/磁盘预算、为何新增训练规模值得做、独立评估集合与停止条件。

可选顺序是先做**有界中程续训**（例如每组总计不超过 256–512 步）和一次固定规模的真实生成复核，而不是直接 4,048 步重训；是否保留当前短程模型继续训练、如何与 Control 等步数公平比较，要预先冻结。中程失败即停止。

**完整训练（4,048 步）、完整 1,833 Dev 重新推理、官方 Val/赛题提交、模型替换、推理协议变更、辅助二分类联合训练均不属于 A3 自动授权**。需要新的批准任务书和资源预算。特别是从已训练 Full B Adapter 继续训练 4,048 步，不等价于重新从 Base 训练一轮，不能直接拿两个 Run 的训练步数或训练 CE 当公平对比。

最终决策写清楚三选一：

- `promising_candidate`：真正提高目标子群与总体画像 F1，副作用受控，可申请中程；仍不自动替换 Full B。
- `negative_result`：真实生成没有改善或 FP/其他指标退化；归档并停止，不继续扫采样比例。
- `insufficient_evidence`：机会空间小、样本不足、评测置信度不足或资产不完整；不扩大训练。
